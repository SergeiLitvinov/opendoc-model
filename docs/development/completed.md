# Завершённые возможности OpenDoc Model

С 0.17.0 реализован модельный [C-LIST-02](../guide/lists.md): продолжения пунктов
и родительская принадлежность через существующие якоря. Пустые родители,
нумерация, JSON, remap, извлечение, правки, удаление, циклы и бюджеты проверены.

С 0.16.0 реализован модельный [C-GRAPHICS-02](../guide/group-color-space.md):
пространство промежуточной композиции, непрозрачный профиль, unknown,
атомарная правка/удаление, JSON, проверка ссылок, remap и лимиты.

С 0.15.0 реализован модельный [C-GRAPHICS-01](../guide/graphics-scopes.md):
общие clips/groups в прежнем VectorScene, явные paint occurrences якорей,
композиция с unknown, атомарная правка/удаление, JSON, ссылки и лимиты.
Нативная композиция и визуальная приёмка остаются снаружи библиотеки.

С 0.14.0 завершён модельный [C-FONT-01](../guide/font-references.md): явная
ссылка TextStyle → FONT resource, face_index, наследование, JSON, композиция,
валидация и ограниченные атомарные операции. Бинарные шрифты остаются непрозрачными.

С 0.13.0 [лимиты](../guide/limits.md) дают структурированные path/quota/maximum,
сохраняя прежние ошибки; бюджет большой модели и профиля текста проверен через
публичные операции. Новый JSON или обязательные зависимости не добавлены.

С 0.12.0 завершён [общий контракт межстрочного интервала](../guide/line-spacing.md):
minimum/exact/relative, модельное наследование, явное неизвестное, атомарная правка
и удаление, JSON, композиция и расположенное сравнение с доступностью области.
Нативные метрики и форматный каскад не входят в модель.

В 0.11.3 проверена [фиксированная компоновка](../guide/fixed-layout.md) на
собственной двухстраничной модели: точные декларации, Unicode-интервалы,
provenance и два JSON-цикла. Исправлена независимость событий новой истории.
Новых layout-структур и нативного расчёта не добавлено.

С 0.11.2 завершён [аудит деклараций цвета](../guide/styles.md): существующий
auto/None/наследование, JSON, правки и расположенное сравнение текстовых
интервалов. Нового цветового типа и вычисления нативного RGB нет.

С 0.11.0 завершены [отступ таблицы и табуляция](../guide/spacing.md):
пункты, позиции, выравнивание/заполнитель, неизвестное и явное подавление,
fallback, атомарные правки, JSON, композиция и расположенная диагностика.
Контракт не рассчитывает компоновку и не заменяет нативную приёмку.

Цель — самодостаточная Python-библиотека: создать документ, обойти и изменить его структуру, управлять свойствами и ресурсами, сохранить, восстановить и проверить изменения через понятный публичный API. Для этого не требуется редактор или конкретное приложение-потребитель.

Библиотека включает модель, её расширение, сериализация, валидация, сравнение, документация, тесты и выпуск пакета. UI, сеансы редактора, undo/redo, хранение прикладных задач, Web/CLI для пользователей, импорт/экспорт офисных файлов и миграции прежних форматов приложений ведутся в отдельных проектах. Инструменты сборки и документации относятся к поддержке библиотеки.

Все вехи L01–L20 завершены. Ниже зафиксированы реализованные возможности и проверки законченного варианта библиотеки. Подробное поведение описано в [руководстве](../guide/index.md), устройство кода — в [навигаторе](../reference/code.md).

## Надёжность ядра и совместимость

С 0.10.0 завершён [контракт измеренного текстового потока](../guide/text-flow-profile.md):
самостоятельный профиль и JSON v1, подтверждённая область, строгая совместимость,
known empty/unknown и существующий flow budget без заявления полного инвентаря.
Другие политики остаются независимыми; нативного извлечения в библиотеке нет.

С 0.9.0 завершён [общий контракт соответствия объектов](../guide/object-mapping.md):
самостоятельная схема v1, устойчивые вхождения, группы связей и замены,
явная публикация/полнота, существующие состояния/диагностика, JSON,
контекстная проверка ссылок и независимый ремап. Нативное вычисление и проверка
результата не входят в библиотеку.

С 0.8.0 завершён [контракт границ таблиц и ячеек](../guide/table-borders.md):
декларации сторон и диагоналей, линии/цвета/размеры, явное наследование,
редактирование и удаление, независимая схема v1, сохранение неизвестных полей,
валидация/лимиты и диагностика потерь. Собственные тесты и пример выполняются
в CI и установленном wheel без обязательных зависимостей.

- **L01. Совместимость API и схем.** [Правила совместимости](../guide/compatibility.md) определяют версии пакета/JSON/свойств, границу публичного API, исключения и порядок устаревания. Сохранённый контракт API и независимые JSON-фикстуры v1/v2 проверяются в `tests/test_compatibility.py`; изменение контракта требует явного решения и регрессионного сценария.

- **L02. Предсказуемые ошибки JSON.** Кодек проверяет контейнеры, обязательные поля, enum, целочисленные версии, base64, идентификаторы и допустимые JSON-расширения до создания объектов. Неверные поля дают `ValueError` с расположением; допустимые неизвестные ключи сохраняются. [Правила JSON](../guide/json.md) и `tests/test_document_json.py` описывают и проверяют ошибки чтения/записи.

- **L03. Лимиты чтения и сложности модели.** [DocumentLimits](../guide/limits.md) задаёт байты, глубину, число значений и общий объём ресурсов/частей пакета. Чтение ограничено бюджетом плюс одним байтом, встроенные данные проверяются до декодирования, циклы — до рекурсивной сериализации. Запись частями остаётся атомарной. `tests/test_document_limits.py` проверяет точные границы, циклы, большое вложение и сохранность прежнего файла.

- **L04. Структурная валидация.** [Общие правила](../guide/validation.md) применяются к модели в памяти, чтению, записи и инспекции: типы элементов, ссылки/наследование стилей, ключи ресурсов, span, конечная геометрия, обрезка и топология пакета. `tests/test_model_validation.py` проверяет одинаковые нарушения в памяти/JSON, вложенные таблицы и все семь коллекций секции. Инспекция повреждённой структуры возвращает ошибки с расположением и неизвестные метрики; предупреждения допустимой модели остаются отдельными.

- **L05. Полнота сериализации.** Матрица `tests/test_document_roundtrip.py` проверяет два цикла через словарь, JSON и файл для v1/v2 и трёх режимов. Сохраняются все блоки/inline, семь коллекций секции, стили/цвета, геометрия/crop, формулы, provenance/surrogate, пустые байты, внешние источники и непрозрачные части/связи пакета. Полная модель сравнивается с исходной, включая вложенные свойства; чтение v1 даёт v2 без прикладных миграций и без открытия внешних источников.

- **L06. Контракты сравнения и политик качества.** [Правила измерений и допусков](../guide/quality.md) закреплены в `tests/test_quality_contracts.py` и `tests/test_object_matching.py`: все политики, пустая модель, пороги, дубликаты, перестановки, эвристики и бюджеты слов/выделений. Неизвестные метрики/хеши не объявляются нулями или доказанной потерей, строгие допуски отклоняют недоступность. Проверены геометрия до округления, шрифты/aliases, кратность ресурсов/частей пакета и независимый эталон расстояния слов.

- **L07. Optional math и границы XML.** [Контракт формул](../guide/formulas.md) описывает подмножество MathML/OMML и недоступность без `math`. `tests/test_mathml.py` проверяет независимые ожидаемые деревья, конструкции, неизвестные атрибуты/namespace; `tests/test_formula_xml.py` — Unicode/XML, DTD/сущности, запрет внешнего разрешения и точные пределы 1 МиБ, 4096 элементов, глубины 64. Общий разбор ограничивает исходник; OMML не отбрасывает значимый текст или данные обёртки. Проверка wheel подтверждает LaTeX и строгую недоступность XML в пустом окружении без `lxml`.

## Удобный самостоятельный API

- **L08. Единый API обхода и поиска.** [Публичные итераторы](../guide/traversal.md) находят секции, блоки, inline, выбранные типы и ресурсные ссылки во вложенных таблицах и всех семи коллекциях секции. `NodeLocation` содержит реального родителя, поле, индекс и относительный путь каждого вхождения; описаны порядок и обновление путей после структурных правок. Валидация, инспекция и инвентаризация используют общий обход; fallback/surrogate учитываются как использования ресурсов. `tests/test_traversal.py` проверяет точные пути, повторные вхождения, поддеревья, фильтры, ссылки, бюджеты и сохранение порядка текстового потока; исполняемый пример и независимый wheel подтверждают поиск и изменение без пользовательской рекурсии.

- **L09. Операции над структурой.** [Модуль операций](../guide/operations.md) копирует документ/поддерево со всеми изменяемыми данными, предоставляет вставку/замену/удаление по расположению, ограниченное UTF-8-извлечение текста и преобразование выбранных вхождений на независимой копии. Описаны мутация, порядок обработчиков, внутренние общие объекты, актуальность путей и сохранение provenance без скрытой истории редактора. `tests/test_operations.py` проверяет вложенные свойства/ресурсы/пакет, все структурные позиции, откат при превышении бюджета, ошибки обработчиков, точные текстовые границы и сохранность оригинала. `examples/operations.py` и независимый wheel выполняют сценарий копирования, изменения выбранного текста, валидации и сохранения/чтения.

- **L10. Объединение и извлечение с зависимостями.** [Композиция документов](../guide/composition.md) объединяет секции с явным отказом/переименованием конфликтующих ID и картами для каждого входа, переписывает поддержанные ссылки на стили/ресурсы без повторного изменения общих объектов. Извлечение секции, блока, inline, строки или ячейки сохраняет контекст и транзитивные зависимости; зависимости расширений можно указать явно. Описаны решения для метаданных, режимов и непрозрачных пакетов, суммарные входные бюджеты. `tests/test_composition.py` проверяет точные карты/значения ссылок, колонтитулы, оболочки, provenance, пакеты, независимость и сохранение/чтение JSON; исполняемый пример и независимый wheel подтверждают самостоятельные сценарии.

- **L11. Свойства и эффективный стиль.** [Строгие операции и разрешение стилей](../guide/styles.md) предоставляют `get_typed`/`set_typed` для известных полей всех bags, сохраняя прежние getters и mapping API расширений. Описаны преобразования, расположение ошибок, атомарность, независимые контейнеры и бюджеты. `resolve_style` и `effective_text_style` разрешают `base_style_id`, проверяют ссылки/циклы и возвращают независимый результат; `None` наследует, явные `False`, ноль и пустые значения переопределяют. `tests/test_properties.py` и `tests/test_styles.py` проверяют правила, ошибки, сохранность, длинную цепочку и JSON. Исполняемый пример и установленный wheel без зависимостей подтверждают самостоятельный сценарий.

- **L12. Согласованные операции с ресурсами.** [Управление ресурсами](../guide/resources.md) предоставляет добавление с `error`/`rename`/`replace`, поиск использований, замещение определения, удаление с явным перенаправлением ссылок и поиск точно одинаковых встроенных байтов. Общая грамматика учитывает изображения, fallback, surrogate и стандартную ссылку TextRun во всех коллекциях; отказ восстанавливает ссылки и сохраняет идентичность узлов. `embed_resources` создаёт независимую копию с ограниченным чтением локальных файлов, явным абсолютным каталогом для относительных источников и общим бюджетом ресурсов/пакета. JSON не открывает внешние источники. `tests/test_resources.py`, исполняемый пример и wheel без зависимостей проверяют политики, ошибки, общие объекты, пути, пустые данные, границы чтения и переносимость.

- **L13. Диагностика модели в памяти.** [Проверка и сравнение](../guide/checks.md) возвращают `CheckResult` без выходного пути, со структурированными `DiagnosticIssue`: код, severity, точное расположение, измерение и причина. Валидация передаёт путь от источника обнаружения, без разбора сообщений; старые строковые ошибки и отчёты поддержаны. Все политики принимают оба результата и сохраняют причины отказа/недоступности; результат сериализуется как самостоятельный `opendoc.check` v1. Проверка не обращается к внешним файлам, неизвестные байты остаются `None`, решение о публикации принадлежит потребителю. `tests/test_checks.py`, исполняемый пример и wheel без зависимостей проверяют коды, стороны сравнения, снимки, все политики, бюджеты, сериализацию и отсутствие файловых обращений.

## Расширение модели и масштабирование

- **L14. Семантические элементы.** [Заголовки](../guide/headings.md), [списки/нумерация](../guide/lists.md), [внутренние ссылки/якоря](../guide/references.md) и [богатые сноски](../guide/footnotes.md) имеют явные структуры, создание/изменение, валидацию, обход и сравнение. Композиция переписывает ID и замыкает зависимости. Собственные tagged-схемы v1 сохраняют JSON документа v2, чтение v1/v2 и bags v1; старый reader сохраняет данные в metadata/properties. Регрессионные сценарии, сохранённый API, исполняемые примеры и wheel без зависимостей проверяют самостоятельное создание, изменение, сохранение/чтение и сравнение без импортёра офисного формата.

- **L15. Уточнить контракт расширений и непрозрачных пакетов.** Реализованы [потребительские пространства имён и явные валидаторы](../guide/extensions.md), версии JSON-конвертов, диагностика неизвестных схем и границы сериализуемых типов без тихой потери состояния. [PackageGraph](../guide/packages.md) получил независимую форматонезависимую фабрику с корнем `/`, ограниченными входами и проверкой связей; прежний конструктор и чтение отсутствующего корня сохраняют DOCX-default. Сохранность расширений и явно заданного произвольного пакета проверена в текущем и прежнем reader, новые API закреплены совместимым дополнением контрактов. Примеры, полные проверки и wheel без зависимостей проходят; JSON документа v2, чтение v1/v2 и bags v1 сохранены.

- **L16. Измерить и ограничить стоимость больших документов.** [Воспроизводимые замеры](../guide/performance.md) публикуют размеры входов и время/память обхода, JSON/base64, вложенных таблиц и сопоставления дубликатов/смешанных источников. Поиск в пределах одного источника индексирован, содержимое вложенных/разделяемых узлов переиспользуется без схлопывания вхождений; пары сверены с прежним алгоритмом на 10 000 инвентарей. `MatchingLimits` ограничивает работу общим бюджетом объектов, якорей/ссылок и сносок. Превышение даёт явную недоступность без частичных потерь, строгая объектная политика отказывает; граничные сценарии, примеры и wheel без зависимостей проверены. Общая линейная сложность, максимальный RSS и ускорение всей инспекции не заявляются.

## Поддержка и выпуск библиотеки

- **L17. Проверять заявленную типизацию.** Mypy 2.4.0 в строгом режиме проверяет все производственные модули без общего подавления ошибок. Типизированы конверты инспекции, сравнения и диагностик, записи сопоставления/текстового отпечатка; сохранённый API-контракт закрепляет поля и возвращаемые типы. `tools/check_types.py` проверяет публичный API установленного wheel без импорта checkout, 12 намеренных ошибок и исполняет положительный сценарий в окружении только с OpenDoc Model. Оба прогона настроены в CI. Аудит `Any`, охват и границы статических гарантий описаны в [руководстве](../guide/typing.md); параметры, классы и JSON-версии сохранены.

- **L18. Усилить проверки независимости.** [Архитектурный тест](../../tests/test_architecture.py) рекурсивно проверяет подпакеты и отвергает вложенный импорт потребителя. [Проверка wheel](../../tools/check_wheel.py) исполняет модель, изменение, JSON, сравнение и формулы в пустом окружении только с OpenDoc Model. `tools/check_math.py` импортирует все библиотечные модули под запретом преждевременной загрузки `lxml` и повторяет один сценарий без extra и с `math`: основные операции и исходники JSON совпадают, отличается доступность XML-отпечатков/преобразования. Строгая недоступность, поддержанные/неподдержанные деревья и появление backend лишь при XML-вызове проверены. Парные установки настроены в CI; math-зависимость экспортируется из lock-файла с хешами. Граница описана в [руководстве](../guide/formulas.md).

- **L19. Подготовить воспроизводимый выпуск.** MIT-лицензия содержит подтверждённого правообладателя и год. Версия metadata берётся из `opendoc_model.__version__`, backend сборки зафиксирован. `tools/check_distribution.py` проверяет состав архивов, metadata, лицензию/`py.typed`, совпадение пакета в sdist/wheel и файлов повторно собранного из sdist wheel. Обе установки проверены в пустых окружениях без импорта checkout, включая runtime-версию и typed API; CI повторяет сценарий на Python 3.11/3.12/3.13. Тесты отвергают загрязнённые/дублированные файлы, чужую лицензию и рассогласованные версии. [Руководство по выпуску](../guide/release.md) и заметки изменений описывают текущий процесс. Публикация в реестр остаётся отдельным явно запрошенным действием.

- **L20. Расширить руководство исполняемыми сценариями.** [Каталог сценариев](../guide/examples.md) связывает ресурсы, свойства, вложенные таблицы, все колонтитулы, диагностику, политики и optional math с исполняемыми файлами; обход, преобразование и объединение также имеют самостоятельные примеры. Проверка документации запускает все сценарии из каталога examples и строго собирает сайт, справочники и навигация генерируются из AST. Ошибки span, конфликтов, типизированных свойств, измерений и неподдержанного XML показаны явно. Math-пример дополнительно проверяется в двух изолированных установках wheel, без extra и с ним. Будущие возможности в руководство не включены.

## Проверки законченного варианта

С 0.7.0 реализованы [оглавление и закладки](../guide/outline.md): собственные ID,
parents и явный порядок, назначения anchor/page/external, provenance и unknown
fields. Иерархия, ссылки, JSON, атомарные правки и бюджеты проверены. Merge
переназначает якорные назначения в выбранном конверте; extract замыкает
зависимости. Явный remap отдельно поддерживает карты entry/anchor/page ID.
Пример исполняется в установленном wheel без зависимостей.

С 0.6.0 реализована [геометрия страницы](../guide/page-geometry.md): исходная
и обрезанная области, четверть-обороты, размеры отображения и обратимые
преобразования точек/прямоугольников. Размеры страницы и геометрия аннотаций
не переинтерпретируются. JSON, композиция, unknown fields, непрозрачные коллизии,
лимиты и атомарные отказы проверены; пример исполняется независимым wheel.

С 0.5.0 реализована [семантика таблиц](../guide/table-semantics.md): явное владение
форматированной подписью, роли и headers, row/column scope, отдельные группы,
JSON и проверка ссылок/циклов. Связи сохраняются при merge/extract либо частичная
операция явно отклоняется; структурный отказ оставляет исходник целым.
Сравнение сообщает утрату деклараций. Собственные модели проверяют два JSON-цикла,
локальный язык, spans, группы и бюджеты; пример исполняется в независимом wheel.

С 0.4.0 реализована [предпочтительная ширина](../guide/styles.md#предпочтительная-ширина-таблиц-и-ячеек)
таблиц и ячеек: `WidthMeasure`, четыре вида предпочтений, явная база доли,
совместимость `width_twips`, проверка конфликта, JSON и сравнение.
Собственный случай 20×3 с 10/80/10 процентами проходит два JSON-цикла,
композицию и проверки отказа; пример исполняется в установленном wheel.
Данные не вычисляют фактическую ширину или число страниц.

После завершения L01–L20 в рабочую версию добавлен
[контракт расширенной модели](model-contract.md): восемь областей
данных реализованы как конечная типизированная optional-схема с JSON,
проверкой ссылок, лимитами и безопасными операциями. Подробности находятся в
[руководстве](../guide/integration.md). Эти дополнения доступны с 0.2.0;
совместимость с API и JSON 0.1.0 закреплена сохранёнными контрактами.

Описанное поведение реализовано и закреплено проверками. При поддержке следующих выпусков сохраняются самостоятельность пакета, публичная совместимость и версионирование собственных схем. Несовместимые изменения требуют соблюдения правил L01.

Проверка устойчивости 0.3.1 добавила восемь сквозных регрессионных сценариев:
вложенные таблицы со ссылками/ресурсами/стилями, Unicode-правки отслеживаемого
текста, независимость копий и отказы по бюджету на 2048 абзацах.
[Результат аудита](audit.md) описывает проверенные сочетания и границы выводов;
назначение и API библиотеки сохранены.

Проверки выполнять по [стандартам](CODING_STANDARDS.md): `uv sync --all-extras` → `uv run ruff check` → `uv run ruff format --check` → `uv run pytest`; справочники обновлять через `uv run python -m tools.docs generate`, затем выполнять `uv run python -m tools.docs check`. Собранный wheel проверять в пустом окружении через `tools/check_wheel.py`. Генерируемые рабочие файлы хранить в `.opendoc/`.
