# Стандарты кодирования OpenDoc Model

Эти правила относятся к самостоятельной библиотеке и проверяются её собственными инструментами. Состав модулей находится в [навигаторе](../reference/code.md), возможности — в [руководстве](../guide/index.md), завершённые возможности — в [описании](completed.md).

## Среда и стиль

Python 3.11+, UTF-8, пакет `opendoc_model` в `src/`. Установка и запуск инструментов — через `uv`, версии зависимостей фиксируются в `uv.lock`. Ruff: длина строки 130, цель `py311`, правила `E, F, I, N, W, BLE, ANN`. Форматирование проверяется отдельно. Не применять небезопасные автоматические исправления и не менять публичные сигнатуры ради стиля.

Имена функций/переменных — `snake_case`, классов — `PascalCase`, констант — `UPPER_SNAKE_CASE`. Реэкспорты явные, со списком `__all__`; приватные определения начинаются с `_`. Докстринги на русском или английском поясняют назначение, ограничения и результат; комментарии объясняют причины решений.

## Типы и публичный API

Все функции и методы в `src/opendoc_model` имеют аннотации параметров и результата, включая `-> None`. Для коллекций используются встроенные generic-типы, объединения — `X | None`. `TYPE_CHECKING` и отложенные аннотации предотвращают циклы и загрузку опциональных зависимостей.

`Any` разрешён на границах динамического JSON, расширяемых метаданных и XML-бэкенда: правило `ANN401` отключено явно. Это не замена конкретному типу в обычной логике. В тестах, примерах и инструментах `ANN` не обязателен; остальные правила и форматирование обязательны везде. Все производственные модули проверяет `uv run mypy` в строгом режиме с целевой версией Python 3.11; конфигурация находится в `pyproject.toml`, версии инструментов фиксирует `uv.lock`. Не отключать анализ модулей или ошибки целиком ради зелёного прогона. Аннотации динамических JSON/XML-границ не доказывают форму входных данных: она проверяется во время исполнения. Текущий охват описан в [руководстве по типизации](../guide/typing.md).

Публичные имена, порядок аргументов, значения по умолчанию, идентичность классов и семантику исключений сохраняют между совместимыми выпусками. Изменение JSON требует отдельного решения о версии и миграции. Результат из неизвестной схемы не восстанавливается молча.

## Граница библиотеки

В библиотеке находятся структуры, свойства, ресурсы, сериализация и структурные проверки. Чтение/запись прикладных форматов, Web/CLI, очередь, сеансы редактора и публикация результата принадлежат потребителям. Производственный код использует стандартную библиотеку; `lxml` загружается только в функции, которым нужен установленный extra `math`.

Проверка архитектуры статически ограничивает импорты, а независимый wheel проверяется без сторонних зависимостей. Измерение, отсутствие измерения и отказ различаются. Неизмеренное остаётся неизвестным; строгий лимит не считает его успехом.

## Ошибки, ресурсы и сохранение

Перехватываются только ожидаемые исключения на минимальном участке. Ошибки входных данных — информативный `ValueError`; превышение размера — `ArtifactLimitError`. Отсутствующий optional backend имеет документированный результат. Широкий перехват не маскирует дефект успешным ответом.

Пути — `Path`. Запись сначала выполняется во временный файл рядом с назначением, затем фиксируется атомарно; частичный файл очищается в `finally`. Отказ и превышение квоты оставляют предыдущий файл целым. Алгоритмы сравнения и XML-разбор имеют существующие лимиты; новые лимиты должны подтверждаться граничным сценарием.

## Проверка изменения

```text
uv sync --all-extras
uv run ruff check
uv run ruff format --check
uv run pytest
uv run mypy
uv run python -m tools.docs generate
uv run python -m tools.docs check
uv build --out-dir .opendoc/release-dist
```

Тесты проверяют контракты, ошибки, границы, сохранность данных и независимость. Не проверять внешний вид или редактируемость офисного файла структурными метриками. Справочники генерируются из AST, руководство содержит исполняемый пример, сайт собирается в строгом режиме. CI повторяет lint, форматирование, тесты, документацию и независимую установку wheel на Python 3.11/3.12/3.13.

После установки wheel без зависимостей в пустое окружение выполнять `uv run python -m tools.check_wheel --python <python-wheel>` и `uv run python -m tools.check_types --python <python-wheel>`. Второй инструмент проверяет положительный сценарий публичного API, точные ожидаемые статические ошибки и отсутствие импорта из checkout; положительный сценарий также исполняется установленным пакетом. Конверты результатов имеют сохранённый контракт ключей и типов полей, а открытые JSON-измерения остаются явными динамическими границами.
