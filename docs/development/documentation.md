# Автоматизированная документация

Руководство редактируется в `docs/guide/`. Все вехи завершены; их результаты собраны в [описании возможностей](completed.md). Справочник API, навигатор по коду и оглавление руководства строятся из исходников и заголовков; они не ведутся вручную.

## Команды

```text
uv sync --all-extras
uv run python -m tools.docs generate
uv run python -m tools.docs check
uv run python -m tools.docs serve
```

`generate` обновляет `docs/reference/`. `check` проверяет их соответствие исходникам, локальные ссылки и якоря, запускает все исполняемые примеры руководства и собирает сайт MkDocs в строгом режиме. `build` проверяет соответствие и собирает сайт. `serve` пересобирает справочники при изменении Python-кода и показывает документацию по адресу http://127.0.0.1:8003/.

Сайт находится в `.opendoc/docs-site`, промежуточные страницы — в `.opendoc/docs-source`. Ссылки на исходники открывают безопасные HTML-снимки с номерами строк. Генератор использует AST, не импортирует библиотеку и не требует её дополнительных зависимостей. Индекс API показывает определения и корневые экспорты; динамически создаваемые объявления не восстанавливаются. Ссылки на тесты обозначают прямые импорты, а не покрытие.

## Проверки изменений

После установки зависимостей запустите Ruff, проверку форматирования, pytest и mypy, затем проверку документации. `uv run python -m tools.dependencies check --site .opendoc/docs-site` проверяет актуальность описания зависимостей и лицензионные материалы сайта. CI повторяет проверки, собирает wheel, устанавливает его без зависимостей в отдельное окружение и запускает независимые сценарии. Версии Python: 3.11, 3.12, 3.13. Артефакт сайта сохраняется отдельно.


Потребитель устанавливает собранный wheel как обычную зависимость и сам управляет её обновлениями. [Стандарты кодирования](CODING_STANDARDS.md) проверяются независимо от потребителей.
