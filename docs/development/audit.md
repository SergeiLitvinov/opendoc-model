# Аудиты OpenDoc Model

## Внешняя карта векторной замены 0.10.1 — 11 октября 2026

Получен отчёт потребителя официальной модели 0.10.1 об автоматической цепочке
SVG → PNG → измеренный нативный PDF target. Созданная PNG-замена имеет scope
target и ID ресурса из свежей модели фактического результата. Исходный SVG
не объявляется растровым ресурсом source-снимка; конечные адреса измеряются
после сохранения и оптимизации.

По отчёту проверены два полных форматных/JSON-цикла, перестановка и удаление,
один объект изображения в двух местах и повторный заголовок с несколькими
target occurrences. Сопоставление с прямым PNG-путём проверялось по пикселям
для прозрачности и смешанного текста. Отсутствующая или неоднозначная связь
запрещает публикацию; отказ качества и отмена очищают targets и target-scoped
replacement. Ошибочный SVG и отсутствие связи отклоняются атомарно.

Дополнительного API модели для этой части не потребовалось. Это внешняя
проверка исходной реализации и установленного пакета потребителя; его CI
и выпуск на момент отчёта ещё не завершены. Общая композиция и split/merge
остаются непроверенными; аутентификация происхождения и полная поддержка SVG
не заявляются. Модель хранит и проверяет декларации, а вычисление изображения,
нативное связывание и проверка пикселей остаются вне её назначения. Текущий
аудит библиотеки не повторял нативный экспорт и не включает файлы потребителя.

## Внешние повторные форматные циклы карты 0.10.1 — 11 октября 2026

Получен следующий отчёт потребителя официальной модели 0.10.1: два полных
PDF → Model → JSON → PDF цикла сохраняют отдельные декларации векторного
происхождения. По отчёту перестановка и удаление не восстанавливают удалённые
объекты или прежние handles.

История хранится в инертном JSON с собственными пределами потребителя:
8 MiB и 10 000 связей. При повторном импорте адреса, геометрия и digest
проверяются вновь; нативные идентификаторы и текущие модельные ресурсы
измеряются заново. Историческое происхождение помечено artifact-declaration:
это сохранённая декларация, не аутентифицированное доказательство исходного
вектора. Повреждённая, чрезмерная или устаревшая история получает адресную LOSS;
по отчёту растровое содержимое при этом продолжает импортироваться.

Редактируемая модель содержит отдельные декларации происхождения изображений
без текущих node/resource/native handles. Агрегатная нативная карта не кешируется;
читатель потребителя возвращает вновь измеренную typed-карту. Для этой части
дополнительного API модели не потребовалось.

Это внешний отчёт о проверке исходной реализации и установленного пакета
потребителя. Его CI и новый выпуск на момент отчёта не завершены. SVG → PNG,
общая композиция и split/merge ещё не подтверждены; полный конечный сценарий
карты не объявляется закрытым. Текущий аудит библиотеки не повторял нативные
операции и не включает форматную историю или исходные файлы потребителя.

## Внешняя частичная карта нативных объектов 0.10.1 — 11 октября 2026

Получен отчёт об интеграции публичного ObjectMapping в исходную реализацию
потребителя официальной модели 0.10.1. Частичная вычисляемая карта связывает
неподдержанный вектор PDF с переданной PNG-заменой и измеренными native-only
target occurrences. По отчёту конечные адреса и признаки объектов подтверждаются
после сохранения и перенумерации; result_id определяется хешем байтов результата,
а не временным путём.

Внешние проверки подтверждают различение двух вхождений ресурса, перестановку,
удаление, два цикла JSON-кодека, перенос файла и отказ от поддельной внутренней
метки во входных properties. Отказ качества, отмена, изменение временных байтов
или ошибка публикации очищают текущие target-связи через rejected/invalidated.
Для проверенной части дополнительных изменений API модели не потребовалось.

Отчёт не закрывает полный нативный цикл: история после повторного импорта,
два полных форматных цикла, создание PNG из SVG, композиция и общие split/merge
ещё не подтверждены. Это частичная интеграционная проверка, не подтверждение
завершённого выпуска потребителя или assessment_complete для всего документа.
Вычисление карты и нативное подтверждение остаются вне библиотеки; её текущий
аудит не повторял эти операции и не включает исходные файлы потребителя.

## Внешняя интеграция текстового профиля 0.10.1 — 11 октября 2026

Получен отчёт потребителя официального пакета 0.10.1: нативная PDF-инспекция
использует публичные TextFlowFingerprint и codec TextFlowProfile. Область
`pdf-native-text-layer-v1` и профиль с версией нативного обработчика обозначают
только извлечённый текстовый слой, сохраняя границу полноты измерения.

По отчёту равный поток проходит TextPreservationPolicy("flow", 0), изменённый
отклоняется; пароль, лимит извлечения и ошибка обработчика дают unavailable.
ObjectLossPolicy(0) остаётся unavailable без самостоятельного инвентаря объектов.
Дополнительного изменения API модели для этого конечного сценария не требуется.

Это свидетельство внешней интеграционной проверки исходной реализации
потребителя с официальным пакетом модели. Оно не подтверждает завершённый
выпуск потребителя, его CI, полный reading order, OCR или полноту документа.
Нативное извлечение в текущем аудите библиотеки повторно не выполнялось;
исходные файлы потребителя и форматный backend не включены в проект.

## Согласованность измерений текста 0.10.1 — 11 октября 2026

Собственный аудит воспроизвёл ложный успех бюджета 0 и 1 при одинаковых
отпечатках слов, но разных полных хешах. Режим без бюджета отклонял такой
результат, однако выдавал противоречивое измерение за verified.

Теперь несовместимые известные декларации дают unavailable в обоих flow-путях.
Отдельный измеренный профиль также отклоняет невозможное число символов и
пустой отпечаток непустого потока/слова. Регрессии охватывают бюджеты,
неизменность входа, известный пустой модельный поток и повреждённые измерения.
Проверки не восстанавливают текст и не добавляют нативный обработчик.
API, JSON, нормализация, зависимости и самостоятельные object/formula gates
сохранены. Отступ таблицы и табуляция остаются возможными расширениями для
конкретных потребностей; наличие этих идей не означает незавершённость ядра.

Статические типы, документация, wheel без зависимостей, типизированный
потребитель, состав архивов и лицензии проверены. Неизвестные токены старого
отчёта не считаются противоречием известному равному полному отпечатку.

## Независимая область текстового измерения 0.10.0 — 11 октября 2026

Подтверждён пробел flow-политики: полный модельный инвентарь был единственным
основанием оценки, поэтому отдельный измеренный текстовый поток оставался
unavailable. Добавлен [TextFlowProfile v1](../guide/text-flow-profile.md) с
явными profile/scope/recipe, measured/completeness и причиной недоступности.
Профиль не сообщает полного инвентаря или полноты нативного документа.

Собственные синтетические входы подтверждают равный поток без object scope,
отказ при изменении текста, known empty/unknown, частичность, недоступность по
причине шифрования или лимита, несовместимость профилей и recipe, испорченные
хеши/счётчики/токены, циклы, JSON и независимость данных. Перестановка слов,
лигатуры и полноширинные символы не нормализуются в равенство. Сегментация
фрагментов и whitespace-only fingerprint v1 сохраняют прежние правила.

Object/formula gates, абзацная политика, проверка вовлечённых сносок и прежний
flow-путь модельной инспекции сохранены. Неподдержанный отдельный профиль не
откатывается к full inventory. Verified нового пути относится только к
объявленной области и помечается в метриках coverage=declared-text-scope.
Извлечение, native PDF engine, OCR и определение реального порядка чтения
не добавлены. Внешняя приёмка конкретного нативного измерения этим аудитом
не подтверждается. JSON документа и обязательные зависимости не изменены.

1382 теста пройдены локально; 3 проверки пропущены по условиям Windows.
Статические типы, строгая документация, исполняемый пример в wheel без
зависимостей и типизированный потребитель проверены. MIT LICENSE, состав
архивов и перечень 29 пакетов среды разработки/сборки проверены без изменений.

## Контракт соответствия объектов 0.9.0 — 11 октября 2026

Аудит выявил пробел: Provenance, якоря, ресурсы и существующие отчёты отдельно
хранят происхождение и диагностику, но не задают однозначной связи вхождений
источника с заменой и конкретным результатом. Добавлен самостоятельный
[ObjectMapping v1](../guide/object-mapping.md), который переиспользует эти
структуры и не меняет JSON документа или прежние конструкторы отчётов.

Собственный синтетический сценарий объявляет два вхождения одного ресурса и
две растровые замены. Он проверяет точный JSON, два цикла, неизвестные поля,
перестановку, явное переназначение ссылок и native locators, удаление узлов и
ресурсов, многие-ко-многим без повторного учёта, unknown и подтверждённое
отсутствие, ограниченные бюджеты и атомарные отказы. ResourceKind — декларация,
не проверка изображения; синтетические байты не являются нативным экспортом.

Отдельно проверен жизненный цикл staged → published, отказ качества, отмена и
утрата актуальности результата. Смена стадии не подтверждает прежние адреса:
они сбрасываются до нового явного измерения. При отказе текущие target-связи
исчезают, исходное свидетельство остаётся независимым; повторный запуск требует
новой карты и новой идентичности результата. Полнота охватывает только
объявленные вхождения и сама по себе не разрешает политики качества.

Локальные проверки подтверждают типы, прежний JSON и отсутствие новых
обязательных зависимостей. Код нового модуля использует стандартную библиотеку
и существующее ядро; сторонние реализации, нативные файлы и ресурсы потребителей
не включены. MIT LICENSE и перечень зависимостей остаются прежними.
Компоновка, форматные обработчики, чтение адресов и проверка фактического файла
остаются обязанностью вызывающего кода. Отступ таблицы, позиции табуляции и
частичная область оценки текста рассматриваются отдельно от этой карты.

Строгая сборка документации, 23 исполняемых примера, wheel без зависимостей,

## Совместная проверка деклараций таблицы 0.8.1 — 11 октября 2026

Продолжен собственный аудит сохранности данных в пределах модели. Синтетический
сценарий в [test_workflows.py](../../tests/test_workflows.py) совмещает
форматированную подпись с якорем, header/data и связь headers, абсолютную
ширину таблицы и относительную ширину ячейки, внутреннюю линию и диагональ,
прямое `none`/`nil` и неизвестные поля разных деклараций.

Два JSON-цикла сохраняют исходную модель. Изменение толщины одной стороны
не меняет ширину, подпись или связи заголовков; сравнение сообщает только
изменение границы. Extract сохраняет зависимость подписи, merge переназначает
якорь подписи и таблицы, оставляя локальные headers согласованными.
Последующая правка объединённой таблицы не изменяет исходные документы;
повторный JSON сохраняет результат. Смежные проверки границ, ширины и семантики
подтверждают лимиты, атомарные отказы и сохранность неизвестных полей.

Новых дефектов по этим воспроизводимым сценариям не обнаружено. Вычислительный
код, публичный API, JSON и зависимости не менялись; добавлен сквозной сценарий
для двух явных состояний отключения линии. Проверка нативных документов,
вычисленной компоновки и внешнего отображения в этот аудит не входит.

## Внешняя проверка контракта границ 0.8.0 — 11 октября 2026

Получен отчёт внешнего потребителя официального пакета OpenDoc Model 0.8.0.
Это свидетельство интеграционной проверки; описанные нативные циклы и запуск
редактора в текущем аудите библиотеки повторно не выполнялись.

По отчёту `Border`/`BorderSet`, `get_borders`, `set_border` и `set_borders`
использованы для прямых деклараций таблиц и ячеек. Два цикла DOCX → JSON → DOCX
сохранили шесть сторон таблицы, различие `none`/`nil` и диагонали ячейки.
Word 16.0.17932 подтвердил исходные сплошные линии, толщину и цвет, а также
нативную правку на двойную красную линию с последующим циклом. Правки и удаление
не восстановили прежние нативные дополнительные данные. Неподдержанные стили
и цвета темы получили диагностику LOSS с расположением; непредставимые значения
отклонялись атомарно. Это результаты внешнего преобразования, а не новые
обработчики или гарантии самого ядра.

Внешняя проверка также сообщила побайтовое совпадение MIT LICENSE официальных
wheel 0.8.0 и 0.7.2. Исходные отчёты и файлы потребителя не включались в проект.
Результат относится к конечному профилю прямых деклараций и указанной версии
пакета; внешняя приёмка исправления 0.8.1 этим отчётом не подтверждается.

Новых требований к общей модели по этому профилю не выявлено. Эффективная
толщина двойной линии может нормализоваться редактором; библиотека сохраняет
заявленное значение. Условные и наследуемые нативные стили, RTL-преобразования,
конфликты соседних границ и межформатное рисование остаются вне назначения
модели. [Контракт границ](../guide/table-borders.md) продолжает определять
явное наследование и сравнение деклараций без обещания внешнего отображения.

## Проверка границ и непрозрачных данных 0.8.1 — 11 октября 2026

Воспроизведена ложная диагностика `table-border-loss`: изменение вложенного
`kind` из `line` в `none`/`nil` в неизвестных полях интерпретировалось как
отключение линии. Теперь это правило применяется только к известным записям
сторон `BorderSet.sides`. Изменение непрозрачных значений даёт
`table-border-change`; удаление данных по-прежнему диагностируется как потеря.
Собственные регрессии проверяют оба владельца, неизвестные поля набора и

## Границы назначения

Расширенная модель хранит сведения о полях, комментариях, ревизиях, сценах,
диаграммах, доступности, медиа, книгах и математических деревьях. Это структуры
в памяти, JSON и проверки. Она не вычисляет поля/формулы, не исполняет actions,
не отрисовывает файлы и не включает редактор, сеть, OCR или внешние движки.
Сохранение исходных bytes или визуальной замены не приравнивается к сохранению
редактируемой семантики. Профили — конечные заявления потребителя, а не обещание
поддержки полного файлового стандарта.
