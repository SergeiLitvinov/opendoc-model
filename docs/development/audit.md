# Аудиты OpenDoc Model

## Проверка границ и непрозрачных данных 0.8.1 — 11 октября 2026

Воспроизведена ложная диагностика `table-border-loss`: изменение вложенного
`kind` из `line` в `none`/`nil` в неизвестных полях интерпретировалось как
отключение линии. Теперь это правило применяется только к известным записям
сторон `BorderSet.sides`. Изменение непрозрачных значений даёт
`table-border-change`; удаление данных по-прежнему диагностируется как потеря.
Собственные регрессии проверяют оба владельца, неизвестные поля набора и
стороны, вложенные массивы и настоящее отключение линии без известных атрибутов.
Публичный API, JSON и зависимости не изменены.

## Приёмка контракта границ 0.8.0 — 10 октября 2026

Завершён [контракт границ таблиц и ячеек](../guide/table-borders.md): внешние
и внутренние стороны, диагонали, линии/цвета/размеры, различие отсутствия,
`none`/`nil`, явное наследование и безопасные правки. Собственные синтетические
входы проверяют два JSON-цикла, сохранность неизвестных полей, композицию,
лимиты, атомарные отказы и диагностику. Изменение структуры таблицы без
деклараций не выдумывает потерю границ.

1301 тест пройден локально; 3 проверки пропущены по условиям Windows.
Статические типы, строгая сборка сайта, wheel без зависимостей и соответствие
wheel/sdist проверены. Официальный пакет 0.7.2 сохраняет новые декларации
непрозрачно без потерь. CI и релиз 0.8.0 прошли на Python 3.11/3.12/3.13;
контрольные суммы опубликованных пакетов и руководство Pages проверены.
JSON документа v1/v2, bags v1 и обязательные зависимости сохранены.
Компоновка, рисование и нативные конфликты границ остаются вне API модели.

## Проверка сохранности дополнительных полей — 8 октября 2026

Повторно проверены операции ширины, геометрии страницы и оглавления:
непрозрачные коллизии, неизвестные версии, ограничения и атомарные отказы.
Новых дефектов по этим сценариям не обнаружено. Уточнено различие полной замены
меры ширины и изменения прочитанной записи с сохранением extra.
Исполняемый пример показывает правку через `dataclasses.replace`, сохранность
неизвестного поля и независимость исходника. Вычислительный API и JSON не менялись.

## Уточнение геометрического контракта Box — 8 октября 2026

Направление clockwise уже было задано общим контрактом координат, но центр
поворота и различие рамки с осевым bbox не были описаны. Докстринг Box и
[руководство](../guide/integration.md#рамка-элемента-и-поворот-box) теперь
определяют рамку до поворота и её центр. Bbox повёрнутой фигуры — отдельное
измерение; исходная affine-геометрия содержимого остаётся данными расширения
адаптера. Поворот страницы применяется отдельно.

Конструктор, поля, числовые данные, JSON и вычислительный код не менялись.
Новые типы и эвристическая миграция не добавлены. Иная прежняя конвенция
обрабатывается явно её владельцем; наличие частного ключа не меняет семантику
Box автоматически. Это уточнение документации, без нового выпуска пакета.

## Проверка передачи лимитов 0.7.2 — 8 октября 2026

Воспроизведена потеря явно заданного бюджета при чтении ширины и построении
снимков семантики таблицы. Неизвестное поле глубиной 70 допускалось при
max_depth 96, но внутренний helper применял стандартные 64. Теперь чтение,
инспекция и сравнение последовательно используют бюджет вызывающего.
Исключение `ArtifactLimitError` при чтении ширины не превращается в неизвестное
измерение, а некорректные legacy-свойства по-прежнему остаются неизвестными.

Собственные проверки охватывают неизвестные поля таблицы/строки/ячейки и ширины,
полный снимок инспекции, сравнение документа с собой, запись независимой ширины
и явный отказ самостоятельного инвентаря при превышении стандартного лимита.
Исходники внешних форматов не используются, API и сохранённые схемы не расширены.

## Проверка граничных контрактов 0.7.1 — 8 октября 2026

Воспроизведены и исправлены три дефекта новых API: зависимость лимита глубины
headers от порядка ячеек, перезапись/удаление непрозрачного null в ключе геометрии
страницы и в ключе оглавления. Исправления не расширяют назначение библиотеки.
Глубина учитывает целую цепочку, включая ранее проверенные зависимости;
занятость непрозрачного ключа определяется наличием, а не значением.

Собственные регрессионные входы проверяют цепочку длиной 13 при max_depth 12/13,
оба порядка ячеек, null/False/0/строку/массив и неизменность исходника при отказе.
Никакие внешние URI или пользовательские файлы не открываются. Новые структуры,
обязательные зависимости и версии JSON не добавлены.

## Обновление модельного контракта 0.7.0 — 8 октября 2026

После первоначального рассмотрения реализованы предпочтительная ширина (0.4.0),
семантика таблиц (0.5.0), геометрия страницы (0.6.0) и оглавление (0.7.0).
[Контракт](model-contract.md) и руководства описывают действующий API и границы.
Нижеследующая проверка отражает исходное состояние 0.3.x, а не отсутствие этих
возможностей в текущей версии. Новые модели проверены собственными синтетическими
входами, JSON, валидацией, лимитами и независимым wheel. Внешняя приёмка файловых
форматов остаётся отдельной задачей потребителя. Обязательные зависимости,
integration v1 и JSON документа v1/v2 сохранены.

## Первоначальная проверка потребительского контракта 8 октября 2026 (0.3.x)

Переданные наблюдения о чтении и записи внешних форматов не воспроизводят
самостоятельный дефект модели. Проверка потребителя на 0.3.0 не доказывает
проверку 0.3.1. Текущий вывод относится к контрактам и исходникам модели;
визуальная приёмка и повторные циклы внешних форматов здесь не выполнялись.

| Требование | Существующий контракт и граница |
| --- | --- |
| Формальный заголовок | `Heading`, `set_heading`/`get_heading`, JSON и сравнение роли уже есть; восстановление роли из внешнего файла относится к адаптеру |
| Язык и доступность | `Accessibility` хранит role/alt/language для anchor узла; произвольные JSON-данные могут храниться в metadata/properties. Это не автоматическое восстановление языка документа или доступности внешнего файла |
| Подпись и заголовки таблицы | `TableProperties` и `TableCellProperties` сохраняют дополнительные JSON-ключи; `repeat_header` обозначает повтор строки, а не семантическую связь заголовка с ячейкой. Типизированных caption, роли ячейки и связей заголовков сейчас нет; общий контракт требует отдельного модельного воспроизведения |
| Исходный объект и визуальная замена | `Provenance`, `VisualSurrogate`, `Resource`, `UnknownFragment` и `PreservationRecord` уже представляют происхождение и разные состояния сохранности. Соответствие записи реальной потере и качество внешнего отображения проверяет адаптер/потребитель |
| Аннотации, формы и действия | `Annotation`, `FormControl`, `DocumentPage`, инертные action-данные и JSON уже есть; создание нативного объекта результата, компоновка и обрезка текста относятся к адаптеру |

На момент первоначальной проверки новых задач реализации по этому
свидетельству не было подтверждено. Оглавление и геометрия тогда рассматривались
как требования; позднее они реализованы в 0.6.0/0.7.0, как описано выше и в
[контракте развития](model-contract.md). Этот исторический вывод не описывает
отсутствие возможностей в текущей версии. Новый TODO-файл не создавался.

Для принятия нового модельного требования нужен собственный минимальный вход
без пользовательских данных, ожидаемая модель и JSON, конкретный недостаток
публичного API, правила чтения/валидации/сравнения и происхождения. Приёмка должна
включать старые JSON, неизвестные измерения, лимиты и сохранность исходника при
отказе. Необходимость отмены долгой операции обосновывается конкретным вызовом;
отмена внешнего обработчика не переносится в модель автоматически.
Опубликованный пакет потребитель проверяет отдельно без локальных патчей;
успех проверки модели не заменяет эту интеграционную приёмку.

## Проверка устойчивости 0.3.1

Дата: 7 октября 2026. Сквозные сценарии в
[test_workflows.py](../../tests/test_workflows.py) проверяют совместную работу
существующих операций:

- отчёт с двухуровневой таблицей, внутренней ссылкой на другой раздел,
  встроенным изображением и наследуемым стилем проходит JSON, извлечение
  с замыканием зависимостей и объединение с переименованием конфликтующих ID;
- правка текста внутри таблицы сохраняет диапазон, ссылки и байты ресурса;
  проверены кириллица, иероглифы, комбинируемый знак, emoji с ZWJ и удаление;
- попытки обойти правку отслеживаемого текста или удалить его узел отклоняются
  без изменения исходника;
- внешние байты остаются неизвестными при JSON, извлечении и сравнении;
  операции не открывают источник;
- документ из 2048 абзацев проходит JSON и преобразование текста; недостаточный
  бюджет числа значений даёт явный отказ и сохраняет исходный документ.

Это синтетические модели с заданным ожидаемым результатом, а не проверка
импорта офисных файлов или визуального представления. В этих сценариях дефекты
производственного кода не обнаружены. Новые API и зависимости не добавлены;
JSON v1/v2 и сохранённый контракт API проверяются существующей регрессией.
Unicode-смещения остаются индексами кодовых точек Python: комбинируемый знак
и последовательность ZWJ могут занимать несколько позиций.

## Исправленные ошибки

| Проверка | Проблема и исправление |
| --- | --- |
| Числа ячеек | Целое число преобразовывалось в float и могло потерять точность. SheetCell теперь различает int/float/bool, JSON сохраняет большое целое точно |
| Отчёт сохранения | Отдельный preservation_result не проверял дубли признаков и причины несемантического состояния. Он использует ту же проверку полноты и согласованности, что и документ |
| Миграции свойств | Проверка схемы использовала metadata даже для схемы properties. Введён явный scope и проверка правильного носителя |
| Медиа и visual fallback | Существующий ID мог указывать на ресурс неправильного рода. Маски/poster/visual требуют изображение; audio/video требуют соответствующий media type |

Регрессии входят в [test_integration.py](../../tests/test_integration.py).
Ошибки и исчерпание бюджета оставляют предыдущий документ/extension bag целым.
Исходные spans остаются привязанными к исходному снимку; редактирование диапазонов
выполняется отдельной операцией с явными границами и affinity.

## Границы назначения

Расширенная модель хранит сведения о полях, комментариях, ревизиях, сценах,
диаграммах, доступности, медиа, книгах и математических деревьях. Это структуры
в памяти, JSON и проверки. Она не вычисляет поля/формулы, не исполняет actions,
не отрисовывает файлы и не включает редактор, сеть, OCR или внешние движки.
Сохранение исходных bytes или визуальной замены не приравнивается к сохранению
редактируемой семантики. Профили — конечные заявления потребителя, а не обещание
поддержки полного файлового стандарта.

## Документация и лицензии

Убраны упоминания других прикладных проектов, их планы и названия задач.
Документы описывают только API OpenDoc Model, его поддержку, выпуск и зависимости.
Руководство содержит исполняемые примеры, справочники генерируются из исходников;
проверяются ссылки, якоря и строгая сборка сайта. Уточнена установка 0.2.0,
область миграций и сохранение целых чисел.

MIT-лицензия OpenDoc Model сохранена. Обязательных внешних runtime-зависимостей нет.
При аудите 0.2.0 все **35** Python-пакетов из объединения lockfile и build requirement были перечислены
в [документации зависимостей](dependencies.md), включая транзитивные, их роли,
основные лицензии и хеши исходных уведомлений. Проверка состава добавлена в CI.

Из сайта исключены неиспользуемые vendor CSS/JS и Font Awesome fonts. Для поиска
сохранены неизменённые исходники и опубликованы полные BSD/MIT/MPL-1.1-уведомления.
Проверка публикации контролирует наличие лицензий, равенство исходников поиска
установленному MkDocs и отсутствие лишних шрифтов.

У optional lxml отдельно отмечены native-компоненты и unlicensed isoschematron
resources из upstream LICENSES.txt. Сторонние компоненты не входят в wheel
OpenDoc Model; его math-код использует XML backend, но не эти isoschematron resources.
Весь lxml wheel не объявляется исключительно MIT или безусловно чистым.
Репакованное окружение проверяется отдельно.

## Приёмка выпуска

Локальная приёмка включает Ruff, форматирование, strict mypy, весь pytest,
проверку зависимостей и сайта, сборку wheel/sdist и сравнение их содержимого,
повторную сборку из sdist, независимую установку без зависимостей, публичный
typed consumer и ветви optional math. Сохранённые контракты API и JSON 0.1.0
не переписаны для обхода проверки совместимости.

GitHub release workflow повторяет проверки на Python 3.11/3.12/3.13 перед
публикацией. Затем атомарно записывает проверенную версию/тег, публикует wheel,
sdist и SHA256SUMS, обновляет сайт Pages. Предыдущий выпуск не перезаписывается.
Исходный архив не включает окружения, кэши или временные рабочие файлы.
