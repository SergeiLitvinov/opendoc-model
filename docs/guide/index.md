OpenDoc Model — библиотека структур документов для Python. Она позволяет создать модель, хранить её в JSON и проверить структурные изменения. Конвертация PDF/DOCX/PPTX, распознавание, Web и шаблонизатор остаются в приложениях, подключающих библиотеку.

## Установка

Для разработки выполните `uv sync --all-extras --locked`. Для установки скачайте wheel из GitHub Releases
или соберите `uv build --out-dir .opendoc/release-dist`, затем установите его через
`uv pip install путь/к/opendoc_model-0.7.2-py3-none-any.whl`. На PyPI пакет пока не опубликован.
Импорт — `opendoc_model`, имя дистрибутива — `opendoc-model`.

Основная библиотека использует стандартную библиотеку Python. Для XML-формул
добавьте extra: `uv pip install "путь/к/opendoc_model-0.7.2-py3-none-any.whl[math]"`.
Без него XML-проверка недоступна; строгий лимит не считает отсутствие измерения успехом.
[Полный состав и лицензии](../development/dependencies.md) описывают границы optional-компонентов.

## Создать и сохранить документ

Исполняемый пример находится в [examples/basic.py](../../examples/basic.py). Проверка документации запускает все примеры из `examples/`; этот сценарий создаёт JSON во временном каталоге, читает обратно и сравнивает структуру.

```python
from opendoc_model import DocumentModel, Section, Paragraph, TextRun
from opendoc_model import save_document, load_document

document = DocumentModel(sections=[Section(blocks=[Paragraph(content=[TextRun("Первый документ")])])])
assert document.validate() == []
save_document(document, "document.json")
restored = load_document("document.json")
```

Раздел содержит блоки: абзацы, таблицы, изображения и другие элементы модели. Содержимое абзаца хранится в текстовых фрагментах и встроенных объектах. Файловые ресурсы присоединяются к документу по идентификатору; ссылки на отсутствующие ресурсы выявляются `validate()`.

[Структурная валидация](validation.md) описывает правила типов, ссылок, геометрии, таблиц и пакетов, а также различие ошибок и предупреждений инспекции.

[Обход и поиск](traversal.md) позволяет найти изображения, абзацы и ресурсы во вложенных таблицах и колонтитулах без пользовательской рекурсии.

[Копирование и изменения](operations.md) описывает независимые копии, вставку/замену/удаление, извлечение текста и преобразование выбранных элементов с сохранением оригинала.

[Объединение и извлечение](composition.md) создаёт самостоятельный документ со стилями/ресурсами, явным разрешением конфликтов и проверкой непрозрачного пакета.

[Свойства и эффективный стиль](styles.md) описывает строгие операции с известными полями и разрешение наследования для абзаца и текстового фрагмента.

[Ресурсы и переносимость](resources.md) предоставляет управление определениями/использованиями, поиск одинаковых данных и явное встраивание локальных файлов.

## Проверить изменения

[Семантические заголовки](headings.md) задают роль и уровень абзаца, поиск и сравнение независимо от оформления.

[Проверка и сравнение в памяти](checks.md) возвращает результат без выходного файла, с кодами, точными путями, измерениями и причинами отказа.

[Сравнение и политики качества](quality.md) описывает измерения, неизвестность, строгие допуски и вычислительные пределы.

[Формулы и optional math](formulas.md) описывает поддержанный MathML/OMML, точные отпечатки LaTeX и ограничения XML.

`inspect_document_model(document)` собирает структуру и доступные свойства; `compare_inspections(before, after)` возвращает сохранность текста и соответствия объектов. `ObjectLossPolicy` и другие политики записывают результат проверки в `ConversionReport`. Это свидетельства структуры; они не подтверждают внешний вид в Word или возможность редактирования в целевой программе.

## Совместимость и границы

[Правила совместимости](compatibility.md) определяют публичный API, версии пакета и схем, порядок устаревания и приёмку изменений формата.

[JSON и ошибки](json.md) описывают допустимые значения, проверку полей и расположение ошибки во входном документе.

JSON имеет идентификатор `opendoc.document`; запись использует версию 2, чтение поддерживает 1 и 2. Метаданные, ресурсы и дополнительные ключи свойств сохраняются. Неизвестные версии формата, схемы свойств и типы блоков отклоняются: произвольный будущий формат не обещан. Файловое сохранение атомарно и ограничено 100 МБ.

Приложения импортируют библиотеку напрямую: `from opendoc_model import DocumentModel`. Адаптацию собственных прежних импортов и идентификаторов файлов выполняет потребитель.

Чтение JSON сохраняет ресурсы с их идентификаторами и свойствами. Значения вроде `docx-footnotes` или `role="docx-styles"` не запускают миграцию и не создают `PackageGraph`. Граф пакета восстанавливается только из явно заданного поля `package`; преобразование прежних соглашений о ресурсах выполняется до передачи данных библиотеке.
