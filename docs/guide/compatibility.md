# Совместимость OpenDoc Model

Версия пакета, версия JSON и версия схемы свойств независимы. Обновление пакета само по себе не меняет формат сохранённого документа.

[Изменения выпусков](changes.md) описывают принятые изменения библиотеки и их последствия для потребителей.

## Версии пакета

Пакет использует `MAJOR.MINOR.PATCH`. До 1.0 совместимость сохраняется внутри одной серии `0.MINOR`: patch исправляет ошибки, включая ошибочное принятие повреждённых данных; несовместимое изменение API требует следующего minor и описания перехода. Добавление API также выпускается в следующем minor. Номер `0.x` не разрешает менять контракт в patch без предупреждения.

Начиная с 1.0 patch исправляет ошибки, minor добавляет совместимые возможности, major допускает несовместимые изменения. Исправление заведомо неверных данных или недоказанного успешного измерения не обязано сохранять ошибочное поведение. Такое исправление описывается в заметках выпуска и подтверждается тестом входного нарушения; допустимые документы и вызовы сохраняют совместимость.

## Публичный API

Публичны имена из `opendoc_model.__all__`, `__version__` и имена из `__all__` публичных модулей. Для модулей без `__all__` публичны собственные функции и классы без начального `_`, показанные в [навигаторе](../reference/code.md). Импортированные вспомогательные имена не являются API. Приватные имена и содержимое `tools` не имеют гарантий совместимости.

Совместимое изменение сохраняет прежние импорты, идентичность реэкспортируемых классов, порядок и виды аргументов, их имена и значения по умолчанию, доступные поля/свойства, значения enum и смысл результата. Можно добавлять новые экспорты и необязательные аргументы после существующих. Нельзя превращать необязательный аргумент в обязательный или менять значение `None` и пустых коллекций.

Типы исключений являются контрактом: повреждённое представление документа даёт `ValueError` или его документированный подкласс, превышение квоты — `ArtifactLimitError`, ошибки файловой системы сохраняют соответствующий `OSError`. Формулировки сообщений могут уточняться; потребитель не должен разбирать их как машинные коды. Прямое создание объектов модели имеет собственные проверки; контракт JSON не означает произвольное приведение типов при вызове конструктора.

Перед удалением публичного API его замена описывается в руководстве и заметках выпуска; вызов устаревшего API выдаёт `DeprecationWarning` с указанием замены и версии удаления. До 1.0 сохраняется хотя бы один полный minor-выпуск с предупреждением, после 1.0 — хотя бы два minor-выпуска и удаление только в major. Исключение допускается для устранения подтверждённой уязвимости или потери данных с явным описанием причины. В текущем API устаревшие имена не объявлены.

Зафиксированный контракт находится в `tests/fixtures/compatibility/api-0.1.json`; тест сверяет импорты, идентичность, параметры, enum и доступность членов. Он разрешает совместимые добавления. Фикстура не перезаписывается автоматически при запуске тестов. Она не доказывает совместимость поведения: для этого используются сценарии в тестах модели, сериализации и сравнения.

## Версии JSON и свойств

Идентификатор JSON — `opendoc.document`. Чтение поддерживает целые версии 1 и 2, запись всегда создаёт версию 2. После чтения модель нормализована к текущей версии: `DocumentModel.version == 2`. Поле `property_schema_version` равно 1; его отсутствие в сохранённых документах трактуется как 1. Отсутствующие необязательные поля восстанавливаются по документированным значениям модели.

Неизвестный идентификатор, версия JSON, версия свойств и тип элемента отклоняются. Дополнительные JSON-ключи в `properties` и `metadata` сохраняются. Иные неизвестные поля не являются механизмом расширения и не имеют гарантии сохранения; новое содержимое помещают в эти словари или вводят через явное изменение схемы.

Изменение смысла поля, новый обязательный атрибут, удаление поля или новый тип элемента требуют отдельного решения о версии формата и правилах чтения старой схемы. Совместимые дополнения тоже оцениваются на сохранность при чтении прежним кодом; номер версии не выбирается автоматически по версии пакета. Схема свойств версионируется отдельно при изменении смысла её стабильных полей. Новые пользовательские JSON-ключи в словарях расширений не меняют номер схемы.

Решение записывается в руководство и заметки выпуска: старый и новый контракт, затронутые сценарии, версия пакета/схемы, способ перехода, поддерживаемые старые версии и регрессионные фикстуры. Существующая фикстура сохраняется для каждого поддерживаемого формата. Проверка API или схемы не отключается ради зелёного теста: изменение базового контракта требует такого решения.

Сохранённые `document-v1.json` и `document-v2.json` в `tests/fixtures/compatibility/` написаны независимо от сериализатора; тесты читают их и проверяют содержимое до повторной записи. Это не обещание поддержки всех прикладных legacy-форматов. Роли вроде `docx-footnotes` не запускают миграцию: библиотека сохраняет ресурсы и явно заданный `package`, а преобразования форматов приложения выполняет потребитель.

## Optional math

Базовый импорт, модель и JSON не требуют `lxml`. Extra `math` даёт XML-проверку поддержанных формул. Отсутствие бэкенда или неподдержанная формула означает недоступность измерения, а не доказанную сохранность. Строгая политика в таком случае не проходит. Расширение поддержанного подмножества формул не обещает чтение произвольного MathML/OMML.
