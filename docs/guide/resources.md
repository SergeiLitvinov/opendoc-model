# Управление ресурсами и переносимый документ

Ресурс хранится в `document.resources` под своим `Resource.id`. У него есть
встроенные байты `data`, внешний файловый/URI-источник `source` или оба поля.
OpenDoc Model обычно сохраняет эти поля как данные. Чтение JSON, поиск ссылок,
сравнение и операции с определениями не открывают внешний источник.
Исполняемый сценарий — `examples/resources.py`.

## Добавить и заменить определение

```python
add_resource(document, resource, *, conflicts="error", limits=None)  # -> str
replace_resource(document, resource_id, resource, *, limits=None)  # -> Resource
```

Обе функции изменяют существующий документ на месте, сохраняя объект словаря
ресурсов и структурные узлы. Входной ресурс копируется со всеми изменяемыми
properties и provenance. Сначала проверяются исходный документ и входной
ресурс, затем кандидат результата; только после проверки обновляется словарь.
Отказ не оставляет частичных изменений. Все ссылки продолжают обозначать ID.

`add_resource` возвращает фактический ID добавленной копии. `ResourceConflictPolicy`
задаёт три политики:

| Политика | Поведение при существующем ID |
| --- | --- |
| `error` (по умолчанию) | `ValueError`, даже если определение равно прежнему |
| `rename` | Первый свободный суффикс `~2`, `~3`, …; новый ID получает только копия |
| `replace` | Прежний ID получает новое определение; существующие использования остаются на этом ID |

При `rename` уже существующие ссылки не перенаправляются: фактический ID
возвращается вызывающему коду для создания новых элементов. Стиль и ресурс
имеют независимые пространства ID. Существующие определения сохраняют порядок,
новое добавляется в конец. Автоматического объединения одинаковых данных нет.

`replace_resource` требует существующий `resource_id`, возвращает прежний
живой объект ресурса, уже отсоединённый от словаря. ID входного ресурса должен
быть допустимым, но ID его копии нормализуется к указанному целевому ID.
Старый ресурс и входная замена не меняются. Изменение media type/kind возможно:
это явное решение вызывающего кода, библиотека не проверяет содержимое файла
декодером изображения и не обещает сохранение внешнего вида.

Прежний `DocumentModel.add_resource(resource)` остаётся совместимым строительным
методом: он возвращает `None`, хранит переданный объект напрямую и отклоняет
повторный ID. Для независимой копии, политики конфликта и полной проверки
используйте новую функцию из `opendoc_model`.

## Найти использования и удалить

```python
find_resource_uses(document, resource_id, *, limits=None)  # -> tuple[ResourceReference, ...]
remove_resource(document, resource_id, *, replacement_id=None, limits=None)  # -> Resource
```

Поиск требует существующий ID и возвращает каждое известное использование
в [порядке обхода](traversal.md), с владельцем, полем и точным путём. Для
неиспользуемого ресурса результат пустой. Повторные вхождения общего объекта
имеют отдельные пути. Владельцы живые; снимок ID и пути нужно обновить после
изменений модели.

Учитываются основные `Image.resource_id`, `Image.properties.fallback_resource_id`,
`TextRun.properties.resource_id` и `visual_surrogate.resource_id` у всех
поддержанных элементов, включая таблицы, абзацы и формулы. Поиск и изменение
используют общую грамматику ссылок с композицией, валидацией и инвентаризацией.
Обход включает вложенные таблицы и все семь коллекций секции.

Удаление возвращает отсоединённый исходный ресурс. Неиспользуемый ресурс можно
удалить напрямую. Если есть ссылки, отсутствие `replacement_id` даёт `ValueError`
с первым расположением. Явная замена должна существовать и отличаться от
удаляемого ID. Все известные использования перенаправляются, затем проверяется
кандидат результата. Неудачная проверка, в том числе квота, восстанавливает
прежние ссылки и оставляет словарь нетронутым. Общие bags и surrogate сохраняют
идентичность; изменение их поля видно во всех связанных вхождениях.

Произвольные ключи расширений, hyperlinks, текст XML, исходные пути provenance
и связи/байты `PackageGraph` не интерпретируются как ссылки на ресурсы. Их
зависимости вызывающий код обрабатывает явно. Ресурс может иметь тот же ID, что
и имя/роль части пакета, без автоматического перенаправления непрозрачного графа.

## Найти одинаковые встроенные данные

```python
find_duplicate_resources(document, *, limits=None)  # -> tuple[tuple[str, ...], ...]
```

Результат содержит группы хотя бы из двух ID с точно равными `data`. Порядок
групп и ID определяется первым появлением в словаре. Пустые байты участвуют;
`data=None` не участвует. Совпадение внешнего `source` не доказывает равенства
данных и не вызывает I/O. Равенство байтов не требует совпадения kind, media type,
properties или provenance и не означает взаимозаменяемость определений.
Данные сравниваются точно, без принятия совпадения хеша за доказательство.
Функция ничего не удаляет и не перенаправляет. Для объединения явно выберите
определение и используйте `remove_resource(..., replacement_id=...)`.

## Явно встроить локальные файлы

```python
embed_resources(document, *, base_dir=None, resource_ids=None, limits=None)  # -> DocumentModel
```

Функция возвращает независимую копию документа. По умолчанию выбираются все
определения, включая неиспользуемые. `resource_ids` задаёт выбранные ID в порядке
входа; повторы игнорируются, пустой iterable оставляет данные копии прежними.
Неизвестный ID и строка вместо iterable дают `ValueError`. Потребление iterable,
включая повторяющийся бесконечный генератор, ограничено `max_nodes`.

Для выбранного ресурса с `data is not None` существующие байты имеют приоритет:
источник не открывается, даже если это URL или отсутствующий файл. Для
`data=None` читается локальный обычный файл. У выбранных ресурсов `source`
становится `None`; provenance и его история сохраняются без неявного события.
Невыбранные ресурсы копируются целиком, включая внешние источники. Поэтому
переносимость всех ресурсов требует выбора всех внешних определений; байты
непрозрачного пакета и пользовательские внешние ссылки эта операция не меняет.

Абсолютный native-путь не требует `base_dir`. Относительный `source` разрешается
только относительно явно заданного абсолютного локального `base_dir`.
Каталог JSON или текущая рабочая папка не подставляются автоматически.
Компоненты `..` и обычные ссылки файловой системы разрешаются средствами ОС:
`base_dir` — якорь, а не граница доступа. URI (`http:`, `https:`, `file:`, `data:`),
UNC/device-пути и drive-relative `C:foo` отклоняются. Windows drive-путь допустим
только на Windows. Непустой local path может содержать пробелы/Unicode; percent
escapes и `~` не декодируются. Сначала разрешаются все выбранные пути, затем
начинается чтение. Функция не скачивает сетевые URI.

Ошибки доступа/отсутствия файлов сохраняют соответствующий `OSError`; каталог
или иной необычный файл даёт `ValueError`. Каждый файл читается не более
`min(max_bytes, оставшийся max_embedded_bytes) + 1` байт. Чтение выполняется
ограниченными блоками; байт сверх предела даёт `ArtifactLimitError`. Общий
бюджет включает уже встроенные ресурсы, все новые файлы и части пакета.
Пустой файл можно встроить при нулевом оставшемся бюджете. Превышение квоты,
ошибка позднего файла или финальной проверки не меняет исходную модель и файлы.
Размер будущего JSON/base64 дополнительно проверяется при сохранении.

Все операции этого раздела принимают [DocumentLimits](limits.md) и проверяют
весь исходный документ. ID/типы/ссылки/пакет должны быть согласованы до вызова:
новые операции не предназначены для скрытого исправления повреждённой модели.
