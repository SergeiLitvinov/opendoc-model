# Геометрия страницы

`PageGeometry` хранит явно объявленную исходную область `media_box`,
необязательную область обрезки `crop_box` и поворот 0/90/180/270 градусов.
Все координаты — пункты, оси направлены вправо и вниз, поворот — по часовой
стрелке. Области заданы в одной исходной системе, до поворота. Начало исходной
области может быть ненулевым и отрицательным. Размеры положительные, значения
и границы конечные; crop целиком содержится в media. Отсутствующий crop означает media.

`get_page_geometry(page, limits=None)` возвращает независимую запись либо `None`.
`with_page_geometry(page, geometry, limits=None)` возвращает независимую
`DocumentPage`, сохраняя её ID, reading order и размеры. Исходная страница
не изменяется. `width`/`height` должны совпадать с размерами media до поворота.
Они не становятся размерами повёрнутой обрезанной области.
`with_page_geometry(page, None)` удаляет известную декларацию.

## Координаты и преобразования

`Point2D` и `Rect2D` экспортируются из `opendoc_model` и остаются теми же
классами, что в `opendoc_model.units`. Преобразование сначала вычитает начало
crop, затем поворачивает координаты с переносом в область отображения.
Её начало — верхний левый угол повёрнутой crop.

| Функция | Результат |
| --- | --- |
| `page_display_size(geometry)` | Ширина и высота повёрнутой crop; при 90/270 меняются местами |
| `page_point_to_display(geometry, point)` | Точка из исходной системы в область отображения |
| `page_point_from_display(geometry, point)` | Обратное преобразование точки |
| `page_rect_to_display(geometry, rect)` | Прямоугольник из исходной системы в область отображения |
| `page_rect_from_display(geometry, rect)` | Обратное преобразование прямоугольника |

Прямоугольники параллельны осям; нулевая ширина/высота допускается для
преобразуемых прямоугольников. Точки и прямоугольники за crop не отсекаются.
Нечисловые, не конечные значения и переполнение дают `ValueError`.
Обратимость чисел с дробной частью ограничена обычной точностью float.
Эти функции не рассчитывают компоновку документа или область видимости.

Существующие `Box`, `Annotation.box` и `FormControl.box` не преобразуются
автоматически. Их координаты остаются в исходной системе страницы;
`Box.rotation` остаётся отдельным поворотом элемента. По
[контракту Box](integration.md#рамка-элемента-и-поворот-box) он направлен
clockwise вокруг центра рамки до поворота. Для преобразования выбранного
прямоугольника вызывающий создаёт `Rect2D` и применяет преобразование страницы.
При ненулевом повороте элемента расчёт его фигуры остаётся отдельной задачей.
[Исполняемый пример](../../examples/page_geometry.py) показывает аннотацию,
обрезку со смещением и поворот 90 градусов.

## Сохранение и совместимость

Декларация хранится в `DocumentPage.extra` под ключом `opendoc.page-geometry`,
с `format="opendoc.page-geometry"` и собственной `version=1`. Существующие
конструкторы и integration v1, JSON документа v1/v2 не изменены. Reader,
не понимающий дополнение, сохраняет его как неизвестное поле страницы.
Отсутствие декларации не означает автоматически выбранную crop или поворот 0.
Непомеченные данные занятого ключа остаются непрозрачными; запись/удаление
через helper отказывают. Неизвестная tagged-версия отклоняется.
Это относится и к явно сохранённому null в занятом ключе .

Неизвестные поля записи попадают в `PageGeometry.extra`. Getter, JSON и helper
сохраняют их; helper объединяет прежние неизвестные поля с явно переданными.
Границы `Rect2D` имеют закрытый набор полей. Бюджеты `DocumentLimits` проверяются
до возвращения новой страницы; превышение даёт `ArtifactLimitError`.
`document.validate()`, `check_document`, JSON и `set_integration` проверяют
объявленную геометрию и согласованность с размерами страницы.

Merge/extract сохраняют геометрию в выбранном integration-конверте по существующей
политике метаданных. `keep_first`/`keep_last` выбирают конверт целиком и не
объединяют наборы страниц. Дополнение не вводит новый алгоритм сравнения страниц,
нативный парсер, отрисовку, оглавление или автоматическую миграцию частных полей.
