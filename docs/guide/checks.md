# Проверка и сравнение в памяти

`check_document` и `compare_documents` возвращают `CheckResult` без обязательного
выходного пути. Они не читают файлы, не проверяют существование внешних источников
и не решают, публиковать ли результат приложения. Исполняемый сценарий —
`examples/checks.py`.

```python
check_document(document, *, limits=None)
compare_documents(source, target, *, policies=None, limits=None)
```

## Структурированная ошибка

`DiagnosticIssue` содержит поля:

| Поле | Смысл |
| --- | --- |
| `code` | Непустой машинный код; проверяйте его вместо текста сообщения |
| `severity` | `IssueSeverity.INFO`, `WARNING`, `LOSS` или `ERROR` |
| `message` | Пояснение для человека; формулировка может изменяться |
| `location` | Путь поля/элемента либо пустая строка для общего результата |
| `measurement` | Словарь измерения/контекста или `None` |
| `reason` | Машинная причина отказа/недоступности или `None` |

Коды структурных ошибок: `model.type`, `model.empty-string`,
`model.number.invalid`, `model.number.range`, `model.reference.missing`,
`model.style.cycle`, `model.cycle`, `model.mapping-key`, `json.invalid`,
`json.utf8`. Остальные нарушения используют общий `model.invalid`; степень
детализации кода не заменяет путь. `reason="invalid-input"` обозначает нарушение
модели. Для отсутствующей ссылки measurement содержит `kind` и `identifier`;
для ограничений чисел — соответствующую границу. Ошибка извлекает путь в месте
обнаружения, включая JSON-свойства с двоеточиями в ключах. Парсинга сообщений нет.

`check_document` включает структурные ошибки и предупреждения инспекции,
а в `metrics["inspection"]` — полный снимок инспекции. Для повреждённой модели
метрики и инвентарь пустые; неизвестные значения не становятся нулями.
Текст с одиночными Unicode-surrogates недопустим: структурная проверка возвращает
`json.utf8`, не доводя инспекцию до ошибки кодирования отпечатка.

## Сравнение и явные политики

`compare_documents` сохраняет оба снимка в `metrics["source"]`/`["target"]`,
сравнение — в `["comparison"]`. Путь структурной ошибки/предупреждения стороны
начинается с `source.` или `target.`; пути событий сравнения относятся к его
данным или исходным объектам. Исходные модели не меняются, снимки независимы.

Без `policies` результат сообщает измеренные потери, но не выбирает допустимый
бюджет за приложение. `success` означает отсутствие `ERROR`; `lossless` дополнительно
требует отсутствия `LOSS`. Эти флаги не доказывают непроверенные свойства.
Например, `LOSS` может оставить `success=True`, а неизвестный хеш внешнего ресурса
не является доказанной потерей. [Сравнение и качество](quality.md) описывает
границы метрик, эвристики и строгие допуски.

В частности, две модели с одинаковым URI изображения и `data=None` могут
получить `lossless=True` при `policies=None`: известных потерь нет, но содержимое
изображения не сравнивалось. Проверьте `measurement.unavailable` с причиной
`external-data-not-loaded` и неизвестные хеши в снимках, если для вашей задачи
нужно подтверждение сохранности байтов. URI сам по себе этого не подтверждает.

`CheckPolicy` объединяет поддержанные `QualityPolicy`, `TextPreservationPolicy`,
`ObjectLossPolicy`, `FormulaLossPolicy` и `EmphasisLossPolicy`. Передавайте iterable
готовых политик; неизвестная политика даёт `ValueError`. Потребление iterable
ограничено `max_nodes`. Политики выполняются в указанном порядке. `QualityPolicy`
считает уже присутствующие `LOSS`, остальные оценивают сравнение. Результат каждой
политики хранится в прежнем ключе `*_quality_gate` (или `quality_gate`).

При отказе в issue фиксируется независимый снимок измерения и его `reason`:
`unavailable`, `uncertain-matching`, `budget-exceeded`, `text-changed-or-removed`
или `text-flow-changed`, в соответствии с выбранной политикой. `unavailable` —
общая категория: сама по себе не различает отсутствие math backend, неподдержанную
формулу и исчерпание вычислительного представления; детали доступны в снимках
и условиях выбранной политики. Изменение metrics после выполнения не меняет
прежнюю причину и снимок issue. Если повторно вызвать политику, её последний gate
заменяет прежний в metrics, а issues остаются накопленными, как в старом отчёте.

Недоступные общие измерения сравнения имеют отдельный `INFO` с кодом
`measurement.unavailable`, именем измерения и причиной `invalid-model`,
`external-data-not-loaded` или `no-pages`. Сведения об отсутствующих геометрии,
хешах и неизвестных размерах остаются в сравнении; строгая политика не принимает
недоступность за успех. Empty-model не получает выдуманной геометрии.

## Внешние ресурсы и совместимость

В новом API `data=None` означает неизвестные байты: `size_bytes`, `sha256` и
`source_exists` равны `None`. Суммарный размер ресурсов также `None`, если
какой-либо размер неизвестен. Путь/URI не открывается и не проверяется через stat.
Для известных встроенных пустых байтов размер равен 0 и хеш вычислен.

Прежние `ConversionIssue`, `ConversionReport(output_path)`, `DocumentModel.validate()`
и возврат bool из `policy.evaluate` сохранены. Все политики теперь также принимают
`CheckResult`, поэтому существующий явный вызов `policy.evaluate(result, comparison)`
работает без файла. `CheckResult.add` сохраняет совместимый интерфейс sink;
для собственных структурированных событий добавьте `DiagnosticIssue` в `issues`.
Его `feature` — совместимое read-only представление `code`.

Прежняя `inspect_document_model` по умолчанию проверяет существование внешнего
source в файловой системе, как раньше. Новый необязательный параметр
`check_external_sources=False` выключает эту проверку; новые функции используют
именно его. Старые строковые ошибки validate остаются; инспекция больше не
разбирает их текст, а использует тот же источник структурированных ошибок.

## Сериализация и бюджеты

`result.to_dict(*, limits=None)` возвращает независимый JSON-словарь с форматом
`opendoc.check`, версией 1, флагами, issues и metrics. Пример сериализации:
`json.dumps(result.to_dict(), ensure_ascii=False, allow_nan=False)`. Это отдельный
формат результата, не новая версия `opendoc.document`; JSON документа остаётся v2.
Автоматический reader результата пока не предоставляется.

Сериализация проверяет JSON-типы, конечные числа, Unicode, циклы, глубину,
число значений и текстовые байты через [DocumentLimits](limits.md). Она не
превращает произвольные объекты в строки. Снимки исходника, результата,
сравнения и ошибок могут занимать больше места, чем одна модель; подходящий
бюджет сериализации задают отдельно. Кодировку и запись выбирает потребитель.

В проверке/сравнении лимиты применяются к каждой модели отдельно. Исчерпание
структурного/JSON-бюджета по-прежнему даёт `ArtifactLimitError`, а не неполный
успешный результат. Ожидаемые нарушения модели возвращаются как `ERROR`;
ошибки программирования не перехватываются широким исключением.
