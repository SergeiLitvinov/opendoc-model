## Подпись и идентичность

`caption_ids` ссылается на существующие `Anchor.id` абзацев. Таблица-владелец
должна иметь собственный anchor. Один абзац не может принадлежать двум таблицам;
порядок ссылок явный. Абзацы не дублируются и не перемещаются автоматически.
Runs, их стили, существующие языковые данные `Accessibility` и `Provenance`
таблицы/абзацев сохраняются обычными структурами. Простая строка названия
не заменяет форматированную подпись.

ID строк, ячеек, групп строк и групп колонок уникальны в каждой своей области
внутри таблицы. Они не являются якорями документа. Соседние и вложенные таблицы
могут повторять такие ID, не смешивая отношения.

## Ячейки, группы и spans

`role=None` означает неизвестную роль. Оформление и расположение не превращают
её в header или data. Scope разрешён только у header: row, column, row-group
или column-group. `headers` ссылается только на header-ячейки той же таблицы;
дубли, собственный ID и циклы отношений отклоняются. Ядро не вычисляет список
headers из scope и не имитирует алгоритм экранного диктора.

Row-group scope требует явной принадлежности строки существующей группе.
Column-group scope требует `column_group_id`, причём ячейка должна целиком лежать
в соответствующем логическом интервале. Другие scope не принимают этот ID.
Группы колонок не пересекаются и не выходят за логическую ширину таблицы.
Несколько body-групп сохраняются отдельно; строки следуют объявленному порядку
групп. Неиспользованные определения групп допускаются.

Логические позиции ячеек вычисляются с учётом rowspan/colspan, без выделения
матрицы по числу колонок. Для объявленной семантики rowspan не выходит за таблицу
и не пересекает границу явно указанной группы строк. Неизвестная принадлежность
строки не заменяется автоматически выбранной группой. Это проверка структурных
интервалов, а не расчёт ширины или высоты. Работа проверки сетки дополнительно
ограничена `DocumentLimits.max_nodes`, глубина headers — `max_depth`;
исчерпание даёт `ArtifactLimitError`, не частичный успешный результат.
глубина headers включает уже проверенные зависимости и не зависит
от порядка ячеек при обходе.
снимки инспекции сохраняют явно переданный бюджет `DocumentLimits`;
увеличенный лимит глубины не заменяется стандартным внутри getters.

## JSON, совместимость и неизвестные данные

Схемы имеют отдельную версию **1** и хранятся в properties под ключами
`opendoc.table-semantics`, `opendoc.table-row-semantics`,
`opendoc.table-cell-semantics`. Пример ячейки:

```json
{"format":"opendoc.table-cell-semantics","version":1,"id":"amount","role":"data","scope":null,"headers":["column-header"],"column_group_id":null}
```

JSON документа v1/v2, bags v1 и конструкторы Table/Row/Cell сохраняются.
Старые readers сохраняют tagged-данные как неизвестные properties; они не
понимают их ссылки. Непомеченное содержимое занятого ключа остаётся непрозрачным,
setter не перезаписывает его. Неизвестная версия tagged-схемы отклоняется.
Неизвестные поля попадают в `extra` каждой записи, сохраняются в JSON и не
исполняются. Setter сохраняет неизвестные поля прежней верхней записи;
изменяя вложенные группы, используйте прочитанную запись/`replace` для их сохранения.
Extra не перекрывает поля схемы или format/version. `None` удаляет известную
декларацию; частные форматные расширения не мигрируют автоматически.

## Операции и диагностика

Merge переназначает anchor ID таблиц и абзацев подписи; локальные ID и отношения
в каждой таблице остаются независимыми. Извлечение таблицы сохраняет подпись;
извлечение абзаца подписи также замыкает зависимость владельца. Как и для других
якорных ссылок, это может сохранить целые дополнительные секции. Частичное
извлечение ячейки/строки с неполными headers, группами или spans даёт явный отказ
без изменения исходника. Автоматического отсечения отношений нет.

Структурные insert/replace/remove и transform проверяют затронутые декларации:
невалидная правка откатывается или не возвращает результат. Прямая запись
в dataclass/property bag остаётся ответственностью вызывающего; последующая
валидация обнаруживает несогласованность. `semantic.table.invalid` сопровождается
расположением нарушения. Сравнение содержит снимки `table_semantics` и сообщает
`table-semantics-change` (WARNING) либо `table-semantics-loss` (LOSS) при удалении
объявленной подписи, роли header, scope, headers или записей/групп.
Прежний инвентарь без этого измерения не получает выдуманной потери.

Совпадение деклараций не доказывает доступность внешнего файла. Чтение/безопасная
запись HTML, полная ARIA, браузер и экранный диктор находятся вне библиотеки.
