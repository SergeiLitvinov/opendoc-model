# Лимиты документа

Для стоимости сопоставления существует отдельный `MatchingLimits`: он ограничивает
записи и кандидаты, а сравнение возвращает явную недоступность при его исчерпании.
Настройки, единицы работы и поведение строгой политики описаны в
[стоимости операций](performance.md#бюджет-сопоставления).

`DocumentLimits` задаёт бюджет одной операции чтения или записи. Объект неизменяемый; каждый вызов получает собственный бюджет и не меняет глобальные настройки.

| Поле | Значение по умолчанию | Назначение |
|---|---:|---|
| `max_bytes` | 100 МБ (100 × 1024²) | Размер строкового/байтового JSON и записываемого файла; для словаря — суммарный UTF-8 объём текстовых значений и ключей |
| `max_depth` | 64 | Число вложенных контейнеров JSON или внутренних контейнеров модели |
| `max_nodes` | 100 000 | Число значений в обходе входного/выходного дерева, включая контейнеры и скалярные значения |
| `max_embedded_bytes` | 75 МБ (75 × 1024²) | Суммарные декодированные байты ресурсов и частей пакета |

Значения — неотрицательные целые числа; `max_nodes` положителен, `max_depth` находится в диапазоне 1–128. Верхняя граница глубины удерживает рекурсивный кодек в пределах обычного стека Python. `None` в аргументе `limits` означает стандартный бюджет, а не отключение проверок. Пользователь может уменьшать бюджет или явно увеличивать допустимый объём в указанных пределах.

## Использование

Все шесть операций `document_to_dict`, `document_from_dict`, `document_to_json`, `document_from_json`, `save_document` и `load_document` принимают необязательный keyword-аргумент `limits`. Старые вызовы и значения `indent` сохраняются.

Методы `DocumentModel.validate()`, `PackageGraph.validate()` и функция `inspect_document_model()` также принимают `limits` для ограниченного обхода модели в памяти.

```python
from opendoc_model import DocumentLimits, DocumentModel, document_from_json, document_to_json

limits = DocumentLimits(max_bytes=1024 * 1024, max_depth=32, max_nodes=10_000, max_embedded_bytes=512 * 1024)
text = document_to_json(DocumentModel(metadata={"custom": "example"}), limits=limits)
restored = document_from_json(text, limits=limits)
assert restored.metadata == {"custom": "example"}
```

Бюджеты применяются к входному и выходному дереву отдельно. Восстановление пропущенных необязательных полей добавляет значения: чтение компактного JSON с очень маленьким `max_nodes` не обещает запись полной модели с тем же бюджетом. Отступы и экранирование тоже влияют на размер записываемого JSON. Число узлов не является числом абзацев или доказательством покрытия документа.

## Отказы и сохранность

С версии 0.13.0 `ArtifactLimitError` содержит отдельные поля:

| Поле | Тип | Смысл |
| --- | --- | --- |
| `path` | `str \| None` | Адрес проверяемого значения, области или файла; неизвестный адрес — None |
| `quota` | `str \| None` | Имя исчерпанного бюджета |
| `maximum` | `int \| None` | Настроенный максимум этой проверки, включая ноль; не фактическое потребление |

Текст и `args`, наследование от ValueError и прежние позиционные вызовы сохранены.
`ArtifactLimitError("message")` оставляет все три поля None: они не извлекаются
из сообщения. Новый вызов может явно передать keyword-поля. Копирование и pickle
сохраняют поля. Нового JSON-конверта ошибки нет; документ и его версии не меняются.

```python
from opendoc_model import ArtifactLimitError, DocumentLimits, document_from_json

try:
    document_from_json("{}", limits=DocumentLimits(max_bytes=1))
except ArtifactLimitError as error:
    assert (error.path, error.quota, error.maximum) == ("$", "bytes", 1)
```

Базовые имена quota — `bytes`, `depth`, `nodes`, `embedded bytes`.
Специализированные проверки сохраняют свои имена: `graph nodes`, `graph depth`,
`embedded input bytes`, `overlap comparisons`, `hierarchy depth`, `headers depth`,
`table grid work`; лимит MatchingLimits использует `work`. Имена открыты для новых
проверок; потребитель обрабатывает неизвестное имя без догадок об единицах.
Path — адрес текущей проверки, не универсальный JSON Pointer: `$` означает корень,
структурный обход даёт пути модели, файловая запись — переданный путь назначения.
Предварительная проверка глубины JSON знает только `$`; глобальный matching
не знает адреса отдельного объекта и возвращает None. Обёртка предварительной
проверки композиции добавляет контекст входного документа к известному адресу,
сохраняя quota/maximum и цепочку cause.

Переданный бюджет проверен через JSON, validate/inspection/check, clone/merge,
integration и файловое сохранение/загрузку. С 0.13.0 `compare_documents` передаёт
его также в проверку большого профиля измеренного текста: внутренний default100k
больше не делает допустимый профиль недоступным. При самостоятельной оценке
`TextPreservationPolicy.evaluate(..., limits=budget)` принимает тот же бюджет.
Прежняя оценка без limits использует стандартный бюджет; выходящий за него профиль
по-прежнему недоступен, а не объявляется проверенным. MatchingLimits, число токенов
и допуск текстовых правок остаются отдельными контрактами.

[Исполняемый пример](../../examples/structured_limits.py) и
[собственные регрессии](../../tests/test_limit_contract.py) проверяют эти гарантии.

Превышение бюджета вызывает `ArtifactLimitError`, подкласс `ValueError`. Неверная структура, недопустимая конфигурация и обнаруженный цикл дают `ValueError`; ошибки файловой системы сохраняют `OSError`. При недостаточном бюджете обход останавливается и не обещает найти все структурные ошибки.

`load_document()` читает не больше `max_bytes + 1` байта: дополнительный байт позволяет обнаружить превышение без полной загрузки файла. Перед JSON-разбором проверяется глубина с учётом строк и экранирования. Бюджет встроенных данных проверяется до декодирования base64; ресурсы и части пакета учитываются вместе. Внешние источники не загружаются.

Перед рекурсивной сериализацией проверяются глубина, размер дерева, встроенные данные и циклы модели. Повторное использование одного поддерева в разных местах допустимо: это два вхождения, а не цикл. При записи JSON выдаётся частями во временный файл рядом с назначением; файл фиксируется атомарно только после успешного завершения и проверки всех квот. Превышение лимита, ошибка сериализации или отказ замены удаляет временный файл и оставляет прежнее содержимое целым. Байты файла соответствуют UTF-8 JSON без преобразования переводов строк Windows.

Это бюджеты представления и обхода, а не обещание точного максимального потребления памяти процесса: JSON-парсер и представления Python имеют собственные накладные расходы.
