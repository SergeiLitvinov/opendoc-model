# Пользовательские расширения

OpenDoc Model сохраняет JSON-данные в `properties` и `metadata`. Для нового контракта
используйте принадлежащее потребителю пространство имён, например `org.example.review`.
Ключ содержит минимум два сегмента из строчных ASCII-букв, цифр, `_` и `-`;
каждый сегмент начинается с буквы. Префикс `opendoc_model.*` зарезервирован библиотекой.
Обратное доменное имя помогает избежать конфликтов; библиотека не проверяет владение доменом.
Существующие свободные ключи сохраняются без переименования.

## Хранение и версии

`set_extension(bag, key, data, version=1)` создаёт явный конверт:

```json
{"org.example.review": {"format": "org.example.review", "version": 1, "data": {"approved": true}}}
```

Данные должны соответствовать [JSON-контракту](json.md) и [лимитам](limits.md).
Положительная целочисленная версия принадлежит расширению. `get_extension`
возвращает независимые `data` и дополнительные поля конверта; чтение не подтверждает
поддержку версии. Запись сохраняет неизвестные поля помеченного конверта и копирует
входные данные. Ошибка до записи оставляет bag целым. `remove_extension` удаляет
только помеченное расширение. Непомеченное значение по занятому ключу остаётся
непрозрачным: getter возвращает `None`, setter и remover отказывают.

JSON-сериализация сохраняет расширения и не запускает пользовательский код.
Схема документа остаётся `opendoc.document` v2 с чтением v1/v2; схема bags остаётся v1.
Версия расширения задаётся независимо. Новые API являются дополнением следующего
minor по [правилам совместимости](compatibility.md).

## Явная проверка

Исполняемый пример — [examples/extensions.py](../../examples/extensions.py).
`ExtensionSchema(key, frozenset({1}), validator, scopes=...)` объявляет поддержанные
версии, доверенную функцию и области `metadata`/`properties`. Без функции допустим
любой JSON payload поддержанной версии. Список схем передаётся на каждый вызов:

```python
from opendoc_model import DocumentModel, ExtensionSchema, check_extensions, set_extension

document = DocumentModel()
set_extension(document.metadata, "org.example.review", {"approved": True})
schemas = [ExtensionSchema("org.example.review", frozenset({1}))]
assert check_extensions(document, schemas).success
```

Те же схемы принимают `check_document(..., extensions=schemas)` и
`compare_documents(..., extensions=schemas)`. По умолчанию `extensions=None`
сохраняет прежнюю проверку модели. Пустой список включает поиск неизвестных
помеченных расширений. При сравнении iterable схем потребляется один раз,
а исходный и конечный документы проверяются отдельно.

Проверяются метаданные документа, свойства и дополнительные поля коллекции сносок,
свойства стилей и ресурсов, всех структурных элементов, встроенного стиля `TextRun`
и дополнительные поля сноски. Секции, таблицы, колонтитулы и тела сносок обходятся
полностью; повторные вхождения одного объекта проверяются отдельно. Вложенные
произвольные JSON-объекты и непрозрачные байты пакетов не интерпретируются как
дополнительные объявления расширений.

Сначала проверяется структура модели. При её ошибках callbacks не запускаются.
Функция получает `ExtensionContext` с независимыми данными, версией, типом владельца,
областью и путём, заканчивающимся `.data`. Она возвращает `None` либо iterable
`DiagnosticIssue`. Относительный `location` диагностики добавляется к пути данных;
измерения копируются. Исключение callback распространяется вызывающему коду.
Лимиты ограничивают входы и возвращаемые диагностики, включая бесконечный iterable;
они не ограничивают время выполнения или побочные действия самой доверенной функции.
Глобальной регистрации и загрузки исполняемых имён из JSON нет.

Неизвестное помеченное расширение даёт `extension.unknown` уровня ERROR.
Явный `unknown="preserve"` (в общих проверках `unknown_extensions="preserve"`)
сохраняет его как INFO с причиной `unknown-extension` и счётчиком `unknown`.
Это разрешение переносить непроверенные данные, а не подтверждение их семантики.
Неизвестная версия зарегистрированной схемы, неверная область, повреждённый конверт
или непрозрачное значение зарегистрированного ключа остаются ошибками даже в этом режиме.
Встроенные роли проверяет модель; объявление известной роли на неподдержанном носителе
выявляет `extension.builtin-scope`. Новая неизвестная роль `opendoc_model.*` не получает
пользовательскую схему и учитывается как неизвестная.

## Явные миграции

`ExtensionMigration` и `migrate_extension` задают явно переданную
цепочку возрастающих версий. Callback получает независимый снимок данных;
изменение фиксируется после всей цепочки и необязательной проверки схемы.
`scope="metadata"` используется по умолчанию, `scope="properties"` — для
проверки схем, предназначенных для свойств. Неизвестные поля конверта сохраняются;
ошибка или лимит оставляют bag целым. Чтение JSON не запускает миграции.
Проверка миграции использует временный DocumentModel для metadata и Paragraph
для properties. Callback видит этот временный носитель; проверки конкретного
элемента исходного документа выполняются отдельно через `check_extensions`.
Подробности находятся в [расширенной модели](integration.md).

## Границы элементов

Схема расширений описывает данные, а не новые типы блоков или Python-классы.
Поддержаны объявленные классы модели и известные JSON-типы. Неизвестные типы блоков,
версии документа и bags отклоняются. Подклассы сериализуемых классов и незаявленные
публичные атрибуты теперь дают `model.type.unsupported`/`model.state.unsupported`:
прежняя неявная проекция могла потерять их данные. Храните переносимое состояние
в `properties`/`metadata`, а поведение потребителя — в отдельном объекте или адаптере.
Приватные временные атрибуты не входят в контракт сохранения. Новый сериализуемый
тип требует отдельного изменения библиотечной схемы и решения о совместимости.
