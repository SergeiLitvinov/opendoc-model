# Объединение и извлечение документов

Для самостоятельных карт объектов используйте
[явный ремап и проверку объявленной области](object-mapping.md#композиция-и-выделение-части-модели).
История карты в metadata сохраняется как непрозрачные данные; она не становится
актуальной картой результата автоматически.

`opendoc_model.composition` создаёт самостоятельную модель вместе с поддержанными зависимостями. Исходные документы остаются неизменными; результат проходит семантическую валидацию перед возвратом. Операции не требуют редактора, файлового назначения или адаптера офисного формата. [Исполняемый пример](../../examples/composition.py) объединяет конфликтующие документы, извлекает абзац из вложенной таблицы и сохраняет/читает его JSON.

## Объединение

```python
from opendoc_model import DocumentModel, Paragraph, Section, TextRun, TextStyle, merge_documents, save_document

first = DocumentModel(
    sections=[Section(blocks=[Paragraph([TextRun("Первый")], style_id="body")])], styles={"body": TextStyle(bold=True)}
)
second = DocumentModel(
    sections=[Section(blocks=[Paragraph([TextRun("Второй")], style_id="body")])], styles={"body": TextStyle(italic=True)}
)
merged = merge_documents([first, second], conflicts="rename")
assert merged.id_maps[0].styles == {"body": "body"}
assert merged.id_maps[1].styles == {"body": "body~2"}
assert merged.document.sections[1].blocks[0].style_id == "body~2"
assert merged.document.validate() == []
save_document(merged.document, "merged.json")
```

`merge_documents(documents, *, conflicts="error", metadata_conflicts="error", package_policy="error", mode=None, limits=None)` принимает непустой iterable документов. `DocumentMerge.document` — независимая модель, `DocumentMerge.id_maps` — кортеж `DocumentIdMap` в порядке исходников. Каждая карта содержит словари `styles` и `resources` с **каждым** исходным идентификатором, включая неизменённые. Словари являются отдельными снимками: их последующая правка не меняет ссылки документа. Заморожен контейнер результата, а модель и словари остаются изменяемыми.

Секции добавляются в порядке документов; все семь коллекций, страницы, свойства, provenance, surrogate, стили и ресурсы копируются. Объединение сохраняет и неиспользуемые определения. Два входа, указывающие на один исходный документ, получают независимые копии; общие объекты **внутри** каждого входа остаются общими внутри его копии.

### Конфликты идентификаторов

С 0.17.2 автоматически создаваемые ID якорей также обходят ID медиаобъектов,
сцен, графиков и диаграмм из integration всех исходников. Эти определения входят
в общее пространство целей `Timing`: например, существующая сцена `a~2` заставляет
переименовать повторный якорь `a` в `a~3`. Сцена и её timing-ссылка сохраняют
`a~2`, структурные ссылки используют карту якорей. Ресурсные и стилевые ID
по-прежнему имеют отдельные карты. Неизвестные поля не переписываются.

Это предотвращает конфликт, создаваемый новым суффиксом. Уже существующее
междоменное совпадение ID якоря одного входа и сцены другого по-прежнему
отклоняется, если выбранные metadata делают итог неоднозначным. Автоматического
переименования интеграционных реестров и объединения их metadata нет;
неоднозначные ссылки не угадываются.

| `conflicts` | Поведение |
|---|---|
| `error` | Любой повтор ключа стиля или ресурса вызывает `ValueError` с индексом входа, доменом и ID; даже при одинаковых определениях |
| `rename` | Первый ID остаётся прежним, поздние получают суффикс `~2`, `~3`, …; все определения сохраняются |

Новые имена обходят как уже занятые ID, так и **все исходные ID поздних документов**. Например, при конфликте `body`, если исходный `body~2` уже существует где-либо во входах, новое имя будет `body~3`. Стиль и ресурс имеют отдельные пространства имён. Имена чувствительны к регистру, Unicode сохраняется; повторный запуск с тем же порядком входов/ключей даёт те же карты.

Переименование не объединяет «похожие» стили или ресурсы и не выбирает случайное содержимое для конфликта. Снимки ссылок создаются до их изменения: общий узел, property bag, inline-стиль или surrogate не получает повторное переименование уже переписанного значения.

### Какие ссылки поддержаны

- `Paragraph.style_id` и `Table.style_id`;
- `TextStyle.properties.base_style_id` именованных и inline-стилей;
- `Paragraph.properties.numbering_source_style_id` и такое же поле `TextStyle.properties`;
- все [ресурсные ссылки](traversal.md#ссылки-на-ресурсы): основное изображение, fallback, surrogate любого элемента и `TextRun.properties.resource_id`;
- ключи словарей стилей/ресурсов и соответствующий `Resource.id`.

`numbering_source_style_id` при композиции трактуется как ID из `DocumentModel.styles`. Он должен быть непустой строкой или `None`; неизвестный ID диагностируется с путём. Общая валидация свободных свойств не стала строже: именно эти операции разрешают такую зависимость и требуют её наличия. При объединении проверяются все эти ссылки во всех исходных определениях, включая неиспользуемые.

Произвольные ключи, URI, `TextRun.link`, названия шрифтов, ICC profile и прикладные номера/якоря не переинтерпретируются как библиотечные ID. Например, `vendor:resource_id` остаётся прежней строкой. Библиотека не переписывает пользовательские схемы ссылок, XML формул или байты непрозрачного пакета. Такие расширения сохраняются как данные; их дополнительные зависимости при извлечении можно указать явно.

### Метаданные и режим

Документные `metadata` объединяются по ключам. Повтор ключа, даже с равным значением, по умолчанию вызывает отдельную ошибку. `metadata_conflicts="keep_first"` явно оставляет первое значение; `"keep_last"` — последнее. Вложенные словари не сливаются по догадке, не переименовываются и копируются независимо. Структурные свойства и provenance каждого элемента не участвуют в конфликте документных метаданных.

Без `mode` режимы входов должны совпадать. При разных режимах явно задайте `mode=ConversionMode.BALANCED` или другой enum. Общий `source_format` сохраняется при совпадении у всех входов, иначе становится `None`. Историческое происхождение элементов/ресурсов и события не переписываются и не выдумываются. Итоговая версия модели — 2; собственной схеме JSON соответствует обычная запись версии 2.

## Извлечение с зависимостями

```python
from opendoc_model import extract_document, iter_elements

location = list(iter_elements(merged.document, Paragraph))[1]
extracted = extract_document(merged.document, location)
assert list(extracted.styles) == ["body~2"]
assert extracted.sections[0].blocks[0].plain_text == "Второй"
assert extracted.validate() == []
```

`extract_document(document, location, *, package_policy="error", additional_styles=(), additional_resources=(), limits=None)` получает актуальный `NodeLocation` из обхода **этого** документа. [Правила расположений](operations.md#вставка-замена-и-удаление) проверяют весь путь родителей. Чужое, смещённое или отсоединённое вхождение отклоняется, вместо выбора другого узла по старому индексу.

| Выбранный узел | Результат |
|---|---|
| Корень `DocumentModel` | Независимая полная копия, включая неиспользуемые определения |
| `Section` | Одна секция со всеми её коллекциями |
| Блок: `Paragraph`, `Table`, блочное `Image`/`Formula` | Поддерево в секции с контекстом исходной секции |
| Inline: `TextRun`, inline-`Image`/`Formula` | Поддерево в оболочке исходного абзаца, с одним выбранным inline |
| `TableRow` | Одна строка в оболочке исходной таблицы |
| `TableCell` | Одна ячейка в оболочках исходной строки и таблицы |

Оболочки сохраняют страницу, свойства и provenance секции, а при необходимости — свойства/стиль/геометрию/provenance/surrogate абзаца или таблицы и свойства строки. Остальные структурные коллекции оболочек пусты. Исходное положение в обычных/first/even колонтитулах сохраняется; блок из ячейки становится самостоятельным блоком в той же верхней коллекции секции. Соседние строки, ячейки, блоки и inline не переносятся.

Значения страницы, span, геометрия и свойства связи с предыдущим колонтитулом остаются исходными: библиотека не выполняет вёрстку, перенумерацию страниц или разрешение прикладного наследования колонтитулов. Provenance остаётся исторической ссылкой на исходник, даже если выбранная секция теперь первая в новом документе.

Все поддержанные зависимости выбранного дерева **и оболочек** включаются автоматически. Стили образуют транзитивное замыкание по `base_style_id` и `numbering_source_style_id`; отдельно учитывается наследование inline-стиля. Сбор выполняется без рекурсивного вызова и не зацикливается на повторном использовании определения. Цикл собственно `base_style_id` отклоняет общая валидация исходника; ссылки нумерации не объявляются наследованием.

Ресурсы включаются по явным поддержанным ссылкам. Если оболочка имеет surrogate, его ресурс тоже включается. ID сохраняются; выходные словари следуют порядку определений исходного документа. Остальные стили/ресурсы исключаются. Документные метаданные, режим и `source_format` сохраняются; все изменяемые данные результата независимы от исходника.

### Дополнительные зависимости расширений

Для ресурса шрифта, профиля или пользовательской схемы можно передать явные ID:

```python
# Если эти определения существуют в исходнике:
# extracted = extract_document(document, location,
#                              additional_styles=["custom-style"],
#                              additional_resources=["embedded-font", "profile"])
```

`additional_styles` включает также транзитивные зависимости указанного стиля. `additional_resources` сохраняет указанные записи без открытия внешнего `source`. Повторы одного ID игнорируются; неизвестный, пустой или нетекстовый ID вызывает `ValueError` с именем аргумента и индексом. Одна строка вместо iterable идентификаторов отклоняется, а не разбивается на символы. Пользовательские поля при этом не анализируются и не изменяются.

## Непрозрачные пакеты

Собрать или обрезать пакет произвольного формата по семантическому дереву нельзя без знания байтов его частей. `package_policy` явно задаёт решение:

| Сценарий | `error` по умолчанию | `preserve` | `drop` |
|---|---|---|---|
| Все входы без пакетов | `None` | `None` | `None` |
| Объединение одного документа или извлечение корня | Копирует пакет | Копирует пакет | Удаляет пакет из результата |
| Объединение нескольких документов с пакетом | Ошибка | Допускается только при полностью одинаковых графах у **каждого** входа | Явно удаляет пакеты из результата |
| Частичное извлечение из документа с пакетом | Ошибка | Сохраняет **весь** исходный граф | Явно удаляет пакет из результата |

Совпадение графов включает формат, корень, имена/типы/байты частей и упорядоченные связи. Смесь наличия/отсутствия пакета, разные форматы, корни, содержимое или связи при `preserve` отклоняются. Имена частей и ссылки внутри их байтов не переименовываются. `drop` не меняет исходные документы и не удаляет семантические ресурсы.

`preserve` сохраняет непрозрачный граф как данные, а не обещает соответствие его байтов новому объединённому/извлечённому дереву или корректность офисного экспорта. Согласование конкретного формата выполняет потребитель. Ни один режим не открывает внешние отношения, URI или ресурсные файлы; относительные `Resource.source` остаются исходными строками. Получение переносимых встроенных байтов — отдельная явная операция.

## Проверки и бюджеты

Каждый источник должен пройти полную [валидацию модели](validation.md), даже если для извлечения выбрана небольшая часть. Дополнительные поддержанные ссылки стилей проверяются при обходе зависимостей. Результат валидируется до возврата; JSON-кодек при сохранении отдельно проверяет свою форму, размер и бюджеты.

`DocumentLimits` ограничивает входы и выход независимо. При объединении числа значений и встроенных байтов **всех** источников суммируются, включая неиспользуемые определения и одинаковые пакеты. Глубина проверяется для каждого входа отдельно. Это также ограничивает потребление длинного или бесконечного iterable документов до копирования результата; для обнаружения выхода за квоту может быть получен первый лишний элемент. Даже когда итог короче, уменьшенный результат не отменяет стоимость входа.

При извлечении проверяется полный источник и итоговая модель. Каждая последовательность дополнительных ID ограничена `max_nodes`, включая повторы, поэтому бесконечный поток одного ID не зацикливает операцию. Семантическая валидация использует обычные бюджеты JSON-расширений; полный UTF-8-размер записываемого JSON проверяет сохранение.

Превышение квоты — `ArtifactLimitError`; конфликты, неизвестные политики, ошибки ссылок и структуры — `ValueError`. Частичный результат не возвращается, библиотека не изменяет исходники. Итераторы пользователя могут иметь собственные внешние действия; они не являются частью отката. Во время операции исходные модели нельзя менять другим потоком или обработчиком.
