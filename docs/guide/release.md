# Сборка и проверка выпуска

Версия пакета задаётся только литералом `opendoc_model.__version__` в
`src/opendoc_model/__init__.py`. Setuptools читает этот атрибут через dynamic version;
отдельного номера в `pyproject.toml` нет. Версия пакета не меняет версии JSON.
Build backend зафиксирован как `setuptools==84.0.0`; обновление инструмента
сборки требует повторного прогона архивных и установочных проверок.

Проект распространяется по [MIT License](https://opensource.org/license/mit).
Файл `docs/LICENSE` содержит правообладателя: Сергей Литвинов (Sergei Litvinov),
2026 год. Он включён в sdist и wheel; метаданные содержат `License-Expression:
MIT` и `License-File: docs/LICENSE`.

## Проверяемые артефакты

```text
uv sync --all-extras
uv run ruff check
uv run ruff format --check
uv run pytest
uv run mypy
uv run python -m tools.docs generate
uv run python -m tools.docs check
uv build --out-dir .opendoc/release-dist
uv build --wheel <sdist.tar.gz> --out-dir .opendoc/sdist-dist
uv run python -m tools.check_distribution --dist .opendoc/release-dist --rebuilt .opendoc/sdist-dist
```

Повторная сборка получает только архив sdist; исходники проекта не передаются
build backend. `tools.check_distribution` сравнивает распакованные файлы wheel,
включая metadata/RECORD, и содержимое пакета в sdist. Это проверка одинакового
payload; временные метки ZIP не являются обещанием побитно одинаковых архивов.
Проверяются название, номер версии, Python 3.11+, отсутствие обязательных
сторонних зависимостей, заявленные extras, лицензия и `py.typed`.

Wheel содержит только `opendoc_model` и metadata дистрибутива. Sdist дополнительно
содержит библиотечные исходники, тесты, примеры, документацию и инструменты.
Архивы отклоняются при наличии окружений, кэшей, файлов прикладного пакета,
небезопасных путей, дубликатов или подменённой лицензии/версии.

## Установка без checkout

Каждый wheel — исходной сборки и повторной сборки sdist — устанавливается
без зависимостей в собственное пустое окружение. Затем запускаются
`tools.check_wheel` и `tools.check_types` с Python этой установки. Процессы
работают во временных каталогах с `-I`; исходники checkout исключены из импортов,
а runtime-версия обязана совпадать с metadata установленного дистрибутива.
Сценарии проверяют модель, изменение, JSON, сравнение, свойства, ресурсы,
композицию, семантические роли и статическую типизацию публичного API.

Отдельная установка с extra `math` проверяет только заявленную возможность
XML; [проверка optional backend](formulas.md#независимость-установки) описывает
парные сценарии. CI повторяет сборку и установки на Python 3.11/3.12/3.13.
Настроенный CI и локальная проверка отличаются от результата удалённого запуска.

Изменения поведения перечислены в [заметках выпусков](changes.md).
Эти команды создают и проверяют артефакты локально. Публикация в реестр
выполняется отдельным явно запрошенным действием.

## Автоматический выпуск на GitHub

В **Actions → Release → Run workflow** выберите ветку `main` и версию:

- `current` выпускает текущий номер, если его тег ещё не существует;
- `patch`, `minor`, `major` увеличивают соответствующую часть номера;
- точный номер `MAJOR.MINOR.PATCH` задаёт версию явно.

Принимаются стабильные версии без префикса `v`; уменьшение номера запрещено.
`tools.release` меняет только `__version__`. Lock-файл использует динамическую
версию корневого пакета, поэтому зависимости при выпуске не пересчитываются.
Сохранённые контракты API и JSON остаются проверками всех выпусков.

Общий workflow `checks.yml` выполняет полную проверку на Python 3.11/3.12/3.13,
собирает wheel и sdist, сравнивает повторную сборку и проверяет пустые установки.
После успешной матрицы workflow фиксирует версию и тег `vMAJOR.MINOR.PATCH`
одной атомарной отправкой. Если `main` успела измениться, отправка отклоняется:
запустите выпуск заново для нового состояния ветки.

GitHub Release сначала создаётся черновиком. Только после загрузки проверенных
wheel, sdist и `SHA256SUMS` он публикуется; описание изменений генерирует GitHub.
Готовые выпуски не перезаписываются. Существующий вручную отправленный тег `v*`
также запускает проверки и выпуск; его номер должен совпадать с `__version__`.
Если загрузка черновика прервалась, выберите **Re-run failed jobs** в исходном
запуске. Повторная попытка проверяет существующий тег и продолжает загрузку;
другой состав исходников отклоняется. Для опубликованного выпуска выполняется
только проверка контрольных сумм, metadata и package sources; его assets
автоматически не изменяются.
Если прервалась отправка версии, создавайте новый запуск из актуальной `main`.

Используется штатный `GITHUB_TOKEN`; дополнительные токены и сервисы публикации
не требуются. Права записи получает только задача выпуска. Обновление ветки/тега
этим токеном не порождает второй CI: проверки и Pages уже входят в выпуск.
Артефакты CI хранятся кратко; постоянные пакеты находятся в GitHub Releases.

## Документация в GitHub Pages

После успешных проверок `main` CI публикует строго собранную документацию через
GitHub Actions. Pages использует артефакт, а не отдельную ветку с HTML-файлами.
Pull requests проходят проверки без публикации. После выпуска из `main` сайт
публикуется тем же процессом. Для первоначального включения в **Settings → Pages**
нужно выбрать **GitHub Actions**; настройки применяются один раз.

Сайт проекта находится по адресу `https://<владелец>.github.io/opendoc-model/`.
В CI адрес берётся из `GITHUB_REPOSITORY`, поэтому перенос в организацию не
требует изменения workflows. Для локальной сборки и ссылок в metadata адреса
задаются в `mkdocs.yml`, `pyproject.toml` и `README.md`.

Проект и организация используют GitHub Free, репозиторий публичный,
лицензия MIT. Linux-проверки и Pages используют бесплатные возможности для
открытого репозитория. Платные runners, планы, подписки и PyPI не подключаются.

## Чистое рабочее дерево

Все документы находятся в `docs/`, кроме корневого `README.md`. Лицензия остаётся
частью обоих дистрибутивов. Кэши, сборки, изолированные окружения и тестовые
файлы игнорируются Git; Ruff, pytest, mypy и uv помещают кэши в `.opendoc/`.
Pytest переиспользует один временный каталог вместо накопления отдельных прогонов.

`uv run python -m tools.release clean` удаляет старые сборки, тестовые окружения,
кэши проверок и `__pycache__`. Сохраняются рабочая `.venv`, кэш uv, локальный сайт
и компактные исходные замеры, подтверждающие руководство по производительности.
В рабочей версии сохраняется также `.opendoc/acceptance` с проверенными
dev-артефактами и свидетельствами их происхождения; остальные временные сборки
удаляются по прежним правилам.
Команда не удаляет исходники и не следует внешним символьным ссылкам.

## Подготовленные draft-assets

Если draft выпуска уже содержит ровно wheel, sdist и SHA256SUMS, задача публикации
проверяет их контрольные суммы, metadata, MIT, границы архивов и совпадение всех
package sources с проверенным checkout. Допускается только переносимость переводов
строк исходного текста; изменение или пропуск модуля отклоняется. Принятый wheel
публикуется без пересборки и изменения SHA. Пустой draft заполняется проверенными
CI-артефактами. Неполный draft и уже опубликованный выпуск не перезаписываются.
