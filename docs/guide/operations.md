# Копирование и изменение структуры

Операции работают с документом или отдельным структурным поддеревом, без сеанса редактора. [Обход](traversal.md) даёт расположения для правок; библиотека проверяет принадлежность расположения корню, тип структурной позиции и бюджеты. Семантические ссылки и значения проверяются отдельно через `validate()` и при сохранении.

## Независимая копия

Для полного документа операции изменения и `transform_elements` дополнительно
проверяют объявленные [продолжения и родителей пунктов списка](lists.md).
Удаление используемой цели/роли отклоняется; автопереноса роли на другой абзац
нет. В преобразовании допустимо явно исправить все связанные роли до итоговой
проверки. Это не заменяет общую валидацию остальных семантических данных.

```python
from opendoc_model import DocumentModel, Paragraph, Section, TextRun, clone_model, extract_text

original = DocumentModel(sections=[Section(blocks=[Paragraph([TextRun("Черновик")])])])
copied = clone_model(original)
copied.sections[0].blocks[0].content[0].text = "Готово"
assert extract_text(original) == "Черновик"
assert extract_text(copied) == "Готово"
```

`clone_model(root, *, limits=None)` возвращает тот же тип корня. Все изменяемые объекты копируются: коллекции, вложенные пользовательские свойства, типизированные property bags, стили, геометрия, provenance с событиями, surrogate, ресурсы и непрозрачный пакет. Неизменяемые строки/байты могут разделяться. Внешний `Resource.source` сохраняется как строка и не открывается.

Общие объекты внутри исходника остаются общими **внутри копии**, но не разделяются с оригиналом. Например, два вхождения одного абзаца в копии указывают на один скопированный абзац. Его изменение видно в обоих местах. Чтобы получить независимый элемент для одной позиции, замените её отдельной копией через `replace_node()`.

Поддерево копируется целиком, но не получает стили/ресурсы из внешнего документа. Идентификаторы сохраняются; разрешение ссылок относится к содержащему документу. `clone_model()` проверяет форму дерева, циклы и бюджет, но не требует разрешённых ссылок или семантически законченного документа.

## Вставка, замена и удаление

| API | Результат и изменение |
|---|---|
| `insert_node(root, parent, field, index, node)` | Вставляет независимую копию `node`, возвращает её `NodeLocation` |
| `replace_node(root, location, node)` | Заменяет одно вхождение независимой копией, возвращает новое `NodeLocation` |
| `remove_node(root, location)` | Удаляет вхождение, возвращает отсоединённый живой объект |

Эти три операции меняют переданный корень **на месте**. `parent`/`location` берётся из обхода именно этого корня; расположение от оригинала не подходит копии. Сначала копируйте документ, если нужно сохранить оригинал.

```python
from opendoc_model import insert_node, iter_sections, replace_node, remove_node

section = next(iter_sections(copied))
added = insert_node(copied, section, "blocks", 1, Paragraph([TextRun("Приложение")]))
changed = replace_node(copied, added, Paragraph([TextRun("Временный блок")]))
detached = remove_node(copied, changed)
assert detached.plain_text == "Временный блок"
assert extract_text(copied) == "Готово"
```

Допустимые коллекции совпадают с моделью: `DocumentModel.sections`; семь коллекций `Section`; `Table.rows`; `TableRow.cells`; `TableCell.blocks`; `Paragraph.content`. Тип нового узла должен подходить позиции. Например, таблица подходит блокам, но не inline-содержимому абзаца. Произвольные поля вроде `page` не являются местом вставки.

Индекс вставки — целое число от `0` до длины коллекции включительно. Отрицательные, булевы и дробные индексы отклоняются с `ValueError`, а не округляются/ограничиваются. Корень нельзя удалить или заменить на месте: присвойте другой корень своей переменной.

Проверка расположения проходит по всей цепочке родителей и проверяет объект в указанном индексе. Смещённая позиция, заменённый/удалённый узел, отсоединённый предок или чужой корень дают `ValueError`. После структурных правок выполняйте новый обход для следующих позиций. Путь остаётся снимком вхождения, а не постоянным ID; перестановку неразличимых вхождений одного общего объекта путь не различает.

Перед правкой проверяется исходная структура, перед копированием — входное поддерево, после правки — итоговый корень. Если итог превышает бюджет, прежняя коллекция восстанавливается с теми же объектами и идентичностью списка. Копия нового элемента отделена от его источника. При удалении оставшиеся ссылки/стили/ресурсы автоматически не удаляются. Повторно используемая коллекция принадлежит общему объекту: правка такой коллекции видна во всех вхождениях её владельца.

## Преобразование выбранных элементов

`transform_elements(root, types, transform, *, predicate=None, limits=None)` возвращает независимую копию корня. `types` имеет те же правила, что `iter_elements()`. Необязательный `predicate(location)` выбирает вхождения; `transform(location)` получает объект **копии** и возвращает:

- тот же элемент, чтобы оставить изменения его полей/поддерева;
- другой элемент, чтобы заменить вхождение независимой копией возвращённого объекта;
- `None`, чтобы удалить вхождение.

```python
from opendoc_model import iter_elements, transform_elements


def finalize(location):
    for run in iter_elements(location.node, TextRun):
        run.node.text = run.node.text.replace("Черновик", "Готово")
    return location.node


result = transform_elements(original, Paragraph, finalize, predicate=lambda location: "Черновик" in location.node.plain_text)
assert extract_text(result) == "Готово"
assert extract_text(original) == "Черновик"
assert result.validate() == []
```

Выборка снимается до обработчиков. Предикаты вызываются в прямом порядке обхода, преобразования — в обратном: потомки перед родителями, поздние соседи перед ранними. Поэтому удаления не сдвигают ещё не обработанные соседние индексы; обработчик родителя видит уже изменённых потомков. Замена родителя может затем отбросить результат работы над его потомками. Новые элементы не попадают в первоначальную выборку и повторно не обрабатываются.

Обработчик может менять собственные поля и поддерево. Перемещение его предков/соседей может сделать выборку устаревшей и приводит к `ValueError`. Корень, выбранный как элемент, должен остаться того же типа и не может быть удалён. Внутренние общие объекты сохраняются: обработчик вызывается для каждого выбранного вхождения, поэтому изменение общего текста может примениться несколько раз. Для однократной обработки общих объектов можно явно выбрать первое вхождение в предикате.

Ошибка предиката/обработчика передаётся вызывающему коду; частичного результата нет. Ошибка структуры или итогового бюджета также отменяет возврат результата. Библиотека не изменяет исходник, но не может отменить внешние действия пользовательского обработчика. Для корректности обработчик должен работать с полученными объектами копии.

## Provenance и непрозрачный пакет

Копирование и структурные операции сохраняют предоставленные сведения о происхождении без выдуманного источника и без скрытого события истории. При замене используется provenance нового узла; если его нет, происхождение удалённого узла автоматически не наследуется. `remove_node()` возвращает объект с его прежним provenance.

Чтобы записать смысл изменения, явно используйте `node.provenance = node.provenance.transformed("replace-text", detail="...")`, если provenance существует. В независимой копии прежние события также независимы от оригинала. [Исполняемый пример](../../examples/operations.py) копирует документ, преобразует выбранный абзац во вложенной таблице, сохраняет событие, проверяет модель и читает записанный JSON.

Непрозрачный `PackageGraph` копируется и хранится как данные. Правка семантического текста не переписывает байты его частей: согласование прикладного формата выполняет потребитель, который понимает этот формат.

## Извлечение текста

`extract_text(root, *, block_separator="\n", cell_separator="\t", row_separator="\n", include_alt_text=True, include_formula_source=False, limits=None)` извлекает текст в [порядке обхода](traversal.md). Все колонтитулы включаются один раз; повторение на физических страницах не моделируется.

- Inline внутри абзаца соединяются без добавочных разделителей.
- Секции, блоки секции и блоки ячейки разделяются `block_separator`.
- Ячейки строки разделяются `cell_separator`, строки таблицы — `row_separator`.
- Пустые узлы сохраняют свои структурные границы; результат не обрезается и пробелы не нормализуются.
- Изображения дают `alt_text`, если включён `include_alt_text`.
- Формулы дают `fallback_text`; при его отсутствии исходное представление включается только с `include_formula_source=True`.

Последнее правило отличается от прежнего `Paragraph.plain_text`, который использует исходник формулы при отсутствии fallback. XML/LaTeX не интерпретируется как отображаемая формула, XML-бэкенд не загружается. Разделители должны быть строками, флаги — `bool`; повреждённый извлекаемый текст и Unicode, который нельзя кодировать в UTF-8, дают `ValueError` с расположением.

`DocumentLimits` ограничивает входную структуру, число значений и встроенные данные всех операций. Для `extract_text()` дополнительно `max_bytes` ограничивает размер **результата в UTF-8**, включая разделители: превышение даёт `ArtifactLimitError` до сборки результирующей строки. Копирование и правки не расходуют JSON-бюджет байтов; при сохранении JSON его лимит применяется отдельно.

Операции не создают блокировок, транзакций приложения или undo/redo. Коллекции и расположения нельзя одновременно менять другим обходом/потоком. Окончательный документ проверяйте через `validate()`; JSON-запись сама выполняет [семантическую валидацию](validation.md).
