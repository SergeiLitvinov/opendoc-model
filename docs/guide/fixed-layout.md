# Фиксированная компоновка

Модель может хранить явно заданные страницы, координаты объектов, векторные
линии, происхождение и текстовые интервалы. Для проверенного двухстраничного
примера новые структуры не нужны. Библиотека не извлекает координаты из PDF,
не распознаёт таблицы, не рассчитывает позиции глифов и не рендерит страницу.

## Существующие декларации

| Данные | Контракт |
| --- | --- |
| Исходные страницы | `IntegrationModel.pages`, `DocumentPage.id/width/height/reading_order` |
| Области и поворот страницы | `PageGeometry`: media/crop, 0/90/180/270°, явные преобразования |
| Рамки объектов | `Paragraph.box`, `Table.box`, `Image.box`, `Formula.box`, `Annotation.box`, `FormControl.box` |
| Линии заполнения | `VectorScene`, `VectorPath`, `PathCommand`, stroke/stroke_width |
| Происхождение | `Provenance` и события `ProvenanceEvent` у существующих узлов/ресурсов |
| Интервалы текста модели | `TextRange` и `TextPosition`: anchor ID run, Unicode offset, affinity |
| Связь с исходным текстом | `SourceMap`, `SourceMapping`, `SourceSpan`, явно заданная единица `SourceFile.offset_unit` |

Координаты задаются в пунктах, исходная система имеет верхнее левое начало,
x направлен вправо, y вниз. `PageGeometry` сохраняет ненулевые/отрицательные
media/crop origins; преобразования не отсекают объекты за crop. `Box.rotation`
— отдельный поворот элемента, который не преобразуется автоматически вместе
с поворотом страницы. Подробности — в [геометрии страниц](page-geometry.md).

`DocumentPage` и `Section.page` имеют разные роли: первая описывает явно
декларированную страницу integration, вторая — настройки секции основной модели.
Они не синхронизируются автоматически и не определяют алгоритм пагинации.
Reading order содержит существующие anchors, не геометрическую сортировку.
Векторная сцена связана с узлом через `node_id`; привязка к странице следует
из объявленного reading order. Рамки аннотаций относятся к аннотациям, а не
объявляются универсальной геометрией глифов.

## Текст и история

`TextPosition.offset` измеряется Unicode code points, а не байтами UTF-8,
единицами UTF-16 или видимыми графемами. Emoji может занимать один code point,
а буква с combining mark — несколько. Конец может равняться `len(run.text)`;
reverse/out-of-bounds и отсутствующие anchors отклоняются.
`SourceSpan` относится к отдельному источнику с явно объявленной единицей
byte/codepoint; исходный интервал не подменяется интервалом изменённой модели.

`edit_anchored_text` сдвигает модельные TextRange по существующему affinity.
Он не пересчитывает Box, векторные линии, страницы или исторические SourceSpan.
После изменения текста потребитель заново измеряет компоновку либо оставляет
её неизвестной; сохранённая прежняя рамка не является доказательством её актуальности.

`Provenance.transformed` возвращает историю с новым событием. С 0.11.3 прежние
изменяемые события копируются независимо: правка события новой истории не меняет
исходную, и наоборот. Существующий формат provenance и конструкторы сохранены.

## Сохранность и границы проверки

[Собственный пример](../../examples/fixed_layout.py) создаёт две страницы,
поворот/crop, дробные рамки, линии, поля, аннотации, Unicode-интервалы и историю.
Два JSON-цикла сохраняют точные модельные декларации, порядок, число страниц,
ссылки и неизвестные поля. [Тесты](../../tests/test_fixed_layout.py) проверяют
четверть-обороты и обратные преобразования, копирование/извлечение, текстовую
правку, атомарный отказ при повреждённой ссылке, лимиты и JSON v1/v2.
JSON документа read1/2/write2, integration v1 и PageGeometry v1 не меняются.

Для точной проверки сохранности сравниваются `document_to_dict` и
`get_integration`, включая pages/ranges/source_map/scenes. Общий
`compare_documents` проверяет свой заявленный структурный профиль; он не является
полной проверкой всех integration-деклараций и истории provenance. Снимки
геометрии объектов в общем inventory округляются до трёх знаков. Их совпадение
не доказывает побитовую сохранность координат или совпадение нативного PDF.

Этот аудит подтверждает достаточность модельных входов для собственного
конечного примера. Произвольные clip/group, шрифты, полная геометрия глифов,
визуальные замены и открытие результата в нативном приложении требуют отдельной
приёмки потребителя. Сохранность JSON не обещает их поддержку.
