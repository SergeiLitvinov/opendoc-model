# Размещённые глифы и редактируемый текст

Контракты **C-TEXT-LAYOUT-01/02** описывают связь глифов с текстом.
Отсутствие layouts сохраняет обычное поведение документа.

`TextRun` остаётся владельцем редактируемого текста, `TextRange` — логического
интервала Unicode codepoints. `TextLayout` хранит одно независимое вхождение
размещённых глифов, а `TextCluster` связывает несколько диапазонов с несколькими
глифами. Существующие типы не давали этой связи: `VectorPath` описывает контур,
`SceneOccurrence` — вхождение узла, `FontReference` — программу шрифта. Ни один
из них не заменяется и не дублируется новым текстовым деревом.

## Данные и координаты

`TextLayout(id, glyphs=(), fonts=(), clusters=(), page_id=None, scene_id=None,
transform=AffineTransform(), state="unknown", binding_sha256=None, provenance=None,
*, binding_version=1)`
— неизменяемая запись `IntegrationRecord` с `extra`. ID уникален среди layout
документа. Разные fill/stroke или иные наблюдения одного текста получают разные
layout ID; от них не требуется единственная общая привязка.

`glyphs` — tuple компактных строк `GlyphPlacement` из **восьми** значений:

| Колонка | Смысл |
| --- | --- |
| 0 | Индекс в `layout.fonts` или `None`, если привязка программы неизвестна |
| 1 | Неотрицательный glyph ID или `None`, если неизвестен |
| 2–7 | `a,b,c,d,e,f`: матрица из glyph-local точек в layout-local точки |

Каждая строка в JSON становится массивом, а не словарём с повторяющимися ключами.
`fonts` — отдельная таблица существующих `FontReference(resource_id, face_index)`.
Одна программа не повторяется байтами в каждом глифе. Glyph ID допустим только
при явном индексе программы и известном `face_index`, включая явный ноль.
`face_index=None` остаётся неизвестным; sentinel `-1` не является glyph ID.
Проверяются наличие и вид FONT-ресурса, но не таблицы шрифта, существование лица,
число глифов или права встраивания. Это непрозрачная программа, без установки
шрифта, парсинга или открытия внешнего `Resource.source`.

Все координаты конечны. Матрица использует существующую конвенцию:
`x' = a*x + c*y + e`, `y' = b*x + d*y + f`. Glyph-local координаты уже выражены
в пунктах; перевод font design units выполняет производитель. Общий `transform`
переводит layout-local точки в координаты указанной сцены, либо страницы, если
сцена отсутствует. При двух ID страница — объявленная принадлежность сцены;
модель проверяет существование обеих целей, но не вычисляет их нативную связь.
Без обоих ID родительская система остаётся неизвестной. Отражение, поворот,
shear, отрицательные координаты и непоследовательные позиции сохраняются.
Порядок glyph rows — порядок внутри наблюдения, не порядок чтения или рисования.
Контракт не задаёт paint, clipping, видимость, advance, shaping или bidi алгоритм.

`TextCluster(glyph_indices, range_ids=())` ссылается на локальные индексы строк
и существующие ID `TextRange`. Внутри одной записи повторы запрещены; разные
кластеры могут разделять диапазон/глиф. Например, `fi` с offsets `[0,2)` может
соответствовать одному глифу; один codepoint — двум глифам. Несколько ranges
могут относиться к разным TextRun; cross-run ranges включают промежуточные runs.
Пустой `range_ids` означает неизвестное сопоставление, а не пустой текст.
Глиф/программа и семантическое сопоставление могут быть неизвестны независимо.

## Правка и актуальность

Все имена доступны из `opendoc_model` и `opendoc_model.text_layout`:

| API | Поведение |
| --- | --- |
| `set_text_layout(document, layout, *, verify=False, limits=None)` | Независимо нормализует запись, сохраняет прежний extra и атомарно проверяет документ |
| `set_text_layouts(document, layouts, *, verify=False, limits=None)` | Нормализует iterable целиком, объединяет по ID и проверяет владельца один раз с общим кешем snapshot |
| `get_text_layout(document, layout_id, *, limits=None)` | Возвращает независимую запись/None; устаревший snapshot сообщает как stale |
| `invalidate_text_layout(document, layout_id, *, detach=False, limits=None)` | Явно сохраняет stale; при detach снимает range-ссылки и snapshot |
| `invalidate_text_layouts(document, layout_ids=None, *, detach=False, limits=None)` | Атомарно инвалидирует набор вхождений; None выбирает все; unknown остаётся unknown |
| `remove_text_layout(document, layout_id, *, limits=None)` | Удаляет вхождение, оставляя текст, диапазоны и FONT-ресурсы |

`unknown` — производитель ещё не подтвердил привязку. `verify=True` является
**явным утверждением производителя**, что переданная связь соответствует его
наблюдению; модель сохраняет snapshot и ставит `verified`. Все размещения должны
быть явно охвачены непустыми кластерами. Это не утверждает покрытие всего текста,
существование неизвестного glyph ID, корректность shaping или отсутствие
нативных потерь. Совпадение ID само не повышает unknown до verified.

Для множества новых вхождений используйте пакетный setter (C-TEXT-LAYOUT-02):

```python
from opendoc_model import set_text_layouts

# Производитель явно подтверждает весь переданный набор привязок.
set_text_layouts(document, layouts, verify=True, limits=limits)
```

Порядок прежних вхождений сохраняется, новые добавляются в порядке входа.
Замена сохраняет прежний `extra`, а переданные ключи имеют приоритет. Остальные
layouts и реестры не удаляются. Пакет и вложенные данные независимы от входа.
`verify=True` подтверждает только переданные записи; остальные unknown остаются
unknown. Без verify переданное состояние не повышается. Все устаревшие привязки
можно заменить одним пакетом без предварительной последовательной инвалидации.
Повтор входного ID, неверная запись, ссылка, неполный набор устаревших привязок
или превышение бюджета отклоняют весь пакет. Пустой пакет также выполняет
полную проверку владельца. Даже бесконечный iterable ограничен
`max_nodes`; общий codec и квота snapshot не обходятся.

Одиночный setter использует тот же маршрут. Пакет делает одну общую запись и
проверку владельца; snapshots рассчитываются с общим кешем контекста отдельно
для утверждения производителя и финальной проверки. Это устраняет повторный
обход накопленного документа для каждого span. Работа остаётся пропорциональна
суммарному размеру snapshots; большие пересекающиеся ranges или named styles
по-прежнему расходуют бюджет каждого snapshot.

SHA256 snapshot фиксирует объявление layout, диапазоны/offsets/affinity,
полный текст и прямой стиль участвующих runs, контекст абзацев, named styles,
объявленную геометрию страницы/сцены и FONT-программы. Числовые длины
нормализуются для устойчивости к JSON. Snapshot консервативен: изменение любого
named style, даже неиспользуемого, может сделать layout stale. Внешние файлы
не открываются: изменение содержимого за прежним URI так обнаружить нельзя.
SHA256 — проверка актуальности данных, не доказательство верности отображения.

Расчёт отмечен keyword-only полем `binding_version`: отсутствие поля означает
прежнюю версию 1, которая продолжает проверять старые snapshots без изменения
их SHA256 и JSON. Явный `verify=True` создаёт версию 2: текст/стиль/контекст
каждого участвующего TextRun входят в snapshot один раз, а диапазоны сохраняют
свои точные offsets, affinity и упорядоченные ссылки на владельцев. Тысячи
кластеров одного run больше не повторяют полный текст тысячи раз. Отдельные
TextRun с одинаковыми значениями не сливаются. Версия 2 записывается явно;
unknown/stale старой версии не мигрируют сами. Неподдержанные версии отклоняются.
В dev-читателе, не знающем версию 2, новый snapshot не подтверждается: нужен
актуальный API. Прежние документы без layout не меняются.

`edit_anchored_text` переносит offsets существующим способом и консервативно
снимает verified у layouts при изменении текста. Глифы не перераскладываются.
Прямое присваивание тексту/стилю или геометрии также не оставляет старую
привязку действующей: getter сообщает stale, а валидация и JSON-запись отказывают
до явной инвалидации или новой привязки. Сам getter документ не меняет.
Другие структурные операции, делающие ссылки неверными, откатываются по прежним
правилам integration. Для редактирования преобразованием можно сначала явно
инвалидировать layout на независимой копии. Повторная раскладка принадлежит
производителю; `verify=True` не выполняет её за него.

Если после прямой правки устарели несколько verified-вхождений одного текста,
их необходимо инвалидировать **одним атомарным вызовом**:

```python
from opendoc_model import invalidate_text_layouts

# После прямой правки текста оба вхождения требуют инвалидации.
invalidate_text_layouts(document, ("fill", "stroke"))
# Либо без layout_ids, чтобы выбрать все вхождения документа.
```

Последовательные одиночные вызовы здесь не заменяют batch: первый такой вызов
правильно отклоняется, пока второе вхождение остаётся объявлено verified с
устаревшим snapshot. Batch не отключает общую проверку владельца. Если набор
не покрывает все требующие инвалидации вхождения, есть неизвестный ID,
dangling-ссылка или превышен лимит, документ остаётся прежним. Glyphs, ranges,
fonts, provenance, extra и исторический snapshot сохраняются; при detach ссылки
и snapshot снимаются явно. Unknown не становится verified или stale автоматически.
Повтор ID допустим, но даже повторяющийся iterable ограничен max_nodes.

Для собственной пакетной правки также доступен прежний общий маршрут:
`get_integration` → `dataclasses.replace` всех нужных typed records → один
`set_integration`. Это та же атомарная граница проверки, без прямой записи в metadata.

## Композиция и удаление

`clone_model` сохраняет независимую копию и verified при неизменном содержимом.
Merge и resource/anchor remap переносят типизированные ссылки, но консервативно
ставят verified-layout в stale, даже при тождественных картах. Extract замыкает
ссылки через прежние ranges/якоря и также снимает verified. Unknown остаётся
unknown. Глифы, unknown fields и provenance сохраняются; история не становится
новой действующей привязкой автоматически.

Специального API split текста нет. Выделение частей использует `extract_document`,
повторная сборка — `merge_documents`, отдельные ObjectMapping — явный remap.
Custom split/ID remap требует явной инвалидации и корректировки диапазонов.
Merge по-прежнему использует выбранную политику metadata, а не автоматически
объединяет интеграционные реестры всех входов. Карты DocumentIdMap не меняются.

Stale не разрешает dangling-ссылки: все оставленные range/page/scene/FONT ссылки
должны существовать. Удаление используемого TextRun/диапазона/программы
отклоняется. Сначала удалите layout либо явно используйте `detach=True`, затем
удалите зависимые ranges и узлы. Detach не снимает страницу/сцену/FONT-программу;
их замена/удаление требует отдельной правки или снятия layout. Ресурсная замена
проверяет FONT kind, переносит ссылку и ставит layout stale атомарно.

## JSON и бюджеты

Хранение — необязательное `IntegrationModel.text_layouts`. Прежние документы
без layout не получают нового ключа и не расходуют новые default nodes.
Конструктор IntegrationModel сохраняет прежние позиционные аргументы; новое
поле keyword-only. Схема integration остаётся 1, JSON документа — запись 2,
чтение 1/2. Два цикла выполняются через `document_to_json/from_json` или
`integration_to_dict/from_dict`. Standalone codec проверяет типы, размерности и
локальные индексы, но внешние ссылки и актуальность подтверждает только владелец.
Старый читатель может переносить неизвестный text_layouts как extra, но не умеет
проверять, использовать или переносить его ссылки; такой перенос не подтверждает
актуальность. API входит в opendoc-model 0.1.0.

Актуальность требует однозначного контекста: дубли TextRun-якорей, ID ranges/
pages/scenes и несовпадение FONT ID с ключом реестра не могут сохранить
`verified` в getter даже при одинаковом тексте и координатах. Getter сообщает
stale; полная валидация и запись продолжают отклонять такой документ.
Инвалидация не исправляет дубли/неверные ссылки и откатывается до их устранения.

Обычные dict и `VersionedProperties`, допустимые для property bags полного
документа, приводятся к одному JSON-виду snapshot. Они не вызывают ложный stale
после двух циклов чтения/записи. Повреждённые типы контекста не приводят к
`AttributeError`: getter сообщает stale, а полная проверка отклоняет документ.
Это относится и к замене записи FONT-ресурса обычным dict: запись должна
оставаться `Resource`, инвалидация не исправляет тип владельца.
Для повторного подтверждения каждого вхождения нужен явный `verify=True` после
проверки производителем; unknown-вхождения автоматически не повышаются.
Нормализация размера шрифта применяется только к числам: bool и числовая строка
не могут совпасть с допустимой длиной и сохранить verified через приведение типа.

Общее объектное сравнение/инспекция не являются проверкой точности глифов,
нативной видимости или полноты coverage. Для проверки контракта сравнивайте
явные layout/ranges и состояния, а для нативного результата нужна отдельная
приёмка производителя. Наличие verified не превращает общий отчёт в lossless.

`extra` layout/cluster/font/transform сохраняется. Дополнительной схемы на каждый
glyph row нет: неизвестная размерность строки отклоняется, а не обрезается.
Неверный FONT kind/face, отрицательные индексы, dangling и NaN/Infinity дают
`ValueError` с адресом; превышение — `ArtifactLimitError` path/quota/maximum.
Неподдержанная форма не оставляет частично записанный layout.

Каждый glyph row из восьми значений расходует не менее девяти nodes, плюс
таблицы fonts/clusters и остальная модель. Общий бюджет не увеличивается
автоматически: 12 000 строк уже превышают обычные 100 000 nodes. Для крупного
наблюдения явно задайте, например, `DocumentLimits(max_nodes=500_000)` во всех
операциях. Unknown JSON values также расходуют квоты; FONT bytes учитываются
в embedded-бюджете полного документа.

Расчёт snapshot ограничен теми же nodes/depth/bytes и отдельной квотой работы
`layout binding work`, максимум которой равен выбранному `max_nodes`. Она считает
обрабатываемые значения snapshot суммарно по verified-layouts одной проверки;
сильное перекрытие владельцев может потребовать большего бюджета, даже если
wire-компактен. Font digests и контекст обхода кешируются только на время этой
проверки. Общий или byte/embedded лимит не обходится. Ошибка квоты не превращается
в успешный stale/unknown результат.

Исполняемый пример: [text_layout.py](../../examples/text_layout.py).
Ни parser, ни font/shaping/rendering engine не становятся зависимостью Model.
