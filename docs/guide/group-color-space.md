# Пространство композиции группы

С версии 0.16.0 C-GRAPHICS-02 добавляет `GroupColorSpace` в существующий
`GroupCompositing.color_space`. Цвет отдельного Paint не определяет пространство,
в котором смешивается полный результат группы. Одинаковые Paint и opacity
могут сопровождаться разными объявлениями пространства группы.

`ColorSpace` и `ColorValue` сохраняют прежний контракт значений sRGB/CMYK.
Строка `ColorValue.icc_profile` не становится ресурсной ссылкой автоматически.
Новая декларация имеет другую роль: промежуточная композиция общего scope,
включая Gray, некалиброванный RGB и непрозрачный профиль. Она не запускает
`ColorValue.to_srgb`, ICC-движок или другие цветовые преобразования.

## Пространства и профиль

| `GroupColorSpace.space` | Смысл |
| --- | --- |
| `rgb` | Общая трёхкомпонентная RGB-модель, без обещания sRGB-калибровки |
| `gray` | Однокомпонентная модель Gray, без придуманной transfer function |
| `cmyk` | Общая четырёхкомпонентная CMYK-модель |
| `srgb` | Явная стандартная sRGB-колориметрия; переопределение профилем запрещено |
| `icc` | Пространство, явно заданное profile_resource_id; ссылка обязательна |
| None | Неизвестное пространство, включая случай известной ссылки на непрозрачный профиль |

Отсутствие `color_space` и запись `GroupColorSpace()` сохраняются как разные
декларации JSON, но оба состояния остаются неизвестными для композиции.
Ни одно из них не превращается в RGB, sRGB, пространство родителя или цвета Paint.
Неподдержанное имя вроде native-режима сохраняется в extra при space=None;
произвольные строки, bool и числовые значения вместо space отклоняются.

`profile_resource_id` ссылается на существующий `ResourceKind.ATTACHMENT`.
Байты и media_type профиля непрозрачны; обычное представление может использовать
`application/vnd.iccprofile`. Модель не проверяет сигнатуру ICC, число каналов,
класс профиля, лицензию или соответствие профиля объявленным RGB/Gray/CMYK.
Эти модели могут иметь необязательную профильную ссылку; None с известным
профилем сохраняет неизвестность модели. Явное srgb не допускает profile override.
Внешний ресурс не загружается автоматически. Профильная ссылка — декларация
данных, а не подтверждение применимости или качества цветового преобразования.

## Чтение, правка и удаление

```python
from opendoc_model import GroupColorSpace, get_scope_color_space, set_scope_color_space

set_scope_color_space(document, "scene", "group", GroupColorSpace("gray"))
assert get_scope_color_space(document, "scene", "group").space == "gray"
set_scope_color_space(document, "scene", "group", None)
assert get_scope_color_space(document, "scene", "group") is None
```

API принимает ID VectorGroup или SceneOccurrence в сцене. Getter возвращает
независимую запись; неизвестный ID — ошибка, а отсутствие декларации — None.
Setter атомарно изменяет только color_space. Opacity, isolation, knockout,
blend, clip, transform, children и локальные ID сохраняются. Для неизвестной
compositing записи создаётся GroupCompositing с остальными неизвестными полями;
значения не достраиваются из legacy. Общий scope_version=1 остаётся на месте.
Старую чисто векторную сцену нужно явно мигрировать к этому профилю перед правкой.

Неизвестные extra предыдущей декларации сохраняются при замене. Удаление None
убирает эту декларацию вместе с её extra; профильный ресурс остаётся в документе,
а не удаляется неявным сборщиком. Нативное имя в VectorGroup.extra остаётся
неисполняемым свидетельством и не восстанавливает удалённую декларацию.
Пакетная правка через dataclasses.replace и set_vector_scene также поддерживается.

## Ссылки, JSON и лимиты

Существование и kind профиля проверяются при set/validate/check/JSON. Dangling,
wrong-kind, ICC без ссылки и конфликт srgb с профилем дают расположенный
`integration.invalid`. Инспекция общего scope с неизвестным пространством даёт
INFO `graphics-color-space-unknown`; это допустимая декларация с недоступной
колориметрией, а не подтверждённый Normal/RGB результат.

Clone сохраняет независимые данные. Merge переназначает профильный ID существующей
resource-картой; локальные ID сцены/scopes сохраняются. Выбор integration metadata
при merge остаётся явной прежней политикой. Extract включает профиль в замыкание
ресурсов. `integration_resource_uses` учитывает новые ссылки; remove/replace resource
отказывают при dangling/wrong-kind или корректно перенаправляют все объявления.
Удаление color_space отсоединяет профиль только в этом scope.

Все новые операции принимают DocumentLimits. Проверки выполняются до рекурсивного
кодирования/копирования записи, выбранный бюджет передаётся во внутренние операции.
Исчерпание сохраняет path/quota/maximum, включая maximum=0; ошибка setter или
ресурсной операции оставляет исходник неизменным. Бюджет встроенных данных
учитывает профиль как обычный ресурс документа, без разбора его байтов.

Новое keyword-only поле color_space=None не выводится в прежний JSON и не
увеличивает прежний счётчик обхода. Чтение v1/v2 и запись v2 документа,
integration v1, scope_version=1 и старые конструкторы сохранены. Неизвестные
поля переносятся через extra; подмена известных полей не разрешена. Новых
обязательных зависимостей нет. Понимание и remap профильной ссылки требуют
новой версии библиотеки; транспорт старым кодеком не доказывает её поддержку.

[Пример](../../examples/group_color_space.py) и
[тесты](../../tests/test_group_color_space.py) проверяют два JSON-цикла,
RGB/Gray/unknown, профили, правку/удаление, remap, замыкание и лимиты на собственных
непрозрачных данных. Generic compare не вычисляет цвета группы и не доказывает
сохранность пространства; конечный профиль проверяется по декларациям и JSON.
Чтение нативных CS, DefaultRGB, overprint и визуальная приёмка остаются у потребителя.
