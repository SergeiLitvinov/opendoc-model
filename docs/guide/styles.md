# Свойства и эффективный стиль

OpenDoc Model сохраняет заданные стили и отдельно вычисляет их эффективные значения.
Разрешение стиля не меняет документ, не материализует свойства в каждом run и не
добавляет историю преобразований. Исполняемый сценарий — `examples/styles.py`.

## Строгое чтение и запись свойств

Все типизированные bags — `SectionProperties`, `ParagraphProperties`,
`TextStyleProperties`, `ImageProperties`, `TableProperties`, `TableRowProperties`,
`TableCellProperties` — предоставляют методы:

```python
properties.get_typed(key, *, limits=None)
properties.set_typed(key, value, *, limits=None)
```

Известны поля существующих публичных accessors, включая унаследованные поля
`ParagraphProperties` в `TextStyleProperties`. Неизвестное имя даёт `ValueError`;
расширения читают и записывают обычным `properties[key]`. Другие ключи при строгой
операции сохраняются. Отсутствующее поле и явный `None` читаются как `None`, в том
числе для контейнеров. Запись `None` сохраняет ключ; `del properties[key]` удаляет его.

| Тип поля | Допустимые значения и нормализация |
| --- | --- |
| `str` | Только строка, включая пустую; автоматического `str(object)` нет |
| `bool` | Булево, целые 0/1, строки `0/false/off/no` и `1/true/on/yes` без учёта регистра и внешних пробелов |
| `int` | Целое без bool либо десятичная ASCII-строка с необязательным знаком и внешними пробелами; дроби не усекаются |
| `float` | Конечное число без bool либо строка, преобразуемая в конечное число |
| `list[int]`, `list[str]` | Именно список; элементы преобразуются по тем же правилам |
| `dict[str, int]` | Именно словарь с текстовыми ключами и целыми значениями по тем же правилам |
| `WrapPolygon` | JSON-словарь с `edited: bool` и `points: list` словарей с целыми `x`, `y` без bool; дополнительные поля сохраняются |

Ошибка преобразования даёт `ValueError` с именем схемы, ключом и расположением
элемента контейнера. Чтение не нормализует хранимое значение. Запись сначала
проверяет и преобразует значение, затем присваивает его; отказ оставляет bag
нетронутым. Контейнеры результата и записанные контейнеры независимы от входа.
Значение проходит JSON-проверку с [DocumentLimits](limits.md), включая циклы,
глубину, число значений и объём текста. Превышение даёт `ArtifactLimitError`.
Ограничения применяются к одному значению; они не валидируют прочие поля bag.

Это преобразование типов, а не проверка предметных диапазонов или ссылок.
Например, существование `base_style_id` проверяет модель/разрешение стиля;
`set_typed` принимает любую строку. `WrapPolygon` координаты задаются целыми,
дополнительные поля не получают неявной семантики.

Совместимость: прежние read-only accessors, конструкторы и mapping-запись
сохраняют поведение. Старые getters могут преобразовать произвольное значение
в строку, применить `bool(value)`, усечь дробь через `int` или вернуть пустой
контейнер при неподходящем типе; numeric getters сохраняют исключения Python.
Для контролируемых данных используйте новые методы. JSON продолжает сохранять
сырые допустимые значения bags без автоматического преобразования известных полей.

## Предпочтительная ширина таблиц и ячеек

С версии 0.4.0 `WidthMeasure` описывает предпочтение, а не измеренную ширину.
`get_preferred_width(table_or_cell, *, limits=None)` возвращает независимую меру
или `None`; `set_preferred_width(table_or_cell, measure_or_none, *, limits=None)`
проверяет данные до изменения. Исполняемый пример —
[table_widths.py](../../examples/table_widths.py).

| kind | value / unit / reference |
| --- | --- |
| absolute | Конечное неотрицательное число; `unit="pt"`, без reference |
| relative | Конечная неотрицательная доля; `unit="ratio"`, reference обязателен |
| auto | Число, unit и reference отсутствуют: ширину выбирает потребитель |
| unspecified | Число, unit и reference отсутствуют: предпочтение явно не задано |

Для таблицы relative reference равен `"content"`: доступная область содержимого
контейнера, включая ячейку для вложенной таблицы. Для ячейки reference равен
`"table"`: ширина содержащей таблицы. Доля 0.1 означает 10 процентов; доли выше 1
разрешены как предпочтение с возможным переполнением. Ядро не выбирает ширину
контейнера и не вычисляет компоновку. Ноль, auto, unspecified и отсутствие данных
различаются. Bool, отрицательные/неконечные числа и несогласованные единицы
отклоняются. Пункты равны 1/72 дюйма, 20 twips равны одному пункту.

```python
set_preferred_width(table, WidthMeasure("absolute", 480, "pt"))
set_preferred_width(cell, WidthMeasure("relative", 0.1, "ratio", "table"))
cell.properties.set_typed("width_twips", 960)  # явная абсолютная правка: 48 pt
```

В bags хранится JSON-значение `preferred_width`, например
`{"kind": "relative", "value": 0.1, "unit": "ratio", "reference": "table"}`.
`TableProperties.preferred_width` и `TableCellProperties.preferred_width` читают
явное новое поле как `WidthMeasure | None`. `get_typed("preferred_width")` возвращает
такую же меру; `set_typed` принимает меру или соответствующий JSON-словарь.
Неизвестные поля сохраняются в `WidthMeasure.extra`, без исполнения или новой
семантики. `to_dict(*, limits=None)` возвращает независимый ограниченный JSON;
extra не может перекрывать kind/value/unit/reference. Ограничения JSON и отказ
по бюджету применяются до записи. Общая валидация и JSON проверяют новое поле
автоматически с диагностикой `model.width.invalid`.

Setter ширины заменяет переданную меру целиком, не объединяя её extra с прежней
мерой. Чтобы изменить известное значение и сохранить неизвестные поля, прочитайте
меру через `get_preferred_width`, обновите её с `dataclasses.replace` и передайте
результат setter. Создание новой `WidthMeasure` без extra — явная замена данных
предпочтения. Частные соседние properties при этом сохраняются. Этот способ
правки показан в [исполняемом примере](../../examples/table_widths.py).

Совместимость: JSON документа v1/v2 и bags v1 сохранены. Старый reader сохраняет
новое поле как неизвестные данные; он не понимает его семантику. Если явного
нового поля нет, `get_preferred_width(cell)` читает legacy `width_twips` как
абсолютное предпочтение, не меняя bag. Старые getters и чтение старых bags
сохраняют прежнее поведение; некорректное legacy-значение новый getter отклоняет.

Явный `set_preferred_width`/`set_typed("preferred_width", ...)` удаляет дубль
`width_twips` ячейки. Явный `set_typed("width_twips", ...)` снимает новую меру.
`set_preferred_width(cell, None)` удаляет оба объявления; grid и частные
расширения сохраняются. Прямые mapping-изменения не означают последнюю явную
правку: одновременно заданные поля принимаются только при одинаковой
абсолютной мере; противоречие диагностируется. Нативные type/value в неизвестных
расширениях не читаются и не мигрируют автоматически.

Копирование, объединение и извлечение сохраняют объявления ширины. Инвентарь
таблицы содержит `preferred_widths` с мерой таблицы и матрицей мер ячеек.
Сравнение сообщает `table-width-change` (WARNING) и удаление известной меры
`table-width-loss` (LOSS), с расположением таблицы и снимками обоих объявлений.
Это не доказательство изменения отрисовки. Сравнение прежних инвентарей без
`preferred_widths` не придумывает измерение или потерю. Некорректное legacy-поле
остаётся неизвестной мерой; фактическая геометрия по-прежнему измеряется отдельно.

## Разрешение стиля

### Цвет: auto, отсутствие и наследование

Существующий `TextStyle.color` (и `background`) принимает `ColorValue`, строку
или `None`. Точная строка `"auto"` обозначает явный автоматический цвет:
она перекрывает унаследованное значение и сохраняется строкой в JSON.
`None` разрешает наследование; отсутствующее поле JSON читается как `None`.
Если нет значения во всей цепочке, результат неизвестен (`None`), а не чёрный.
Пустая строка остаётся прежним явным legacy override и не превращается в auto.

`ColorValue` описывает известный цвет SRGB/CMYK, не автоматический цвет.
Новый тип или версия JSON для auto не нужны. `resolve_style` и
`effective_text_style` разрешают только модельные `base_style_id`, стиль абзаца
и inline-стиль run. Нативные темы, правила конкретного редактора и фактический
RGB для auto не рассчитываются. Непрозрачные properties с похожим названием
не подменяют типизированное поле. Явная правка задаёт `run.style.color`, удаление
прямого значения присваивает `None` и снова разрешает наследование.

`color_to_css("auto")` возвращает `None`: автоматический цвет нельзя выдать
за валидный CSS color или угаданный RGB. Прежние конкретные цвета и допустимые
legacy-токены сохраняют поведение.

С 0.11.2 инспекция абзаца содержит `text_colors`: разрешённые модельные
`paragraph`, прямые `paragraph_direct` поля выбранного стиля и `spans`
текстовых интервалов с `start/end`, `direct`, `resolved` для color/background.
Соседние одинаковые интервалы объединяются, пустые runs не создают видимого
цвета. Нативные поля и неиспользованные определения стилей не получают
собственного измерения цвета. `resolved="auto"` остаётся декларацией auto.

Сравнение работает на сопоставленных абзацах с одинаковым известным текстовым
хешем. Изменение известной декларации даёт `text-color-change` (WARNING),
утрата прямого/разрешённого значения или замена auto — `text-color-loss` (LOSS).
Удаление прямого auto остаётся потерей даже при повторном наследовании auto.
Это различие намерения деклараций, не оценка визуального сходства. Адрес абзаца
и оба снимка доступны в `DiagnosticIssue.measurement`; `QualityPolicy(0)`
отклоняет LOSS. Старые или некорректные inventory без полного снимка остаются
неизвестными (`text_colors_available=False`) и не порождают выдуманную потерю.
Изменённый текст не выравнивается по догадке: цветовые интервалы такого абзаца
не сравниваются. Новая диагностика не меняет JSON документа read1/2/write2,
формат `ColorValue`, конструкторы или зависимости.

[Пример](../../examples/text_colors.py) и
[собственные тесты](../../tests/test_text_colors.py) проверяют auto/None/наследование,
два JSON-цикла, правку/удаление, split runs, композицию и явные лимиты.

### Применение API

```python
resolve_style(document, style=None, *, overrides=None, limits=None)
effective_text_style(document, paragraph, run=None, *, limits=None)
```

Обе функции экспортированы из `opendoc_model` и возвращают независимый `TextStyle`.
`resolve_style` принимает ID из `document.styles`, самостоятельный `TextStyle`
или `None`. Сначала разрешается цепочка `base_style_id` до корня, затем значения
накладываются от корня к потомку. `overrides`, если задан, должен быть `TextStyle`;
его собственная цепочка разрешается отдельно и накладывается последней.

`None` в поле или property означает наследование. `False`, `0`, пустая строка,
пустой список или словарь — явное переопределение. Отсутствующий property ведёт
себя как `None`. Если нигде нет значения, поле остаётся `None`, а property не
появляется в результате. Эти правила относятся и к неизвестным JSON-свойствам.
Значения свойств накладываются по ключу: вложенный словарь/список заменяется
целиком, без глубокого слияния. `base_style_id` является управляющей ссылкой,
потребляется при разрешении и отсутствует в результате. Другие properties,
включая `numbering_source_style_id`, сохраняются как данные и не создают
дополнительного наследования. Значение `None` не является командой сброса;
неявных шрифта, размера, цвета и прочих defaults рендерера нет.

`effective_text_style` накладывает разрешённый `paragraph.style_id`, затем
ненулевые в смысле `is not None` свойства абзаца, затем разрешённый inline-стиль
заданного run. Свободный `base_style_id` в properties абзаца не создаёт цепочку.
Геометрия и `paragraph.alignment` остаются полями абзаца, не превращаются в поля
`TextStyle`. Без run возвращается стиль абзаца; run должен находиться в
`paragraph.content` по идентичности объекта. Сам абзац может быть вне документа:
его ссылки проверяются относительно стилей и ресурсов переданного документа.
Табличный стиль автоматически не применяется к содержимому ячеек; его ID
можно отдельно передать в `resolve_style`.

Перед операцией проверяется весь исходный документ, включая неиспользованные
стили, ресурсы и пакет. Для самостоятельного inline/абзаца проверяется также
его контекст. Отсутствующие ссылки, неверные типы и циклы дают `ValueError`.
Цепочка обрабатывается итеративно, без ограничения глубиной рекурсии Python.
`limits` ограничивает исходную модель, отдельный контекст и результирующий стиль;
размер JSON для сериализации проверяется отдельно при сохранении.
Мутируемые значения результата скопированы; внутренние общие объекты внутри
результата могут сохранять общую идентичность. Источник и override не меняются.
