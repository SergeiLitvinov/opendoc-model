# Составные группы потока

**C-BLOCK-GROUP-01.** BlockGroup — нейтральный scope потока документа;
он не задаёт отступы, каскад стилей, маркер списка или визуальную компоновку.

## Данные и идентичность

`BlockGroup(children, role="generic", list_owner=None)` входит в `Block` наряду
с Paragraph, Table, Formula и Image. Children сохраняют порядок и могут содержать
вложенные группы. Группа допустима в Section, его headers/footers, TableCell
и Footnote. `role` принимает только generic или quotation; quotation не добавляет
кавычек, шрифта или геометрии. Пустая группа допустима.

Обычные properties, provenance, необязательные box/visual_surrogate принадлежат
самой группе. `set_anchor(group, Anchor(...))` задаёт отдельную идентичность:
она не копируется детям. Walk возвращает группу и каждый дочерний occurrence;
обычные вставка, замена, удаление и clone работают с children. Повторное вхождение
одного объекта имеет отдельный путь, а повторный anchor в документе отклоняется.

## Один составной пункт списка

`BlockGroupListOwner(paragraph_id)` — типизированная ссылка на anchor существующего
primary Paragraph внутри этой группы. Его обычный ListItem остаётся единственным
владельцем номера. SDK не ищет первого ребёнка и не вставляет невидимый абзац.
Остальные блоки сами по себе не создают номера. Явные continuation_of и parent_id
по-прежнему адресуют primary Paragraph, а не anchor контейнера.

Владелец должен существовать ровно в одном occurrence внутри группы, быть
Paragraph с ListItem без continuation_of и не принадлежать другой вложенной
compound group. Вложенные compound items объявляют собственных владельцев;
прежние правила start/restart, unordered, уровней и продолжений не меняются.
Anchor группы и paragraph_id могут различаться и не подменяют друг друга.

Правка/удаление `group.list_owner` явные. Удаление связи оставляет дочерние
ListItem как есть; оно не удаляет их membership. Снятие membership с владельца
требует также снять/изменить связь группы. Удаление владельца через общий API
откатывается, если связь остаётся; удаление группы удаляет весь scope и его детей.
Прямые присваивания проверяются при validate/codec. Никакая правка не перенумеровывает
исходные данные: iter_list_numbers вычисляет номера из текущей модели.

## JSON, ссылки и границы

Новый JSON block имеет `type: "block_group"`, children, role и list_owner
(`{"paragraph_id": "..."}` либо null). Неизвестные поля самого block и ссылки
сохраняются в соответствующих `extensions`; properties также остаются открытыми.
Reserved поля в extensions отклоняются, чтобы исключить тихую перезапись.
Два JSON-цикла сохраняют структуру, provenance и unknown values; mutable данные
снимка, входного JSON и восстановленной модели независимы.

Формат документа остаётся `opendoc.document`, запись версии 2, чтение 1/2.
Старые документы и конструкторы не меняются. Старый читатель без BlockGroup
отклоняет новый type; перенос в такой читатель требует явного решения потребителя,
автоматического flattening нет.

Merge переименовывает paragraph_id вместе с anchor владельца и сохраняет
собственный anchor группы. Extract удерживает scopes и замыкает зависимости
на владельца; при необходимости это расширяет выборку до содержащего раздела.
Инвентарь объектов показывает группу, роль, ссылку и родителя детей. Сравнение
регистрирует изменение роли/владельца; это структурная проверка, не визуальная.

DocumentLimits передаются через walk/codec/композицию и правку: группа, children,
unknown поля и ссылка потребляют общий бюджет. Неверный child, role, owner,
структурный цикл и неподдержанная ссылка дают адресный отказ; превышение квоты —
ArtifactLimitError с прежними структурированными полями. Существующий ListItem API
по-прежнему принимает Paragraph. Парсинг исходных форматов, source mappings,
CSS/рендеринг и визуальная приёмка в библиотеку не входят.

Исполняемый пример: `examples/block_groups.py`.
