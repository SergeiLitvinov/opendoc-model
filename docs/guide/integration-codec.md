# Самостоятельный кодек IntegrationModel

С 0.18.0 публичные `integration_to_dict(value, *, limits=None)` и
`integration_from_dict(data, *, limits=None)` сериализуют `IntegrationModel`
без `DocumentModel`. Отдельная схема диагностики, фиктивный документ и приватный
импорт кодека не нужны. Обе функции доступны из `opendoc_model` и
`opendoc_model.integration`.

```python
import json
from opendoc_model import IntegrationModel, integration_from_dict, integration_to_dict

original = IntegrationModel(extra={"future": {"values": [1]}})
restored = original
for _ in range(2):
    restored = integration_from_dict(json.loads(json.dumps(integration_to_dict(restored))))
assert restored == original
```

## Форма данных и совместимость

`integration_to_dict` возвращает JSON-совместимый конверт прежнего вида:
`{"format": "opendoc.integration", "version": 1, "data": ...}`. Содержимое `data`
полностью совпадает с существующим кодеком интеграции в metadata документа.
`integration_from_dict` принимает **весь конверт**, а не отдельный `data` и не
строку JSON. JSON-текст читает стандартный `json.loads`, словарный кодек проверяет
полученные значения. Гарантия отсутствия дубликатов имён в исходном тексте
при таком разборе остаётся на стороне выбранного JSON-парсера; кодек получает
уже построенный словарь. Новых JSON/text или файловых API не добавлено.

Enum сохраняют тип при чтении, tuple-поля представлены массивами JSON.
Неизвестные поля `IntegrationModel` и вложенных `IntegrationRecord` проходят
через `extra`. Имена полей схемы и `extra` не могут быть перекрыты расширениями.
Причина и адрес диагностики, state, measurement, provenance и события сохраняются
при повторных dict/JSON циклах. Результат кодирования и восстановленная модель
не разделяют изменяемые вложенные значения с источником.

С 0.18.1 JSON-словари extra/measurement/properties/action проверяются до
копирования. Не-JSON объекты, включая memoryview и генераторы, отклоняются через
`ValueError`; собственный `__deepcopy__` объекта не может преобразовать их в
допустимое значение. Допустимые JSON-словари и списки копируются в обычные
контейнеры без вызова `__deepcopy__`, в том числе для подклассов контейнеров.
Общие вложенные значения не становятся циклами, но результат независим от
источника. Идентичность Python-подкласса контейнера не является частью JSON.

Служебные поля **внешнего конверта**, кроме format/version/data, относятся к
владельцу хранения, как и у `get_integration`. Они не входят в `IntegrationModel`:
standalone чтение допускает их, но новый конверт из `integration_to_dict` содержит
только три известных ключа. Для сохранения таких полей храните исходный конверт
у владельца; `set_integration` по-прежнему сохраняет их в существующем документе.
Это прежнее разделение конверта и типизированных данных, без скрытого переноса
служебных полей в `extra` модели.

Схема интеграции остаётся 1, JSON документа — запись 2 и чтение 1/2.
`get_integration` / `set_integration` и прежние документы совместимы. Читатели
прежних версий понимают тот же конверт; сами новые функции требуют 0.18.0.

## Проверка и бюджеты

Кодек проверяет типы и обязательные поля, enum, схему/версию, конечные числа,
JSON-значения, циклы данных и `DocumentLimits`. Непомеченный/чужой конверт,
отсутствие data, булева или неизвестная версия дают `ValueError`; превышение
квоты — `ArtifactLimitError` с прежними path/quota/maximum. В отличие от getter,
отсутствие конверта здесь не является успешным результатом `None`.

Бюджет передаётся в существующий типизированный кодек без сброса к умолчанию.
При кодировании проверяются модель, data и итоговый конверт; при чтении —
конверт и data. Это отдельные проверки представлений, без суммирования их
стоимости и без начисления пропущенных значений по умолчанию при decode.
Внешние ресурсы не загружаются, их байты не придумываются: ссылки на ресурс
не являются встроенными данными. Для большого ledger задайте, например,
`DocumentLimits(max_nodes=300_000)` в обоих вызовах.

**Успешный codec roundtrip не подтверждает валидность ссылок или документа.**
Без владельца кодек не разрешает node/resource/range ID, не проверяет всю
семантику графов и полноту assessment. Он сохраняет объявления, даже если
внешний якорь ещё не существует или профиль не объявлен. Полную проверку
по-прежнему выполняют `set_integration`, `check_document`, валидация и JSON-кодек
полного документа. Проверка сама не становится успешным свидетельством нативного
импорта, экспорта или отображения.

Исполняемый пример: [integration_codec.py](../../examples/integration_codec.py).
