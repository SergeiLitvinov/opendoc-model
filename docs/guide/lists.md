# Списки и нумерация

`ListItem(list_id, level=0, kind="ordered", start=1, restart=None)` задаёт принадлежность абзаца к списку независимо от текста и оформления. Непустой ID объединяет элементы в последовательность; отдельный реестр списков не нужен. Уровни — целые числа от 0 до 8, начальный номер и перезапуск — положительные целые числа. `bool` не принимается вместо числа. Для `kind="unordered"` допускаются только `start=1` и `restart=None`.

`set_list_item(paragraph, item)` устанавливает роль, `get_list_item(paragraph)` читает её, а `set_list_item(paragraph, None)` удаляет. Изменение проверяется до записи и сохраняет неизвестные поля распознанного расширения. `iter_list_items(document)` возвращает положения абзацев во всех семи коллекциях секции и вложенных таблицах. Повторные вхождения одного объекта учитываются отдельно.

`iter_list_numbers(document)` возвращает `ListNumber(location, item, number)`. Для маркированного элемента номер равен `None`. Для нумерованного элемента счётчик каждого уровня начинается с `start`, увеличивается при следующем вхождении и может быть явно изменён через `restart`. Более низкий по вложенности уровень сбрасывает более глубокие счётчики этого списка, включая случай маркированного родителя. Разные ID имеют независимые счётчики; обычный абзац не прерывает последовательность. Один ID продолжает последовательность между секциями и колонтитулами: для независимых последовательностей назначайте разные ID.

На одном уровне одного ID значения `kind` и `start` должны совпадать. Вся последовательность проверяется до выдачи первого номера. Уровень без родителя допустим. Результат содержит номер текущего уровня; составная метка, вид маркера и оформление принадлежат потребителю. Положение ссылается на живой абзац, роль и номер фиксируются на момент расчёта. После изменения структуры рассчитывайте номера заново.

## Сохранение и композиция

Прежняя роль без связей хранится в `Paragraph.properties["opendoc.list-item"]`
как JSON-объект с `format="opendoc.list-item"`, `version=1`, обязательным `list_id`
и необязательными полями прежнего конструктора с указанными выше значениями
по умолчанию. Неподдержанная версия объявленного расширения отклоняется;
произвольное значение без этого маркера остаётся непрозрачным и не перезаписывается
setter-ом. Старые свободные свойства нумерации автоматически не мигрируют.

`merge_documents` проверяет конфликты ID списков наряду со стилями и ресурсами. По умолчанию конфликт отклоняется; `conflicts="rename"` переименовывает группы с учётом всех исходных ID и возвращает карту `DocumentIdMap.lists`. Прежний конструктор карты с двумя аргументами сохраняется. `extract_document` сохраняет принадлежность; номер пересчитывается для полученной последовательности. Для фиксированного исходного номера задайте `restart` явно.

## Несколько абзацев и родительский пункт (C-LIST-02)

С 0.17.0 `ListItem` имеет два необязательных именованных аргумента:
`continuation_of` и `parent_id`. Оба используют существующий `Anchor`, без
дополнительного реестра пунктов. Первый абзац пункта имеет обычный `ListItem` и,
если на него ссылаются, якорь. Продолжение получает `continuation_of="якорь-первого"`.
Номер выдаётся только первому абзацу: у продолжения `ListNumber.number is None`.
Продолжение не увеличивает и не сбрасывает счётчики, в том числе вложенных уровней.
Обычный абзац без роли остаётся вне списка; принадлежность по соседству не угадывается.

`parent_id` указывает на первый абзац родительского пункта. Родитель, содержащий
только дочерний список, представлен пустым `Paragraph` с ролью и якорем. Родительская
ссылка отделена от `list_id` и `level`: дочерняя последовательность может иметь
собственный ID и уровень 0. Ссылка сама не меняет нумерацию и не задаёт вид маркера.
`None` означает отсутствие объявленной связи; прежний уровень без родителя остаётся
допустимым. Форматное дерево списков библиотека не создаёт.

Обе ссылки должны указывать на более ранний первичный абзац с ролью списка в
общем порядке обхода. Цепочка продолжений запрещена: все абзацы одного пункта
ссылаются непосредственно на первый. Продолжение должно совпадать с первым по
`list_id`, `level`, `kind`, `start` и `parent_id`; свой `restart` запрещён. Идентификаторы
непустые UTF-8 строки; dangling, неверный тип цели, циклы, ссылки на себя и
несовместимые объявления дают ошибку. Диагностика содержит путь ссылки и код
`semantic.list.reference`, `semantic.list.cycle` или `semantic.list.config`.
Глубина владения ограничена `DocumentLimits.max_depth`; общий обход и JSON используют
переданный бюджет, включая большие неизвестные поля.

Локальный `set_list_item` проверяет значение до записи и сохраняет неизвестные
поля; проверка ссылок всего документа выполняется `check_document`, JSON codec
и `iter_list_numbers` до выдачи первого результата. Для правки используйте
`dataclasses.replace`: снятие `continuation_of` делает абзац самостоятельным пунктом,
снятие `parent_id` убирает только родительскую связь, `set_list_item(..., None)`
удаляет всю роль. Старые произвольные свойства не восстанавливают удалённые связи.

`remove_node` / `replace_node` / `insert_node` над полным документом проверяют
оставшиеся связи и откатывают структурное изменение при ошибке. Удаление первого
абзаца с продолжениями или пустого родителя с дочерними пунктами отклоняется;
автоматического переноса роли, якоря или текста нет. Сначала явно сделайте
продолжение самостоятельным пунктом и исправьте зависимые ссылки либо снимите/
переназначьте родительские ссылки детей. Прямое изменение `blocks` возможно,
но оставленные dangling-ссылки отклоняются при следующей проверке или JSON-записи.
`clone_model` сохраняет связи и независимость данных; копия отдельного поддерева
сама не собирает внешние зависимости.

При композиции ссылки переименовываются через `DocumentIdMap.anchors`, ID
последовательностей — через `DocumentIdMap.lists`; вложенные неизвестные поля
остаются непрозрачными. `extract_document` замыкает ссылки на первый/родительский
абзац по общему правилу якорей: при необходимости включает всю исходную секцию
или сноску, а не только выбранный абзац. Номера вычисляются заново для результата.

Новые связи записываются в том же `opendoc.list-item`, **с версией расширения 2**.
Без связей setter пишет прежний объект версии 1, без новых ключей; прежний
позиционный конструктор и нумерация сохранены. Поля с такими именами в версии 1
остаются неизвестными и не интерпретируются как ссылки. Переход на версию 2
заменяет эти имена явными аргументами. При снятии обеих связей setter возвращает
версию 1, удаляя известные поля версии 2. Версия документа не меняется: запись 2,
чтение 1/2. Библиотека 0.16.0 отклоняет новые объявления версии 2 вместо
молчаливого добавления номеров продолжениям; для нового контракта требуется 0.17.0.

## Проверка и сравнение связей

Инспекция абзаца содержит `list_item` и вычисленный `list_number`, счётчики `semantic_list_items` и `ordered_list_items` считают новые роли. Прежний `numbered_paragraphs` продолжает учитывать старое свойство `numbering_id`.

`semantic_list_items` считает абзацы с ролью, включая продолжения;
`ordered_list_items` считает только первичные нумерованные пункты. Изменение
связей видно в `list_item`; отсутствие номера у продолжения является известным
результатом и не делает сравнение недоступным.

Сравнение возвращает `lists_available`, `changed_list_items`, `list_numbers_available`, `changed_list_numbers`. Старые или повреждённые инвентари не объявляются известными: соответствующие счётчики равны `None`. Снятие роли даёт `LOSS` с кодом `list-loss`, изменение роли — `WARNING/list-change`, изменение только вычисленного номера — `WARNING/list-number-change`. Общая политика качества может запрещать потери; объектная политика сама по себе не проверяет роли списков.

Исполняемый пример: [examples/lists.py](../../examples/lists.py).
