# JSON: данные и ошибки

`document_to_dict()` возвращает JSON-совместимое представление, `document_to_json()` — строку UTF-8 JSON. `document_from_dict()` принимает объект JSON, `document_from_json()` — строку или байты. Файловые операции — `save_document()` и `load_document()`. [Правила совместимости](compatibility.md) описывают поддерживаемые версии.

## Проверка перед созданием модели

Чтение проверяет JSON-значения и структуру полей до создания объектов. Объекты представлены словарями с текстовыми ключами, массивы — списками. Версии являются целыми числами: `True`, `1.0` и `"1"` не заменяют версию 1. Булевы поля принимают только `true`/`false`; размеры и координаты — конечные числа, а enum — поддержанные строковые значения. Отсутствующие необязательные поля сохраняют прежние значения по умолчанию.

Обязательные поля проверяются явно. Для ресурса нужны `id`, `kind`, `media_type` и хотя бы один источник содержимого: `data_base64` или `source`. Пустая строка base64 представляет `b""`, а `null` — отсутствие встроенных данных. Идентификатор ресурса совпадает с ключом словаря. Имя части пакета совпадает с её ключом и начинается с `/`; неизвестные аргументы `box` и `crop` отклоняются. Base64 проверяется строго; XML внутри ресурса остаётся непрозрачными байтами.

После восстановления выполняется `DocumentModel.validate()`: например, ссылка на отсутствующее изображение делает документ недопустимым. Структурная валидация не проверяет оформление офисного файла.

## Ошибки с расположением поля

Повреждённая структура или значение вызывает `ValueError` с расположением и причиной. Например, `$.document.resources['image'].data_base64: invalid base64 data`. Синтаксически неверный JSON даёт `json.JSONDecodeError`, подкласс `ValueError`, с позицией ошибки. Текст сообщений не является стабильным машинным протоколом.

```python
from opendoc_model import document_from_dict

try:
    document_from_dict({"format": "opendoc.document", "version": True, "document": {}})
except ValueError as error:
    assert "$.version" in str(error)
else:
    raise AssertionError("Булево значение не должно приниматься за версию")
```

## Значения расширений

С 0.17.3 словарные границы создают независимые данные: `document_to_dict`
возвращает снимок, а `document_from_dict` отделяет восстановленную модель от
входного словаря. Изменение вложенного metadata, properties или свойства-ссылки
с одной стороны не меняет другую. Это касается также стилей, ресурсов и реестра
сносок. Сам `VersionedProperties.to_dict()` по-прежнему является обычной неглубокой
копией mapping; гарантия независимости относится к кодеку документа.

`document_from_json` и `load_document` отклоняют повтор одного ключа внутри
одного JSON-объекта через `ValueError`, включая неизвестные расширения и ключи,
равные после декодирования escape-последовательностей. Это исключает молчаливую
замену версии, ID или цели ссылки последним значением. Даже одинаковые повторные
значения отклоняются. Сообщение содержит имя ключа; `$` обозначает границу JSON,
полный путь вложенного объекта для этой ошибки не вычисляется. Одно имя ключа
в разных объектах допустимо. Проверки байтов и глубины выполняются до разбора,
проверки дерева и ссылок — до возврата модели.

В `metadata` и `properties` сохраняются неизвестные ключи и вложенные JSON-значения: словари, списки, строки, конечные числа, булевы значения и `None`. `NaN`, бесконечности, tuple, bytes, произвольные Python-объекты, нетекстовые ключи и циклические значения не являются JSON-расширением. При чтении они отклоняются; при записи ошибка обнаруживается до замены файла. Бинарные данные хранятся в `Resource.data`, кодек переводит их в base64.

Запись не преобразует не-JSON данные в строки и не выдаёт отсутствующее измерение за успешную проверку. Внешний `source` ресурса сохраняется строкой; чтение JSON не открывает его и не загружает внешнее содержимое. Сохранение использует атомарную запись и действующую квоту 100 МБ; отказ не меняет предыдущий файл.

[DocumentLimits](limits.md) позволяет задать бюджет одной операции: байты, глубину, число значений и объём встроенных данных. Ограничения применяются и при чтении, и при записи; превышение даёт `ArtifactLimitError`.
