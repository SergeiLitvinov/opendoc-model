# Обход, поиск и ресурсные ссылки

OpenDoc Model обходит документ и любое структурное поддерево без пользовательской рекурсии. `walk_model()` возвращает структурные вхождения; фильтры находят секции, блоки, inline или нужные типы элементов. Обход используется также в валидации, инспекции и инвентаризации.

```python
from opendoc_model import DocumentModel, Image, Paragraph, Section, Table, TableCell, TableRow, TextRun, iter_elements

paragraph = Paragraph([TextRun("Текст"), Image("diagram", "Схема")])
document = DocumentModel(sections=[Section(blocks=[Table([TableRow([TableCell([paragraph])])])])])
images = list(iter_elements(document, Image))
assert images[0].path == "sections[0].blocks[0].rows[0].cells[0].blocks[0].content[1]"
assert images[0].parent.node is paragraph
for reference in iter_elements(document, TextRun):
    reference.node.text = reference.node.text.replace("Текст", "Новый текст")
```

Поиск не требует, чтобы `diagram` уже существовал: его отсутствие является семантической ошибкой и выявляется `validate()`. Это позволяет найти элемент в ещё не завершённой модели и исправить ссылку. Полный исполняемый сценарий находится в [examples/traversal.py](../../examples/traversal.py); проверка документации запускает его вместе с остальными примерами.

## Итераторы

| API | Вхождения |
|---|---|
| `walk_model(root)` | Корень, секции, блоки, строки/ячейки таблиц и inline |
| `iter_sections(root)` | Секции |
| `iter_blocks(root)` | Блоки, включая вложенные ячейки и все колонтитулы; inline-изображения/формулы сюда не входят |
| `iter_inlines(root)` | Текст, изображения и формулы в inline-позициях |
| `iter_elements(root, types)` | Типы элементов в обеих позициях; например `Image`, `Paragraph` или `(Image, Formula)` |
| `iter_resource_references(root)` | Поддержанные ссылки на ресурсы с владельцем и полным путём поля |

`root` — `DocumentModel`, `Section`, `Paragraph`, `Table`, `TableRow`, `TableCell`, `TextRun`, `Image` или `Formula`. Стили, геометрия, свойства, ресурсы и части пакета являются данными узлов и не выдаются как структурные вхождения. Фильтр `types` принимает только классы элементов или их кортеж; пустой кортеж даёт пустой результат после проверки формы дерева. Неподдержанный корень или фильтр вызывает `ValueError`.

Самостоятельный `Image`/`Formula` считается корневым блоком, самостоятельный `TextRun` — inline. Для изображения/формулы в документе роль определяется коллекцией, в которой оно расположено, а не только его классом.

## Расположение элемента

Каждый `NodeLocation[T]` содержит:

- `node`: сам объект модели, без копирования;
- `path`: путь относительно переданного корня; у корня пустая строка;
- `parent`: `NodeLocation` непосредственного структурного родителя или `None` у корня;
- `field` и `index`: имя коллекции и индекс в родителе, либо `None` у корня;
- `kind`: `document`, `section`, `block`, `inline`, `row` или `cell`;
- `section` и `section_index`: содержащая секция и её позиция в документе, когда такой контекст есть.

Родитель блока в ячейке — `TableCell`, родитель ячейки — `TableRow`, родитель строки — `Table`. У самостоятельного поддерева нет контекста внешнего документа: пути относительны, индекс секции неизвестен. У секции, переданной как корень, `section` указывает на неё саму, `section_index` равен `None`.

Расположение — неизменяемый снимок одного **вхождения**, а `node` остаётся изменяемым объектом. Два вхождения одного объекта имеют разные пути и разные `NodeLocation`; объект намеренно не клонируется и не сворачивается в одно вхождение. Изменение общего объекта видно во всех его местах. Для независимого изменения сначала нужна независимая структура.

## Порядок и срок действия пути

Обход — в глубину, сначала родитель, потом дети. Секции идут по индексу. В секции коллекции следуют в порядке `SECTION_CONTENT_FIELDS`:

1. `headers`;
2. `first_page_headers`;
3. `even_page_headers`;
4. `blocks`;
5. `footers`;
6. `first_page_footers`;
7. `even_page_footers`.

Это порядок библиотечной инспекции и отпечатка текстового потока; он не моделирует повторение колонтитулов на физических страницах. Строки, ячейки, блоки ячеек и содержимое абзацев идут по индексам. Изменения этой последовательности требуют пересмотра совместимости отпечатков.

Путь уникален в рамках одного законченного обхода неизменённой структуры. Он не является постоянным идентификатором элемента. После вставки, удаления, переноса или замены коллекции нужно выполнить новый обход: прежний путь/индекс может относиться к другому объекту, хотя старый `node` всё ещё доступен. JSON-сохранение не делает путь стабильным идентификатором.

Текст и другие значения существующих элементов можно менять через `reference.node`; это не меняет структурный путь. Структуру коллекций во время ленивого обхода менять не следует. Для правок структуры сначала соберите необходимые вхождения, закончите обход и затем получите свежие пути. Итераторы не предоставляют транзакцию, блокировку, историю редактора или автоматическое клонирование.

## Ссылки на ресурсы

`ResourceReference` содержит `owner` (`NodeLocation` элемента), `resource_id`, полный `path`, относительный `field` и `kind`:

| `kind` | Поле владельца |
|---|---|
| `image` | `Image.resource_id` |
| `fallback` | `Image.properties.fallback_resource_id` |
| `surrogate` | `visual_surrogate.resource_id` любого элемента, включая текстовый фрагмент |
| `text` | `TextRun.properties.resource_id` |

Ссылки идут в порядке владельцев при обходе, для одного изображения — основная, fallback, surrogate; для текста — ресурсная ссылка, затем surrogate. Отсутствующие необязательные ссылки пропускаются. Неизвестный непустой идентификатор выдаётся как ссылка; пустой/нетекстовый идентификатор и повреждённая форма полей вызывают `ValueError`.

```python
from opendoc_model import iter_resource_references

references = list(iter_resource_references(document))
assert references[0].resource_id == "diagram"
assert references[0].owner.node is paragraph.content[1]
assert references[0].path.endswith("content[1].resource_id")
```

Произвольные прикладные ключи не интерпретируются как ссылки. Например, `vendor:resource_id` остаётся расширением. Связи непрозрачного пакета отдельно относятся к `PackageGraph`, а не к `DocumentModel.resources`. Обход не открывает файлы, URI или офисные адаптеры. Валидация и инспекция используют тот же набор поддержанных ссылок; fallback и surrogate учитываются при поиске неиспользуемых ресурсов.

## Проверки и бюджеты

Все итераторы ленивые и принимают `limits=DocumentLimits(...)`. До первого вхождения проверяется переданный корень: циклы, глубина, число значений и встроенные данные. В бюджет входят данные полей корня, даже если они не выдаются как отдельные структурные узлы; для поддерева проверяется только это поддерево. `max_bytes` относится к операциям JSON и не измеряет весь текст при обходе.

Форма структурных коллекций проверяется при продвижении. Ошибка в поздней ветви может возникнуть после уже выданных вхождений, поэтому частично прочитанный итератор не подтверждает корректность остальных ветвей. Фильтры тоже проверяют пропущенные ветви. Превышение бюджета даёт `ArtifactLimitError`; повреждённая форма — `ValueError` с расположением. Повторное использование поддерева допустимо, циклическое — нет.

Обход не подменяет [семантическую валидацию](validation.md): она дополнительно проверяет ссылки, размеры, span и содержимое полей. После изменений перед сохранением используйте `validate()`; сам JSON-кодек также выполняет валидацию.
