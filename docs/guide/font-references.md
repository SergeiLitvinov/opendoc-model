# Явная ссылка на программу шрифта

С 0.14.0 `FontReference(resource_id, face_index=None)` связывает `TextStyle`
с конкретным ресурсом `ResourceKind.FONT`. `font_family` остаётся отдельным
именем семейства и не выбирает бинарную программу. Две разные программы
с одинаковыми family/variant не объединяются по имени.

## Значение и наследование

`resource_id` — непустой UTF-8 ID ресурса документа. `face_index` — неотрицательное
целое число либо None. Bool, дробные, строковые и отрицательные индексы запрещены.
None означает неизвестный индекс, **не нулевой**. При явном нуле выбран первый
face коллекции, но библиотека не подтверждает наличие такого face в байтах.
Число faces, корректность TTF/OTF/TTC, лицензия и возможность встраивания
проверяются потребителем. Ресурс может иметь внешнее представление: автоматической
загрузки или выбора системного шрифта нет.

```python
from opendoc_model import FontReference, TextStyle, get_font_reference, set_font_reference

style = TextStyle(font_family="OwnFamily")
set_font_reference(style, FontReference("font-resource", face_index=None))
assert get_font_reference(style).resource_id == "font-resource"
set_font_reference(style, None)  # удалить прямую ссылку, разрешить наследование
```

Getter возвращает независимое значение. Setter проверяет локальную декларацию
и атомарно записывает её, сохраняя неизвестные поля прежней ссылки в `extra`.
Удаление убирает всю прямую декларацию вместе с её расширениями. Существование
ресурса и его kind проверяются в контексте документа при validate/check/JSON,
а не по несуществующему контексту отдельного TextStyle.

`resolve_style` и `effective_text_style` используют существующую цепочку
base_style_id, paragraph.style_id и прямой run style. Ссылка заменяется целиком,
face_index не достраивается из предыдущей ссылки. Отсутствие прямой декларации
разрешает наследование; отсутствие по всей цепочке остаётся неизвестным.
Изменение только font_family не отменяет явно унаследованную ссылку. Удаление
прямой ссылки также не выбирает ресурс по совпадению имени. Выбор нужной программы
и назначение ссылки реальному тексту остаются явным решением потребителя.

## JSON и ошибочные ссылки

Декларация лежит в `TextStyle.properties["opendoc.font-reference"]`, format
совпадает с ключом, version равен 1. JSON документа read1/2/write2, конструкторы
TextStyle и прежние документы без ссылок сохранены; обязательных зависимостей нет.
Неизвестные поля декларации сохраняются плоско и доступны через extra.
Нельзя подменять поля схемы и format/version. Непомеченное содержимое ключа
остаётся непрозрачным: getter возвращает None, setter отказывается его стирать.
Неизвестная tagged-версия отклоняется. None в API удаления не равен записи
произвольного null в занятой property bag.

Именованные и inline стили проверяются одинаково. Dangling ID даёт расположенный
`font.reference.missing`, ссылка на ресурс другого kind — `font.reference.kind`,
некорректный индекс/декларация/владелец — `font.reference.invalid`.
Ссылка принадлежит TextStyle, а не Paragraph.properties или metadata.
Целостность неизвестных расширений не выводится из их имён.

Все новые операции принимают `DocumentLimits`; ошибки сохраняют структурированные
path/quota/maximum. Лимит применяется до рекурсивного декодирования/копирования
декларации. При ошибке setter или ресурсная операция оставляют исходник целым.

## Композиция и управление ресурсами

Clone сохраняет независимые данные. Merge переназначает FONT resource ID и
ссылки в именованных и inline стилях по одной карте, включая общих владельцев.
Extract включает ресурсы прямых ссылок и замыкание ресурсов нужных именованных
стилей. Ненужные ресурсы не добавляются из совпадений family.
Прежний словарь ID-карт сохраняется; новой доменной карты не требуется.

`iter_font_references` возвращает `FontReferenceLocation(style, reference, path)`:
живой TextStyle, независимую декларацию и путь текущего обхода. Он включает
document.styles и inline стили всех структурных областей, включая колонтитулы
и сноски. Унаследованные использования не становятся выдуманными прямыми ссылками.
После структурной правки нужно получить новые пути. Старый
`iter_resource_references` / `find_resource_uses` сохраняет область структурных
слотов изображений, surrogate и text properties; ссылки стилей обходятся отдельно.

Remove/replace resource учитывают FONT-ссылки, включая dictionary стилей.
Удаление используемого ресурса требует явной замены, а замена ресурсом другого
kind отклоняется с откатом. При замене index сохраняется как объявлен: наличие
этого face в новой программе не проверяется моделью. Инспекция не помечает
явно связанный FONT как неиспользуемый. Её общий счётчик семейств и сравнение
не доказывают сохранность бинарной программы, binding или нативного начертания;
точная проверка этого профиля использует декларации и JSON.

[Собственный пример](../../examples/font_references.py) и
[тесты](../../tests/test_fonts.py) используют разные непрозрачные байты с одним
семейством. Два JSON-цикла подтверждают модельную идентичность, а не качество
пользовательского шрифта или результат отображения. Разбор TTF/PDF/OOXML,
встраивание, нативные relationships и проверка лицензионных прав остаются снаружи.
