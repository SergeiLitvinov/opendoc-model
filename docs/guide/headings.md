# Семантические заголовки

Заголовок — явная роль абзаца с уровнем 1–9. `Heading` — неизменяемое значение,
элемент остаётся `Paragraph`. Роль не выводится из шрифта, bold, текста или стиля
и не выбирает визуальное оформление. Пример — `examples/headings.py`.

```python
from opendoc_model import Heading, Paragraph, get_heading, set_heading

paragraph = Paragraph()
set_heading(paragraph, Heading(2))
assert get_heading(paragraph) == Heading(2)
set_heading(paragraph, None)
```

## Представление и совместимость

JSON документа остаётся `opendoc.document` v2 (чтение v1/v2), bags — v1. Новая
схема использует сохраняемые properties без нового типа блока или обязательных
полей. `HEADING_PROPERTY` равен `opendoc.heading`; значение непосредственно
в свойствах абзаца:

```json
{"format": "opendoc.heading", "version": 1, "level": 2}
```

Это явная модельная роль. Прежний reader не знает роль,
но сохраняет её как неизвестные properties. Новый код распознаёт только явный
`format="opendoc.heading"` в этом месте. Свободный `heading_level`, стиль и
непромаркированные значения ключа не мигрируются: они остаются допустимыми
расширениями. `get_heading` возвращает для них `None`; `set_heading` отклоняет
запись и удаление занятого ключа с `ValueError`, оставляя решение о переносе
прикладных данных потребителю. Данные в других bags не создают роль абзаца.

У явно промаркированного значения `version` — целое 1 без bool, `level` — целое
1–9 без bool. Отсутствующее/неподдержанное значение отклоняется в памяти, чтении
и записи. [Проверка в памяти](checks.md) возвращает `semantic.version` или
`semantic.heading.level` с точным путём. Дополнительные JSON-ключи сохраняются;
при смене уровня bag копируется со всеми расширениями. Снятие роли удаляет весь
heading bag. Остальные properties, текст, стиль, геометрия и provenance не меняются.

## Поиск и изменение

`get_heading(paragraph, *, limits=None)` читает явно заданную роль.
`set_heading(paragraph, heading, *, limits=None)` принимает `Heading` или `None`,
меняет свойства на месте после проверки кандидата. Отказ не оставляет частичных
изменений. JSON-значение, включая расширения, проверяется с
[DocumentLimits](limits.md). `None` снимает роль, не наследует её из стиля.

`iter_headings(root, *, limits=None)` возвращает `NodeLocation[Paragraph]` в
[общем порядке обхода](traversal.md), включая вложенные таблицы и семь коллекций
секции. Корень может быть документом или поддеревом. Общие узлы имеют отдельные
расположения; после структурных правок повторите обход. Итератор проверяет форму
дерева и heading bags, но не заменяет полную валидацию остальных ссылок.
Копирование, преобразования и композиция сохраняют роль как обычные свойства;
уровень не добавляет ID-зависимостей.

## Сравнение

Инвентарь абзаца содержит `heading`: уровень или `None`. Роль не меняет текстовый
fingerprint. Изменение уровня появляется как `heading` в списке изменений
`object_diff.changed`. `headings_available` показывает полноту представления
на обеих сторонах, `changed_headings` считает изменения среди сопоставленных
абзацев. Старый инвентарь без поля не объявляется plain-ролью: доступность false,
счётчик `None`.

Смена уровня даёт `WARNING`/`heading-change`, снятие роли у сопоставленного абзаца —
`LOSS`/`heading-loss`. Исчезнувший абзац даёт `object-loss`; его известный уровень
остаётся в lost-инвентаре. Добавленная роль учитывается в изменениях. `ObjectLossPolicy`
оценивает число объектов, не равенство ролей; явная `QualityPolicy` может отклонить
сообщённый LOSS. Сравнение не подтверждает визуальный результат во внешнем формате.
