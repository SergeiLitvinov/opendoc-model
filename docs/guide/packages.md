# Непрозрачные пакеты

`PackageGraph` хранит объявленный формат, логический корень, части и направленные
связи. Он отделён от семантических ресурсов документа. OpenDoc Model сохраняет байты
и топологию без распаковки, исполнения, конвертации или чтения внешних целей.
Смысл media type, relationship type и самих байтов задаёт потребитель.

## Создание произвольного формата

Исполняемый пример — [examples/packages.py](../../examples/packages.py).
Новый `PackageGraph.create(format, *, root="/", parts=(), relationships=(), limits=None)`
требует непустой строковый формат и создаёт независимые копии входных записей.
Он проверяет топологию и общие бюджеты узлов/встроенных байтов; iterables потребляются
последовательно и ограничиваются до накопления всего ввода. Повторное определение
части отклоняется даже при равных данных.

```python
from opendoc_model import PackageGraph, PackagePart, PackageRelationship

graph = PackageGraph.create(
    "example.archive",
    parts=[PackagePart("/content", "application/octet-stream", b"opaque")],
    relationships=[PackageRelationship("main", "example.main", "/", "/content")],
)
assert graph.root == "/"
assert graph.validate() == []
```

`format` — декларация непрозрачного формата; произвольное значение не обещает
существование импортёра. Проверяются схема документа и структура графа, а не
содержимое объявленного формата. Части кодируются base64 и восстанавливаются
побайтно, включая пустые данные. Граф записывается в явном `DocumentModel.package`.
Роли ресурсов не создают граф автоматически.

## Имена, корень и связи

Имена частей — непустые абсолютные логические строки с ведущим `/`, без пустых
сегментов, `.` и `..` или завершающего `/`. Ключ словаря совпадает с `part.name`.
Unicode допустим. Строки сравниваются буквально: `%2F` не декодируется, регистр
не нормализуется, обратный слеш, `?` и `#` не получают файловой или URI-семантики.
Это идентификаторы графа, не локальные пути.

Корень — `/` или имя той же формы. Он обозначает логический источник связей и
может не иметь физической части. Источник связи должен быть `/`, заданным корнем
или существующей частью. Внутренняя цель должна быть существующей частью;
внешняя цель — непустой строкой с `external=True` и никогда не открывается.
Тип связи и ID непустые. Пара `(source, id)` уникальна: один ID допустим у разных
источников. Циклы и ссылки части на себя разрешены; ацикличность не заявляется.
Ошибки топологии возвращает `validate()`, превышение бюджета даёт `ArtifactLimitError`.

`related_part(source, relationship_type)` возвращает часть первой подходящей
внутренней связи, не разрешает внешние URI и не интерпретирует тип связи.
Правила сохранения/отбрасывания пакета при композиции описаны в
[объединении и извлечении](composition.md).

## Совместимый переход

Прежний конструктор `PackageGraph(format)` сохраняет корень `/word/document.xml`.
Чтение JSON v1/v2 без явно указанного корня сохраняет то же прежнее значение.
Новые потребители используют `create` или явно передают свой `root` конструктору.
Writer записывает корень явно; чтение явно заданного пакета произвольного формата
не подставляет DOCX-части и не переосмысляет содержимое.

Это явный контракт: старые сигнатуры и значения по умолчанию сохранены,
JSON документа остаётся v2 с чтением v1/v2. Автоматическое изменение старого корня
не выполняется: если потребителю нужна миграция, он выбирает новый корень и
соответствующие источники связей явно, затем проверяет граф. Неизвестные версии
JSON и типы элементов по-прежнему отклоняются; непрозрачный формат пакета не
обходит эти проверки.
